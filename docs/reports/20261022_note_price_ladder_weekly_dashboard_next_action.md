## 背景・動機

note 記事の価格設定ルール（¥100 開始 → 200 PV で 2 部以上なら上げる、1 部以下なら冒頭と有料ラインを見直す、上げた価格で売上/1,000 PV が前の価格を下回れば戻すかブラッシュアップするか判断）は、同日の前の変更で毎朝のメール通知まで入った。しかしメールは条件を満たした日に 1 回しか届かないので、見落とすと改善作業がそのまま止まる。よーんの「忘れずにできるようにしたい」に対して提案した 3 層（朝の通知 ／ 週次で未対応を列挙 ／ ダッシュボードで現状を見る）のうち、残り 2 層を実装した。

同時に、判定が `note_article_daily.py` の中だけにあると、ダッシュボードや週次の表で別の計算をして食い違う恐れがあるため、判定関数を 1 つのモジュールに出して 3 か所が共用する形にした。

## 実施内容

### 1. 判定ロジックの一本化 `scripts/note_price_rule.py`（新規）

- `RULE_PV = 200`、`RULE_BUYS = 2`、`decide_action(n_pv, n_buy, price, prev)` を置く。窓の PV が 200 未満なら空、規則 4（前の価格区間の売上/1,000 PV が今の区間を上回る）を優先し、それ以外は 規則 2「価格を上げる」／ 規則 3「冒頭と有料ラインを見直す」を返す
- `note_article_daily.py`（毎朝のメール通知）はこの関数を import するよう書き換え、独自の判定を削除

### 2. `article_price_cvr.csv` に動作の列を追加（`scripts/note_funnel_export.py`）

- `note価格履歴` を A:J で読み、改稿日・通知日・通知内容を区間に持たせる
- 現在価格の区間だけ、改稿日 ／ 窓開始日（区間開始と改稿日の遅い方）／ 窓PV ／ 窓購入 ／ 次の動作 ／ あとPV（200 までの残り）／ 通知日 ／ 通知内容 の 8 列を埋める。規則 4 の比較相手は直前の閉じた区間

### 3. 週次振り返り「⑨ note 価格のはしご」

- `scripts/note_funnel_measures.py` の末尾に「価格のはしご」の表（記事 ｜ 価格 ｜ 窓 ｜ 窓PV ｜ 購入 ｜ 次の動作 ｜ 通知 ｜ 状態）と「未対応: N 件（記事名）」を出す。未対応 ＝ 通知済みで、価格も改稿日も通知後に変わっていない記事。`--json` にも含める。施策の対象が無くても価格のはしごは出す
- `reporter-weekly-ops` STEP 5.7 に転記手順（未対応を先に列挙、判定や催促はしない）、テンプレートに「### ⑨ note 価格のはしご」、完了報告に「価格のはしご: 未対応 X件」を追加

### 4. ダッシュボードの「次の動作」列（v30 → v31）

- 「価格別 CVR」の表に「次の動作」列。現在の区間だけ「価格を上げる（規則 2）」「冒頭と有料ラインを見直す（規則 3）」「戻すかブラッシュアップするか判断（規則 4）」か「あと nn PV」を表示し、動作がある行は色付き。改稿日があれば「（改稿 MM/DD〜 PV・購入）」、通知済みで未対応なら「（通知済み・未対応）」を添える。列はソート可
- `article_price_cvr` データセットを新しい列入りの CSV に差し替え（version 4）。以後は routine「note 導線ダッシュボード更新」（06:30）が毎朝更新する

## 設計判断

- **判定は 1 か所**。メール・CSV・週次表で判定が食い違うと、どれを信じるかで迷う。`note_price_rule.py` を正とし、他は数値を渡すだけにした
- **週次は列挙のみ**。判定も催促もせず「未対応」として毎週出す。対応するまで消えないことが目的で、文面で急かす必要はない
- **「あと nn PV」も表示する**。条件を満たす前から残りが見えると、改稿のタイミングを前もって考えられる

## 確認結果

- `note_funnel_export.py --out <一時>`：`article_price_cvr.csv` の現在区間に 8 列が入り、ボイジャー ¥980 → 規則 4（売上/1,000 PV 0 ＜ ¥490 区間の 3,508）、赤い空（後編）¥490（233 PV・4 部）→ 規則 2、ニューホライズンズ ¥300 → あと 13 PV
- `note_funnel_measures.py`：「価格のはしご」の表と「未対応: 0 件」。`note_article_daily.py --dry-run` の判定と一致
- ダッシュボード v31：スクリプトの構文チェック通過、「次の動作」列に上記の 3 件が表示される
- 4 本の Python は `py_compile` 通過

## 今後の課題

- 未対応の判定は「通知後に価格も改稿日も変わっていない」で見ている。改稿せず価格だけ変えた場合も対応済みと見なすので、意図どおりでなければ改稿日の自動検知（本文ハッシュ）と合わせて見直す
- 初回のメール通知は 10/23 05:55 の cron。ボイジャーの ¥980 → ¥590 の価格変更はそこで `note価格履歴` に記録される
