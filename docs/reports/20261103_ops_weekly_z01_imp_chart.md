## 背景・動機

2026-11-01 に週次の発信運用振り返り（`/reporter-weekly-ops`）がビジュアル版になり、W001 長文の実IMP を 1 本ずつ対数棒グラフで見せる「分散記録チャート」が入った。よーんから「z01 実IMP の分散記録のグラフも追加してほしい」と依頼。

z01 は改善対象外・定点観測用（2026-08-16 決定）で、週中央値をベースラインとして毎週記録しているが、1 本ごとの振れ幅（土台と跳ね）は数字の列挙でしか見えていなかった。本数が多い（半減後 7/3〜で 59 本）ので W001 のような累積リストは向かず、チャートが合う。

## 実施内容

- **W44 レポート**：W001 チャートの直下に z01 版を追加。outputs で what_id＝z01 の X 投稿（7/3〜11/1、59 本）を X投稿一覧の IMP と tweet ID で突合し、同じ対数スケール（縦軸 400〜30 万）の棒グラフに全期間の中央値（1,581）を破線で引いた。59 本中 54 本が 584〜9,095 の帯、1 万超えは 5 本（9/1・9/5・9/16・10/22・10/31）。値は 11/3 取得時点のため、本文の 10/31 分（33,111、11/1 時点）がチャートでは 42,609 になっている旨をキャプションに明記
- **SKILL.md**：
  - STEP 4-1 に「z01 の分散記録」の集め方（outputs × X投稿一覧の突合、累積リストは書かずチャートと n・中央値・1万超え本数だけ）を追加
  - ビジュアル要素 2 のスニペットを W001／z01 共通に汎用化：`label`・`lo,hi`・`median` をパラメータにし、n＞26 で日付ラベルを自動で間引く（`every`）。W001 は 600〜30 万・中央値なし、z01 は 400〜30 万・中央値あり
  - レポートのテンプレートに z01 チャートの位置（W001 チャートの後、累積リストの前）と見出し文を追加

## 設計判断

- **別スクリプトにせず SKILL.md 内のスニペットを汎用化**：既存の W001 用がインライン python だったので同じ型に揃え、2 枚とも 1 つのスニペットから出す
- **中央値線は z01 だけ**：z01 はベースライン（週中央値）を監視する対象なので全期間の中央値を基準線にした。W001 は n=16 で当たり率を見る段階のため線を引かない
- **既存レポートの他の数字は直さない**：チャートだけ 11/3 時点の値になるが、本文の 11/1 時点の値を書き換えると「その週に何が見えていたか」の記録が崩れる。差があることをキャプションで示すにとどめた

## 確認結果

- SKILL.md のスニペットを抜き出して bash 経由で実行し、W001 設定・z01 設定（`median=True`）の両方で SVG が出ることを確認
- W44 レポートに `<svg>` が 2 つ（W001・z01）あることを確認。Wiki の表示は W001 チャートと同じ CSS 変数を使っているので、同じく両テーマで表示される
- 日付ラベルは 59 本 → 3 本おき（20 ラベル）で重ならない幅（1 本 11 px）
