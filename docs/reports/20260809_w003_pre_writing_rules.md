## 背景・動機

シロナガスクジラの心拍投稿（2026-08-06 フォルダ）で、check-fact・check-brand を通した初稿から最終原稿まで、ユーザー推敲が10往復近く必要になった。初稿と最終原稿を並べて差分を分析したところ、修正は次の5系統に整理でき、うち3つは**執筆前の工程**で防げるものだった。

| 差分 | 原因 |
|---|---|
| フックが演出過多（「あなたの心臓が60回打つあいだに…」）→ 素朴な事実型に | brand.md の冒頭フック5軸を「埋めるべきテンプレート」として使い、盛り込みながら組み立てた |
| 「心臓は限界まで働いている／大きくなれない」を削除 | 限界なのは実は浮上時の高心拍で、徐脈の直後に置くと因果が逆に読める。研究チームの仮説を断定調で書いた。「なぜ？」に本文内で答えられない主張だった |
| 「ゆっくり打つほど酸素が長くもつ」に中間リンク補完 | 因果チェーンを1段ずつ書き出さずに書いた |
| 数値の層別（海面25〜37回→通常4〜8回→最低2回）・深度180m | 執筆前のファクト確認が二次情報止まりで、極値（2回）を代表値のように使った |
| 締めの往復（クジラ→人→クジラ→人）解消 | 視点切替の設計不足 |

同種の「初稿→最終稿の差分分析による執筆前ルール化」は、同日に W002 でも行っている（[W002 初稿精度向上ルール](../20260809_w002_first_draft_quality_rules/)）。本件はその W003 版。

## 実施内容

`projects/w003/brand.md` の Writing Rules 冒頭に「執筆前チェック（初稿の精度を上げる 3 ルール）」を新設：

1. **ファクト表が先、本文が後** — 原典から「代表値／極値／測定条件」を表にしてから書く。極値をフックに使うときは本文で代表値を必ず併記（例: フック「最低2回」→本文「潜水中は通常4〜8回、いちばん低いときは2回」）
2. **why チェーン検査** — 本文中のすべての「なぜ？」に本文内の1〜2文で答えられるか確認。答えられない主張は面白くても落とす。研究者の仮説は原則不採用
3. **フックは素朴な事実型を第一候補に** — 「実は、〇〇は△△だ」で事実をそのまま書き、冒頭フック5軸は**書いた後の点検**に使う（5軸を埋めにいってフックを作り込まない）

ルール3の「点検に使う」は順序の転換：5軸で組み立てる（生成の型）のではなく、素朴に書いてから5軸に照らして欠けが致命的なときだけ直す（検収）。はちみつ・クジラの2回連続で、ユーザーが最終採用したフックはいずれも素朴な事実型だった。

検討過程で「締めは確認済み数値だけで組んだ情景にする」「数値比較は同一主体の Before/After を優先」の2項目も候補に挙げたが、ユーザー判断で不採用（ルールとして固定するには縛りが強すぎるため）。
