## 背景・動機

z01（X短文投稿）は高頻度運用のため、noteNeta / newsTopics の全データ行を対象に「未使用」フィルタをかけずランダム選定していた（`ステータスによるフィルタは行わない`）。この方式では同じネタが短期間で繰り返し選ばれる可能性があり、よーんから「短文投稿済み」を記録し、未チェックのネタから選ぶ方式への変更を相談された。

検討の結果、以下の方針にまとまった：
- 記録方式は「チェック列」ではなく「最終使用日」列とする（在庫を絞らない現行方針を保ったまま重複回避でき、全ネタ枯渇によるフォールバック判断が不要になるため）
- 記録タイミングは下書き作成時ではなく **実投稿時**（cron の `post_from_email.sh` → `record_output.py`）。下書き段階で記録すると、破棄・修正された下書きのネタも消費扱いになってしまうため
- 対象は noteNeta / newsTopics のみ。thoughts は無制限のまま（対象外）
- 選定条件は「ステータス（既存列）≠ボツ」かつ「短文最終使用日が空、または90日以上前」。候補が0件の場合はフォールバックで条件を緩めず、ネタ枯渇として下書きを作らず終了する（よーんの指示による簡素化）

## 実施内容

- SS1 の `noteNeta` / `newsTopics` シートに新列「短文最終使用日」を追加（`noteNeta` は既存 A〜M列の次の N列、`newsTopics` は既存 A〜H列の次の I列。gws CLI の `appendDimension` でグリッド列数を拡張してからヘッダーを書き込み）
- `docs/database.md` に両シートの新列定義を追記
- `projects/z01/spec.md` STEP 2 を書き換え：
  - 取得範囲を `noteNeta!A:N` / `newsTopics!A:I` に拡張
  - 候補行を「ステータス≠ボツ」かつ「短文最終使用日が空または90日以上前」に絞り込んでからランダム選択
  - 候補0件時はSTEP 3以降に進まず、STEP 7で下書き未作成のネタ枯渇報告を出して終了（Rules・Verificationにも明記）
  - thoughts は従来どおりフィルタなし
- `scripts/record_output.py` に実投稿成功時の書き戻し処理を追加：`how_id=="z01"` かつ `--neta-id` が `noteNeta[N]` / `newsTopics[N]` の場合、SS1 の該当行（A列一致）の短文最終使用日へ投稿日を書き込む

## 設計判断

- **チェック列ではなく最終使用日列を採用**：高頻度運用で在庫を絞らない現行方針（`ネタは「未使用」フィルタをかけず全データ行を対象に選ぶ`）と両立させるため。使い切り＋リセット管理が不要になる。
- **記録は実投稿時、下書き作成時ではない**：下書きは1投稿1回だけ作成し作り直さない運用のため、下書き段階で記録すると「作ったが投稿されなかった／修正版が別途投稿された」ケースでネタが誤って消費扱いになる。`post_from_email.sh` は既に本文の `ソース: {シート}[{番号}]` を解析して `record_output.py` に `--neta-id` を渡す仕組みが存在していたため、その経路にそのまま乗せた。
- **枯渇時のフォールバックは持たせない**：当初は3段階フォールバック（条件を段階的に緩める）を検討したが、よーんの指示で「枯渇時は投稿を作らず報告して終了」に簡素化。データが本当に枯渇していれば人間の判断（ネタ補充）を仰ぐべきという考え方に合わせた。
- **thoughts シートは対象外**：ステータス列・追加日列を持たないシート構造のため、同じ仕組みを持ち込むと不整合になる。無制限のまま据え置き。

## 確認結果

- `python3 -m py_compile scripts/record_output.py` で構文エラーがないことを確認
- gws CLI で `noteNeta!A1:N1` / `newsTopics!A1:I1` を取得し、ヘッダー行に「短文最終使用日」が正しく追加されていることを確認
- mcp-gsheets がこのセッション中 `GOOGLE_PROJECT_ID` 未設定で接続不可だったため、シート列追加は `gws sheets spreadsheets` コマンド（`sync_to_sheets.sh` と同じ経路）で代替した

## 今後の課題

- mcp-gsheets の接続不良（`GOOGLE_PROJECT_ID` 未設定）は別途原因調査が必要
- 下書き作成〜実投稿（cron 21:00）の間に z01 が再実行された場合、その間は短文最終使用日が未更新のため同じネタを再び引く可能性が理論上ある（高頻度運用ではないため実害は小さいと判断し、今回は対応を見送った）
