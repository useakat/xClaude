## 背景・動機

週次の発信運用振り返り（`/reporter-weekly-ops`）は「フック型別にどの投稿が伸びたか」を分析したいが、z01 のフック型記録は W33〜W35 の3週連続でアクション未消化だった。原因は記録の設計にあった：

- 「投稿時によーんがメモする」形になっており、人の記憶に依存していた
- 実際にはフック型は制作フローの中で毎回決定されている（`/writer-xpost` の冒頭フック候補「## 決定」、W001 の `draft/hook-candidates.md`）のに、その決定が Gmail 下書きの中に埋もれて振り返り時に読めなかった

つまり「記録していない」のではなく「記録が回収不能な場所にある」問題。決定した瞬間に、振り返りが読める場所へ機械的に書き出す設計に変えた。W35 の振り返りで「記録先未定のままの再掲はしない」と決めたことを受け、記録先の確定とフロー組み込みを同時に実施。対象はよーんの指示で z01 だけでなく W003・W001 にも拡大した（型別比較は本数が多いほど早く効く）。

## 実施内容

- `logs/hook_records.csv` を新規作成。列は `日付,プロジェクト,フック型,冒頭15字,ソース,備考`
  - **冒頭15字**が X投稿一覧の本文との突合キー（制作時点ではツイート URL が存在しないため）
  - フック型は `style/hook-patterns.md` の①〜⑤＋短縮名（例: `①逆説` `⑤口火`）。複合は主たる型を1つ
  - 当週の4本をバックフィル（W001 ハッブルは hook-candidates.md の決定記録＝①逆説。z01×2・W003 クマムシは事後分類と備考に明記）
- `projects/z01/spec.md` STEP 6 に記録ステップを追加。**z01 は無人フローのため、追記した CSV だけを即 commit & push するところまで spec に明記**（push しないと実行環境の破棄で記録が消える）
- `projects/w003/spec.md` フロー9.5・`projects/w001/spec.md` フロー14.5 に記録ステップを追加。対話フローなのでテーマ／投稿フォルダの通常コミットに同乗させる
- `/reporter-weekly-ops` のデータソースに CSV を追加し、STEP 5 の型分析を「制作時記録を第一に使い、無い投稿のみ事後分類と明記」に変更

## 設計判断

- **記録先を repo 内 CSV にした理由**: ①制作は Claude セッションが spec どおりに実行するため、spec に書けば人の記憶に依存しない。②振り返りは Read だけで済み、Sheets の列追加や cron スクリプト（`post_from_email.sh`）の改修が不要。③追記が git に乗るため、週次振り返りの「③前週アクションの消化確認」を痕跡で機械的に判定できる
- **却下した案**: outputs シートへの列追加（記入者が cron スクリプトになりフック型を知らないため要スクリプト改修）／Gmail 下書きからの事後回収（下書きの投稿後の扱いが不定で恒久記録に不向き）

## 確認結果

- `logs/` が gitignore されていないこと（既存の tracked ファイルあり）を確認のうえ CSV を作成

- バックフィル4行の突合キー（冒頭15字）が X投稿一覧の本文先頭と一致することを当週データで確認
