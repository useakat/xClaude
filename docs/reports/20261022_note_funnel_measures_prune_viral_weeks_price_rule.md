## 背景・動機

10/21 に作った施策レジストリ（N1〜N11）を、よーんと一緒に 1 件ずつ見直した。きっかけは「各価格帯で記事の CVR を上げるには、タイトルと無料部分を直すしかないか」という問いで、そこから 3 つのことが分かった。

1. **記事側の改稿は今の PV では判定できない。** CVR 0.5% の記事で 2 倍の差を p<0.2・検出力 80% で見るには before / after それぞれ約 1,700 PV、1.5 倍なら約 5,600 PV が要る。5% 程度の差は数十万 PV で判定不能。一方、有料記事の週 PV は W001 を出した週だけ 60〜300 で、出さない週は 0〜数 PV（`note記事日次` 直近 12 週）。改稿前後を暦の週で切っても意味が無い。
2. **N1〜N3 は 10/18 に実施済みだったが、before が 9 日しか無かった。** 判定条件は「before ＝ 10/9〜実施日前日で 3 週以上」と固定していたが、実施日が 10/18 なので満たせない。10/9 より前に広げると、9/14〜9/28 の 3 週は娘の円周率の投稿（9/19 1,125 万 IMP・9/21 957 万・9/29 98 万）でプロフアクセスが 5,427・4,419・744 に跳ねた週で、フォロー率 2〜4% と平常週（25〜38%）の客層が違う。
3. **N5「Threads 転載に note リンク付きセルフリプを必ず付ける」はどの経路でも成立していなかった。** 10/11 に自動化した「分割マーカー ＋ note リンク優先」は過去投稿の下書き経路（`make_threads_draft.py`）だけで、新しい W001 の同時転載（`post_from_email.sh`）は 10/2 の変更で note リンクのセルフリプを転載しない設計のまま。10/15 の W001（天王星、Threads 5,317 views）も note リンク無しで、10/11 以降 note リンク付きの Threads 投稿は 1 件も無い。

## 実施内容

### 1. 順位表に「目的」「判定 KPI」列（`docs/plans/note_funnel_measures.md`）

- 施策の狙いと成功条件の要約を順位表に並べた。ヘルパー `note_funnel_measures.py` は順位表を列位置（先頭 8 列）で読むため、新しい列は末尾に置いて順序を変えていない。正は各施策の節の「比較方法・判定条件」

### 2. N1〜N3 を実施中（2026-10-18）にし、検証窓を再設計

- before ＝ 2026-09-07〜10-17 のうち拡散週（9/14・9/21・9/28）を除く 3 週（9/7・10/5・10/12 週）。CTR と note 到達を使う率は、到達の取れる 10/9〜10/17 のみ
- 実施日を含む週の扱いを規則化：実施日が土日ならその週は before、月火なら after、水〜金は混在として除外（10/18 は土曜なので 10/12 週は before）。それまでヘルパーは 10/12 週を after に入れていた
- 広げた後の before（3 週）：X プロフ 61・フォロー率 30%・CTR 13%、Threads フォロー 7.4 / 万 views、note フォロワ純増 中央値 0

### 3. スクリプトの変更

- `scripts/note_funnel_export.py`：週次ファネルの bio 行を `BIO_START`（9/7 週）から出す。10/9 より前の週はクリック・note 到達を空欄にし、備考「クリック・到達は 10/9 から」（案内ページ化前はスキャナ混入）。10/9 を含む 10/5 週は従来どおり 10/9 からの部分集計。Threads フォロワ純増の基準を 9/7 前日に。ダッシュボードは空欄を null として率を空にするので変更不要
- `scripts/note_funnel_measures.py`：`split_weeks`（実施日を含む週の扱い）、`VIRAL_WEEKS`（拡散週の除外）、到達のある週だけで CTR・到達率を計算、X は週別フォロー率、Threads は 1 万 views あたりのフォロー・到達を表示。N3 の週列も 9/7 から

### 4. 施策の削除と保留（よーん判断）

- **N5** 削除：上記のとおり未成立。実装し直すには同時転載の経路で note リンクを tpost 形式に置き換える変更が要るが、やらないと決めた
- **N9**（無料記事の有料化）・**N11**（有料 note の増産）削除
- **N10**（価格の検証）削除：価格は下の価格設定ルールで動かし、価格区間ごとの数値はダッシュボードの「価格別 CVR」で随時見る
- **N6**（冒頭と有料ラインの見直し）は保留（未実施）。目的を「記事ページに来た人のうち買う割合（CVR¥）を上げる」と明記し、検証の前提「記事ページの PV を週数百に上げる必要がある。before / after は投稿イベント単位で切る」を記載
- ID は欠番にして順位だけ繰り上げ（10/21 の報告書が N6・N10 を参照しているため）。順位は N1 N2 N3 N8 N4 N7 N6（実施中の N8 を 4 位、保留の N6 を最下位）

### 5. note 記事の価格設定ルール（よーん決定）

1. 有料 note 記事は ¥100 から始める
2. その価格で 2 部以上購入 かつ 200 PV に達したら価格を上げる
3. その価格で 200 PV に達しても 1 部以下なら、冒頭（無料部分）と有料ラインを見直し、さらに 200 PV 溜まるのを待つ
4. 上げた価格で 200 PV 溜まった時点の 売上/1,000 PV が前の価格を下回ったら、価格を戻すか、記事をその価格で売れるものにブラッシュアップするかをその時に判断する

狙いは、記事自体を改稿して高い価格に挑戦し続けること。同一価格で改稿効果を検証する N6 とは方向が違うので、N6 は保留のまま。最初の 200 PV が公開投稿の温かい客に偏る点は「今は気にしない」。当てはめると、ニューホライズンズ ¥300（187 PV・1 部）は見直しの一歩手前、赤い空（後編）¥490（233 PV・4 部）は上げる条件を満たし、ボイジャー再点火 ¥980（388 PV・0 部）は 4 の判断対象。

## 設計判断

- **before を広げるのではなく拡散週を外す**：広げただけだと before フォロー率 5% が拡散 3 週にほぼ決まり、プロフが減っただけで「改善」に見える。平常週同士で比べる
- **実施日を含む週は曜日で振り分ける**：週単位のデータしか無い指標で、6/7 日が before の週を after に入れるのは誤り。除外だけにすると before が 10/9〜10/11 の 3 日になり使えない
- **削除した ID は欠番**：10/21 の報告書・セッション履歴が N6・N10 を参照しているため、振り直さない
- **価格設定ルールは検定ではなく引き金**：200 PV で 2 部は CVR 1% の線だが、真の CVR 0.5% でも 4 回に 1 回は 2 部出る。はしごとして動かし、上げすぎは 4 で戻す

## 確認結果

- `note_funnel_export.py --out <一時フォルダ>`：bio 行が 9/7 週から 14 行。9/7〜9/28 週はクリック・到達が空欄、10/5 週は 10/9 からの部分集計（プロフ 12・到達 0）で変更前と一致
- `note_funnel_measures.py --all`：N1 before 3 週（プロフ 61・フォロー率 30%・週別 38 / 25 / 27%・CTR 13%）、after 1 週（10/19 週、集計中）。N2・N3 も 3 週。10/12 週が before に入っていることを確認
- `read_registry` が列追加後・削除後とも順位表を正しく読む（7 件）。`py_compile` 通過
- 週次の判定は毎週日曜 20:00 JST の `/reporter-weekly-ops` routine が行う。N1〜N3 の after はプロフ累計 100 以上が条件で、平常週は週 10〜30 なので確定は早くて 11/15 の週

## 今後の課題

- N5 を復活させるなら、同時転載の経路（`post_from_email.sh`）で note リンクを tpost 形式に置き換えて転載する変更が要る
- 記事側の改稿（N6）は、W001 の本数と到達率で記事ページ PV を週数百に上げてから。複数記事に同じ改稿を施して購入件数を合算する設計なら必要 PV を 1 記事に集めずに済む
- 価格設定ルールの「200 PV に達したか」の確認は手動。週次振り返りに組み込むなら `article_price_cvr` の現在価格の区間を見るだけでよい
