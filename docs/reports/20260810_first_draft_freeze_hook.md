## 背景・動機

8/9 に W002・W003 で「執筆前チェックルール」を相次いで新設した（[W002版](../20260809_w002_first_draft_quality_rules/) / [W003版](../20260809_w003_pre_writing_rules/)）。どちらも **初稿と最終稿を突き合わせて「毎回どこを直されているか」を洗い出し、それをルール化する**という手順で作られている。

ところがこの分析の土台が残っていなかった。3プロジェクトとも `draft/draft.md` を上書きしながら仕上げる運用なので、**完成時点では初稿が消えている**。8/9 の2回はたまたまセッションが生きていて遡れたが、次からは同じ分析ができない。

よーんの言葉では「いかに僕に見せる初稿の完成度をあげられるかという問題」であり、そのためには**ユーザーが実際に目にした初稿**が記録として残っている必要がある。

## 実施内容

**初稿凍結 hook の新設（`scripts/freeze_first_draft.sh`）**

2段階で動く：

1. **PostToolUse(Write|Edit)** — 書き込み先が `projects/w00[123]/*/draft/draft.md` なら、そのパスを記録簿 `.claude/.draft-touched` に控える（`--record` モード）
2. **Stop** — 記録簿にあるパスだけを `first-draft.md` へコピーし、記録簿を空にする。`first-draft.md` が既にあれば何もしない

**なぜ Stop まで待つか**：W002 は執筆後に字数チェック・セルフチェック2周・ファクトチェック・参考情報チェックを通してからユーザーに提示する（フロー6〜11）。書き込み時点で凍結すると「ユーザーが見た版」にならない。Claude がターンを終える瞬間＝提示の瞬間なので、そこを凍結点にした。

**draft 運用の3プロジェクト統一**

実態を調べると、w001（`focus-candidates`/`hook-candidates`/`draft`）と w002（`agenda`/`draft`/`image-plan`）は既に「工程ごとに1ファイル・本文は `draft.md` 一本を上書き」で同じ思想だった。**w003 だけが `draft_vN.md` で本文の各版を残していた**。

その w003 の版管理は実態として機能していなかった：

| 記事 | 版の数 |
|---|---|
| 南極の砂漠 | 18 |
| ダイヤモンドの星ルーシー | 16 |
| アルミホイル放射線防御 | 10 |
| 嗅覚は犬に匹敵 / はちみつが腐らない理由 | 0（`draft.md` のみ） |

同じ spec なのに 0〜18 とばらつき、多くが `draft_v1` を持たず `v2` から始まる（`draft.md` が暗黙の v1）。直近の記事ほど版が少なく、運用が定着していない。18版ある記事でも実際に参照されたのは初稿と最終稿の2点だけだった。

そこで **w001/w002 方式（本文は `draft.md` 一本）に統一**し、失われては困る初稿だけ `first-draft.md` で凍結する形にした。共通ルールは `projects/CLAUDE.md` を新設して1箇所に置き、3つの spec.md の冒頭から参照する（`projects/` 配下で作業すると自動で読まれる）。

## 設計判断

**なぜ「全フォルダ走査＋導入マーカー」から「触ったファイルだけ」に作り直したか**

初版は Stop hook が `projects/w00[123]/*/draft/draft.md` を全走査していた。だが repo には既に**25件の記事フォルダに `draft.md` があり、その中身は初稿ではなく完成稿**である。走査すると導入直後の初回発火で25件分の偽の初稿が一斉に作られ、差分分析の土台が汚れる。これを避けるため「導入マーカーより新しいファイルだけ」という日付の線引きを入れていた。

よーんの「作業フォルダの中の draft.md だけ処理すればいいのでは」という指摘を受けて作り直した。**自分が書いた `draft.md` しか記録簿に載らないので、過去記事はそもそも候補に上がらない**。走査が消えた結果、導入マーカーという回りくどい仕掛けも丸ごと不要になった。残るガードは「`first-draft.md` が既にあれば何もしない」の1つだけで、これは初稿の定義そのものなのでこれ以上減らせない。

**`output/index.md` ガードを撤回した経緯**

初版には「`output/index.md` が無い時だけ凍結する（完成済み記事を除外）」というガードも入れていたが、**W002 では `output/index.md` がユーザー提示より前に作られる**（フロー10-4 で反映 → フロー11 で提示）。このガードは W002 の凍結を常にブロックしており、誤りだったので削除した。既存記事の除外は当時のマーカーだけで足りており、役割も重複していた。

**なぜ w003 の `draft_vN.md` を廃止する側に倒したか**

版を全部残す方式は情報量では勝るが、実運用で 18版まで膨らんで誰も見返していない。差分分析に必要なのは初稿と最終稿の2点であり、中間版は費用（ファイル数・混乱）に見合わない。

## 確認結果

テスト用フォルダを作って5パターン検証し、すべて期待どおりだった：

| 確認内容 | 結果 |
|---|---|
| `draft/draft.md` への書き込みが記録される | 記録簿に1行 |
| z01・docs など対象外パスは記録されない | 記録簿は1行のまま |
| Stop で凍結され記録簿が空になる | 初稿の内容で凍結・記録簿は空 |
| 推敲して再度 Stop しても初稿は不変 | `first-draft.md` は初稿のまま |
| 触っていない過去25件は一切対象外 | `first-draft.md` は1件も作られず |

`output/index.md` が先に存在する W002 想定の構成でも凍結されることを確認（撤回したガードの再発防止）。

## 今後の課題

- 原稿を書いた直後に（提示前に）ターンを終えると、その版が初稿として凍結される。`projects/CLAUDE.md` に注意として明記したが、仕組みでは防げない。
- 過去記事に残る `draft_v*.md` は削除していない（ファイル削除は確認が必要なため）。整理するかは別途判断。
- 本コミットには、同一ファイルに同居していた**別セッションの `/check-critic` スキル追加**（`.claude/skills/check-critic/`・`metadata.yaml`・w001/w002/w003/z01 spec のチェック工程）が含まれる。spec.md を行単位で分離できないため一緒にコミットした。**check-critic 自体の記録は別途必要**。
