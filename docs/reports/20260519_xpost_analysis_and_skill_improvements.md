## 背景・動機

5/15 に W003（ワンポイント解説）単独でインプレッション分析と writer-xonepoint / daily-xonepoint の改善を実施したが、その後 X 投稿一覧シートに導線メトリクス（プロフフォロー率・リンククリック率・フォロー増）が追加され、より事業視点の分析が可能になった。
次週（5/19-5/25）の運用改善方針を立てるため、直近 4 週間の全 39 投稿を「インプレッション + 事業導線」の二軸で分析し、その結果をスキル群に恒久反映した。

5/15 の改善は「ワンポイント解説の文体」のみが対象だったが、今回はストーリー型・質問回答・分析スキル自体まで含めた横断的な改善とした。

## 実施内容

### 1. データ分析（直近4週間／39投稿）

| 観点 | 主な発見 |
|---|---|
| **高フォロー率投稿** | ワンポイント解説 × 朝6時 × 「数字 or 日常入り口」フックがプロフフォロー率 9〜11% を出す（中性子星 11.2%、GPS相対性理論 10.3%、原子はスカスカ 9.7%、ニュートリノ 9.1%） |
| **高リンククリック投稿** | ストーリー型 → セルフリプnoteリンクの2段構造が機能（SOHO本編72,633 IMP・セルフリプ note リンク211クリック） |
| **低反応投稿** | 個人ネタの雑投稿（GW・家族・風景）が IMP 400-900 で頭打ち、フォロー増ほぼゼロ。科学ネタの 1/10 の反応 |
| **長文質問回答の課題** | 800字超の長文化でエンゲ率3〜4%に低下 |
| **文字数最適レンジ** | 200〜260字でエンゲ率8〜12%・フォロー増8〜15件のスイートスポット |
| **時間帯** | 朝6:00投稿が支配的、夜21時以降の補助スロットは未検証 |

### 2. スキル修正（5ファイル + 新規1ファイル）

#### writer-xonepoint/SKILL.md
- 文字数を「140〜300字」から **「200〜260字推奨・最大300字」** に変更（実データの高反応レンジ反映）
- 文体ルールに **明示CTA禁止** を追加（「フォローしてください」等は本文の質で取りに行く方針）
- 締めルール（セクション4）を **「読者の『今日』に再接続する1文」必須化** に強化。NG例に「自然はすごい」「これが科学の面白さだ」など教訓化・抽象化パターンを追加

#### writer-xstory/SKILL.md
- 本編冒頭に **「日付・地名・状況の具体3点セット」必須化** を追加（SOHO 72,633 IMP の構造を一般化）
- **note 誘導セルフリプの定型ブロック**を追加（本編は完結させ、セルフリプで「全部 note に書いた → [URL]」型を送る）

#### brand.md
- 共通NG表現に **直接的な反応誘導**（フォロー・いいね・RT・ブクマ誘導）を追加

#### writer-xqa/SKILL.md（新規）
- X 上の質問回答専用スキル
- **400字以内・3段以内・先に結論** を厳守
- 400字を超える内容は note 誘導 or 「続きは明日6時」の具体的次回予告で切り上げ
- 質問本文の引用・お世辞・名指しを禁止

#### analyze-impression/SKILL.md
- データソース列マップを更新（Q列プロフアクセス・AA-AF列の導線メトリクスを明示）
- STEP3 で **基本メトリクス（A:R）と導線メトリクス（AA:AF）の2範囲を併行取得** するよう変更
- STEP5 に以下を追加：
  - 投稿種類別の集計を**デフォルト出力化**
  - **異常パターン抽出**（高IMP×ゼロフォロー、低IMP×高フォロー率、高クリック×ゼロフォローの3類型）
  - インプレッションだけで判断せず**導線メトリクスを必ず併記**する原則を明示

#### metadata.yaml
- `writer-xqa: コンテンツ制作` を追加

## 設計判断

- **5/15 改善との重複回避**：「日常入り口」「数字フック」「4段構成」は既に writer-xonepoint に実装済み。今回は新たに判明した「文字数の最適レンジ」「明示CTA禁止」「締めの『今日』再接続」のみ追加した。
- **brand.md の雑投稿運用ルール（個人投稿は科学接続必須化）は不採用**：よーんの判断で、運用は柔軟性を残す方針。
- **writer-xqa を新設**（既存 writer-xonepoint への質問回答機能追加ではなく）：質問回答は「短く密度高く・続きは note」という独立した制約があり、ワンポイント解説と別運用の方が運用判断が明確になるため。
- **明示CTA禁止をスキルとブランド両方に書く**：writer-xonepoint には「文体ルール」として具体例つきで、brand.md には「すべての発信に共通」として原則で書き分け。
