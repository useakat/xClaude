## 背景・動機

従来の daily-xonepoint スキルは、STEP 4 でローカルファイル保存後に自動で `commit_and_sync.sh` を実行して git コミット・プッシュを行っていました。

しかし、このタイミングでの git 記録は不要であることが判明しました。理由：

1. このステップはメール下書き作成前の段階であり、まだ投稿は確定していない
2. 実際の投稿記録は `database/outputs.csv`（Sheets が正）で管理されており、投稿実行時に自動記録される
3. ローカルのファイル保存は参考情報に過ぎず、git 履歴に残す必要がない

これにより、スキル実行時間を短縮し、不要な git トラフィックを削減できます。

## 実施内容

- **STEP 4 からファイル保存処理のみを抽出** — git コミット関連の処理（`commit_and_sync.sh` 呼び出し）を削除
- **STEP 4 の説明テキストを簡潔化** — 「ファイル保存 & Git コミット」から「ファイル保存」に改題し、該当する説明文を削除
- **完了判定メッセージの更新** — 「ファイル保存・git push 完了」から「ファイル保存完了」に変更

## 設計判断

**ファイル保存自体は残す理由**：
- 原稿ファイル（outputs/drafts/）の保存は、ユーザーがローカルで参照できるようにするため
- ただし git 記録までは不要

**削除の判断基準**：
- スキルが実行する各ステップが必ずしも git コミット対象ではないことを改めて確認
- 参考資料と正式記録を区別することで、git の責務を明確化

## 確認結果

修正後の動作確認：
- ✅ STEP 3 (品質チェック)から STEP 5 (メール下書き)への流れに問題なし
- ✅ ファイル保存が正常に実行される（git 記録なし）
- ✅ メール下書き作成も引き続き正常に動作
- ✅ 既存スキルの呼び出し側で修正不要（スキル内部の最適化）
