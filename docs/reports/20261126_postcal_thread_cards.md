## 背景・動機

よーんから「予約投稿サイトをスレッド形式の投稿にも対応させたい」という要望があった。

調べると、postcal は「セルフリプ」欄に `=====` だけの行で区切って書けば、X では返信チェーン、Threads でも同じ順の連結として投稿する仕組みをすでに持っていた（`scripts/post_scheduled.py`）。足りていなかったのは画面で、1 つの入力欄に区切り記号を手で書く形だったため、何本のスレッドになるのか、各投稿が何字なのかが見えなかった。

そこで投稿の仕組みは変えず、編集画面だけを「1 投稿 = 1 カード」の形に変えた。

## 実施内容

- 編集画面の「セルフリプ」欄を「続きの投稿（スレッド・セルフリプ）」に変更。1 投稿を 1 枚のカードで表示し、「2 本目」「3 本目」…と番号を付ける
- 「＋ 続きを追加」でカードを増やし、各カードの「削除」で消せる。追加・削除のたびに番号を振り直し、枠の見出しに「全 n 本」を出す
- カードごとに字数カウンタを付けた（数え方は本文と同じで、空白・改行を除く）
- カレンダーのチップに続きの本数（例「＋2」）、一覧に「＋続き2本」を表示
- フォームの受け取りを、カード（`name=reply`）が投稿の数だけ届く形に変更。カード内に `=====` だけの行があればそこでも分割する。旧形式の `name=replies`（1 欄に `=====` 区切り）も引き続き受け付ける
- CSS / JS の読み込みに `?v=20261126` を付け、ブラウザのキャッシュで古い画面が出ないようにした

## 変更ファイル

| ファイル | 変更内容 |
|---|---|
| `postcal/templates/form.html` | 「セルフリプ」のテキストエリア 1 つを、カードのリスト（`thread_item` マクロ）と「＋ 続きを追加」ボタンに置き換え。追加用の `<template>` を同じマクロから生成 |
| `postcal/static/app.js` | カードの追加・削除・番号の振り直し・カードごとの字数カウンタ。字数カウンタの処理を `bindCounter()` に切り出し |
| `postcal/static/style.css` | カードと小さいボタン（`.btn.small`）のスタイル |
| `postcal/app.py` | `parse_form()` が `form.getlist("reply")` を読むように変更（各値を `=====` 行でも分割）。使わなくなった `replies_text` をテンプレートに渡すのをやめた |
| `postcal/templates/calendar.html` | チップと一覧に続きの本数を表示 |
| `postcal/templates/base.html` | CSS / JS の URL にバージョン（`?v=20261126`）を付与 |

## 設計判断

- **投稿スクリプトと DB は変えない**。`replies_json`（文字列の配列）と `post_scheduled.py` の返信チェーンはそのまま使える。変えたのは入力の見せ方だけなので、投稿の動き（X は順に返信、Threads は同じ順、note.com リンク入りの投稿は Threads に載せない、outputs シートには先頭の投稿だけ記録）は従来どおり
- **2 本目以降の画像・動画は付けない**。よーんの判断（「ひとまず不要」）。付ける場合は DB の形・`post_scheduled.py`・`post_threads.py` の変更が必要になるため、今回の範囲から外した
- **予約ファイルの書式は変えない**。`## セルフリプ` を `=====` で区切る形のまま取り込め、画面ではカードに分かれて表示される
- **`=====` での分割は残す**。スレッド全文を 1 枚のカードに貼り付けても、保存時に分割される

## 確認結果

- 一時 DB を使った Starlette TestClient で、登録・更新・旧形式（`replies`）の受け取り・続きなし・入力エラー時にカードの内容が残ること・投稿済みの予約で編集できないことを確認
- 一時 DB の postcal を別ポートで起動し、ヘッドレスブラウザ（スマホ幅 390px）でカードの追加 3 枚 → 1 枚削除 → 保存 → 再表示を通し、番号・「全 n 本」・字数カウンタが合うこと、JavaScript のエラーが出ないことを確認
- `postcal.service` を再起動し、`/healthz` が 200、`/new` に「＋ 続きを追加」が出ることを確認
- 本番 DB への書き込みと X / Threads への投稿は行っていない。変更時点で未投稿の予約 7 件に続きの投稿が付いたものは無く、実データのスレッドは画面で未確認

## 今後の課題

- 2 本目以降への画像・動画の添付（必要になったら）
- スレッドの途中で X の投稿が失敗した場合は、従来どおりそこで止めてメールで知らせるだけで、自動の再開はしない
