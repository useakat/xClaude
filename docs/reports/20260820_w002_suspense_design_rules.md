## 背景・動機

ユーザーから「今の note 記事は正確性とわかりやすさを重視して書いているが、読んでいて面白くない。説明が多く、頭で理解しないといけないところが多い。続きが読みたくなるようにするには？」という診断相談があった。

分析の結論は、**原因は説明の量ではなく、制作システム全体が「誤解ゼロ」に最適化されていて「面白さ」を作る工程がどこにもない**こと。具体的には：

1. check-reader / check-critic / ユーザーの「なぜ？」への対応が、いずれも本文への説明追加で解決されるため、合成すると「全ての疑問がその場で説明される原稿」ができる
2. 疑問には**理解の疑問**（なぜ壊れる？＝即答すべき）と**物語の疑問**（助かるのか？＝保留こそが面白さ）の2種類があるのに、同じ「即時解消」の扱いをしていた。問いと答えが同じ段落に同居する文が多い（「チームの出した答えは、拍子抜けするほどシンプルだった。冬ごもりをする」）
3. 章の頭が背景説明（季節学など）で始まり、仕組みの説明が出来事の**前**（＝読者の宿題の位置）に置かれていた
4. 危険・賭け金が一般論で立てられ、名前のある人間の決断の場面が少ない

ルール化に先立ち、公開済みオポチュニティ記事の「冬ごもり」章で **Before/After 実験**を実施。管制室の決断から入り、スピリットの凍死（notebook で裏取り）を賭け金に置き、「なぜ、斜面だったのか」で説明を出来事の後の種明かしに移した場面主導版を提示し、ユーザーが方向性を承認（「悪くなさそうだね。落とし込んで」）したためルール化した。

## 実施内容

- **brand.md に新セクション「物語の疑問と理解の疑問（サスペンスの設計）」**を新設。運用ルール4点：
  1. **説明は質問の後** — 仕組み・幾何・背景の説明は、読者がその答えを欲しがる出来事の後に種明かしとして置く。先回りしてよいのは理解の疑問（動力・位置・因果の一段）だけ
  2. **問いと答えを同じ段落に密着させない** — 見せ場では問い→場面（実行）→種明かしの順で1拍以上あける
  3. **章の頭は場面・決断・異変から入る** — 背景説明で章を開始しない。背景は危機の文脈の中に1文で後置
  4. **賭け金（stakes）は一般論でなく記憶で立てる** — 前例・当事者が知っている失敗で立てる（出典の範囲で）
- 出力前セルフチェックに対応2項目を追加
- **spec.md 構成フェーズに「感情の設計図」**を追加 — agenda に章ごとの (1) 物語の疑問（**保留リスト**＝どの章で回収するか） (2) 感情の線 (3) 1場面 を明記。**当事者の一次証言・発言記録の有無を構成段階で notebook 確認**し、無い題材は出典済み事実だけで場面を組む設計にする（セリフの捏造は不可）
- spec.md 本文フェーズに「説明は質問の後（章を書くたび）」の点検を追加
- **保留リストをチェック系に配線** — check-reader（フロー8）: 保留リストにある物語の疑問は「設計どおりの保留」として改稿対象から除外（回収章まで読んで未回収なら通常どおり指摘）。**読者役にはリストを渡さず writer 側で選別**し、読者役の隔離を維持。check-yohn（フロー10.5）: 感情の設計図を検品役に渡し、設計どおりの保留を指摘させない。persona-yohn.md 基準6に「問いと答えの密着」「章頭の講義開始」「一般論の賭け金」の指摘観点を追加

## 設計判断

**面白さは検品でなく設計（agenda 段階）に置いた。** 検品系（check-reader/check-critic）は欠陥の除去には強いが、面白さ（緊張・場面・感情の線）は執筆後に足せない。よって新ルールの本体は構成フェーズの「感情の設計図」で、検品系には「設計を壊さない」（保留を潰さない）連携だけを入れた。

**保留リストは読者役に渡さず、writer 側でフィルタする。** 読者役に渡すと「制作文脈を知らない読者」という check-reader の根本設計（知識の呪いの回避）が壊れる。読者役は素朴に報告し、writer が選別時に保留リストと突き合わせる形にした。

**理解の疑問は保留の対象にできない、と明記した。** サスペンス設計を口実に因果の飛躍が放置されるのが最大の副作用リスクのため、保留できるのは物語の疑問（結末・成否・正体への期待)だけに限定した。

**セリフの捏造禁止を場面設計とセットで明記した。** 場面主導にすると当事者の発言を書きたくなるが、Before/After 実験でもこの冬の当事者の発言記録はソースに存在しなかった。一次証言の有無を構成段階で確認し、無ければ日付・数値・動作などの出典済み事実だけで場面を組む、という制約を設計図に組み込んだ。

## 確認結果

- Before/After 実験（オポチュニティ「冬ごもり」章・約1,050字→約1,250字）で、説明の総量を減らしつつ（自転軸の説明等を削除）、決断の場面・スピリットの凍死という賭け金・「なぜ、斜面だったのか」の種明かし構造に組み替えられることを確認。追加事実（スピリットの凍死の経緯・2012年5月8日の3.7m 前進・静止中の観測60回）はすべて記事の notebook で裏取り済み
- ユーザーが方向性を承認したうえでルール化・commit 済み（`5057f65`、master へ push 済み）
- 実効性の確認は次回の W002 記事制作時に行う（agenda に感情の設計図が作られ、保留リストが check 系で尊重されるか）
