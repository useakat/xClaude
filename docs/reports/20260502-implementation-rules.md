## 概要

`CLAUDE.md` に「実装ルール」という新規セクションを追加し、Google サービスとの連携、およびスクリプト化すべき処理の判断基準を明文化しました。

これまでのプロジェクト実装で蓄積されたベストプラクティスを、明確なルールとして定義することで、今後の実装品質と効率性を向上させます。

---

## 追加されたルール

### 1. Google サービス連携ルール

**ルール内容**：
```
Google サービス（Gmail、Drive、Sheets など）との連携は、必ず gws CLI を使って実装する
```

**詳細**：
- Python SDK や MCP ツールではなく、bash スクリプト経由で gws CLI を呼び出す
- メリット：認証管理の統一、トークン節約、実装の簡潔性

**根拠**：
- 本プロジェクトでは既に Gmail 関連スクリプトを gws 化完了
  - `scripts/create_gmail_draft.sh`（下書き作成）
  - `scripts/get_gmail_body.sh`（本文抽出）
  - `scripts/download_gmail_attachment.sh`（添付ダウンロード）
- CLAUDE.md に明記：「外部認証は基本 gws CLI に統一」
- 実績：複数の Gmail 操作が gws で安定動作中

### 2. スクリプト化の原則

**ルール内容**：
```
確実な処理実行とトークン節約のため、スクリプト化できる処理はなるべく bash / Python スクリプトを作成して実行する
```

**スクリプト化に向いている処理**：
- データ読み書き（CSV、JSON、YAML）
- ファイル操作（保存、削除、移動、圧縮）
- API 呼び出し（Gmail、Drive、Sheets、X など）
- git 操作（commit、push、branch 管理）
- テキスト変換・整形・バリデーション
- データベース操作

**スクリプト化に向かない処理**：
- コンテンツ作成（ブログ、SNS 投稿文など）
- 創造的な判断が必要な作業
- 複雑な条件分岐が多い処理

**メリット**：
- **トークン節約**: スクリプトが処理を担当→ Claude の推論コスト削減
- **確実性**: スクリプトで確実に実行→再現性・信頼性向上
- **監査性**: スクリプトコードを版管理→何をしたか履歴が残る
- **保守性**: スクリプトを再利用→類似処理での開発時間短縮

## 背景・動機

### 問題認識

1. **Google 連携の複数化**
   - MCP ツール、Python SDK、gws CLI が混在していた
   - 認証管理が複雑、設定が統一されていない
   - トークン依存関係が不明確

2. **トークン消費の無駄**
   - Claude が直接実行できる処理を Claude にやらせていた場合がある
   - 同じ処理の繰り返しで毎回トークンを消費

3. **スクリプト化のメリット周知不足**
   - ファイル I/O、API 呼び出しなどはスクリプピング適合度が高い
   - しかし「ケースバイケース」という曖昧な判断基準のみ

### 解決策

明確なルールを定めることで：
- 実装時の判断が高速化
- Google サービスの統一された呼び出し方
- スクリプト化優先度の明確化

## 実装例

### 例 1: 既に実装済み（Google サービス）

**daily-xonepoint agent の STEP 5**

**Before**: Gmail MCP ツール（mcp__claude_ai_Gmail__create_draft）を使用
```
Gmail MCP ツール → 認証設定が複雑
```

**After**: gws CLI ベースのスクリプト
```bash
bash scripts/create_gmail_draft.sh \
  --to useakat@gmail.com \
  --subject "..." \
  --body-file "..."
```

**効果**:
- 認証: gws CLI の統一設定を使用
- トークン: スクリプト側で処理→ Claude は指示のみ
- 再現性: bash スクリプトのコード版管理

### 例 2: 既に実装済み（スクリプト化）

**CSV ネタ管理**
- `scripts/csv_reader.py` - ネタ一覧取得
- `scripts/update_neta_status.py` - ステータス更新
- `scripts/sheets_manager.py` - Sheets 同期

これらはすべてスクリプト化され、CLI から呼び出し可能。

## 今後の適用

このルールは、以下のシーンで活用されます：

1. **新規 Google 連携機能の実装時**
   - 「gws CLI を使ってスクリプトを作成する」が判断基準に

2. **既存スクリプトの拡張時**
   - 「Claude が判断する部分」と「スクリプトで実行する部分」の境界が明確

3. **新規スキル・エージェント設計時**
   - API 呼び出しは率先してスクリプト化
