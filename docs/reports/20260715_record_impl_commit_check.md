## 背景・動機

「報告書・変更ログだけがコミットされ、肝心の実装ファイルが未コミットのまま残る」事故が繰り返し起きていた：

1. 7/4 の mcp-gsheets 事前ウォーム実装（docs のみコミット、実装は後日反映）
2. 7/7 の `enableAllProjectMcpServers` 追加（docs のみコミットで対策が効かず、7/14 に同じ障害が再発してから発覚）

報告書には「実施した」と書かれているのに実装が反映されていないため、同じ障害が再発するまで誰も気づけない。これを記録フローの中で機械的に検出する仕組みが必要だった（実装コミットは 7/14 `e54e93f`）。

## 実施内容

- `/record` スキルに STEP 4.7「実装コミット照合チェック」を追加。変更ログへの追記・push の前に、報告書の「変更ファイル」表に挙げた各ファイル（docs 自身は除く）について以下を照合する：
  - `git status --porcelain -- <file>` で未コミット変更が残っていないこと
  - `git log --oneline -3 -- <file>` でそのファイルを変更したコミットが直近に存在すること
- いずれかを満たさない場合は push に進まず、よーんに報告して指示を待つ。

## 確認結果

- 本報告書自身の記録フロー（7/15 の /record 実行）で STEP 4.7 を通過することを確認。なお同日の調査で、6/27 報告書記載の許可ルールが未コミットだった同パターンの3件目が見つかっており（[報告書](./20260715_mcp_gsheets_tool_allow_exact_rules/)）、このチェックの必要性が裏付けられた。

## 今後の課題

- チェック対象は「変更ファイル」表に依存するため、表への記載漏れがあると検出できない。報告書作成時に `git show --stat` と突き合わせて表を書くことで補完する。
