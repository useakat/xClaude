## 背景・動機

プロジェクト内で Gmail 連携に MCP ツール・Python SDK・gws CLI が混在しており、認証管理が複雑化していた。また Claude が直接実行できる処理もトークンを消費しながら実行しており非効率だった。明確なルールを設けることで今後の実装判断を統一する。

## 実施内容

- CLAUDE.md に「実装ルール」セクションを新設
- Google サービス連携は gws CLI を使うルールを明文化
- スクリプト化に向く処理・向かない処理の基準を定義

## 変更ファイル

| ファイル | 変更内容 |
|---|---|
| `CLAUDE.md` | 「実装ルール」セクション追加（Google サービス連携・スクリプト化の原則） |

## 設計判断

Python SDK ではなく gws CLI を選んだ理由：認証設定が `~/.config/gws/` に統一されており、bash スクリプトから呼び出せるため実装がシンプルになる。MCP ツールと違いトークン消費もない。

## 確認結果

既存の Gmail 関連スクリプト（`create_gmail_draft.sh` 等）がすべて gws CLI ベースで動作していることを確認。
