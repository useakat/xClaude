## 背景・動機

週次の発信運用振り返り（`/reporter-weekly-ops`）は 2026-11-01 に Wiki（Starlight）のサイドバーから辿れるようになった（同日の「Wiki 報告書サイドバーに『発信運用振り返り』『マネタイズ月報』を追加」）。それまでは数字が表と箇条書きの列挙だけで、週の状態（基準未達・当週の跳ね・W001 の当たり率）を一目で掴めなかった。当初 claude.ai の Dashboard アーティファクトとして HTML 化を試みたが、Wiki 掲載に一本化する判断に合わせ、レポートの md 自体にビジュアル要素を埋め込む方式にした。

実装・コミットは 2026-11-01（別セッション）。変更ログへの記載漏れを本日補完する。

## 実施内容

- **W44 レポート**（`docs/reports/ops-weekly/2026-W44.md`）を見本としてビジュアル版に改稿
  - 冒頭に KPI タイル 6 枚（週間インプ＋前週確定／X 投稿本数＋threads 転載／W001 本数／note 公開本数／投稿 0 本日／当週最大 IMP＋倍率）。基準未達は赤
  - ① 実績表の直後に **W001 実IMP の分散記録チャート**：半減後 7/3〜の 16 本を対数スケールの棒グラフ SVG にし、2 万以上の本に数値ラベルを付ける
  - 「当週の X 投稿（n 本）」セクションを新設し、1 本 1 行で日付・題材・フック記録（型・謎・自分事）・IMP バー（平方根スケール、最大の 1 本だけアクセント色）・倍率を表示
  - 表内の判定（×／○／保留／支持）と伸び・沈みの見出しを色付き `<span>` に
- **SKILL.md**（`.claude/skills/reporter-weekly-ops/SKILL.md`）の STEP 6 に「ビジュアル要素」節を追加
  - 4 要素（KPI タイル／W001 分散記録チャート／当週投稿バー／判定の色付け）の HTML・SVG の型と、チャートを生成するインライン python スニペット
  - 本文テンプレートに各要素の挿入位置（「ここにビジュアル要素 1〜3」）を明記
  - 週報リンクは小文字で書く注記（Astro のルートが小文字で生成されるため）
  - メール送信時は `<div>`・`<svg>`・色付き `<span>` を除去したテキスト版にし、冒頭に Wiki ページの URL を 1 行添える

## 設計判断

- **色は Starlight の CSS 変数だけを使う**（`var(--sl-color-red/green/orange/accent/gray-3/4/5)`）：生の色コードはライト／ダーク片方のテーマで読めなくなる
- **チャートは外部画像ではなく md 内のインライン SVG**：画像ファイルの生成・配置・push の工程を増やさず、routine が md を保存・push するだけで Wiki に出る。生成はスキル内の python スニペットで、分散記録の数値を渡すだけ
- **バー幅は平方根スケール**：IMP が 844〜33,111 と桁で違うため、線形だと小さい本が消え、対数だと差が見えない
- **メールは別途テキスト版**：Gmail では raw HTML が読めないため、ビジュアルは Wiki で見る前提にし、メールには URL を添える
