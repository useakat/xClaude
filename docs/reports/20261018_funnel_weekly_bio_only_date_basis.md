## 背景・動機

note 導線ダッシュボードの「導線ファネル（週次）」で、10/12〜10/18 の X bio 行が CTR 55%・note 到達率 31% と不自然な値になっていた。よーんの依頼で原因を調べたところ、2 つの問題が重なっていた。

1. **クリックに自動アクセスが混ざる。** Caddy の生ログで、10/12 の X bio ビーコン 14 件のうち 12 件が 10:17〜11:24 の 1 時間強に集中し、1 秒おきに別の海外 IP から来ていた。Accept-Language は en-US / ru-RU が大半で、10/8 以降の X bio ビーコン 35 件のうち日本語設定は 1 件だけ（Threads 投稿リンクの tpost は 9 割以上が日本語）。現在の判定（UA の bot 判定と `/note` 付きビーコン）は、JS を実行して UA も偽装するスキャナを通してしまう。転送ページはビーコン送信後すぐ note に転送するので、クリック 16 に対して note 到達 5 という「低い到達率」は、note 側が自動アクセスを数えていないだけだと推定した。
2. **分母と分子の日付基準が違う。** リンク到達（プロフアクセス）は「その週に投稿したポスト」の X投稿一覧の値の合計で、クリックと到達は日付で数えていた。分母 29 は 4 本の投稿の値（2＋8＋19＋0）にすぎず、同じ週の人の流れになっていなかった。

あわせて、X 固定ポストの行は「プロフアクセス → 固定ポストの IMP 週増分」という作りだったが、固定ポストの IMP はタイムラインや検索からの表示が大半でプロフ経由でない。よーんの判断で、固定ポストをプロフの一部として扱うのは正しくないとして表から外すことにした。投稿 → プロフ（どの投稿がプロフに人を送ったか）は X投稿一覧のプロフ率で分かり、note とも直接関係しないので、ダッシュボードには入れない。

## 実施内容

### 週次ファネル（`funnel_weekly.csv` とページ）

- 経路を **X bio / Threads bio の 2 行（2 表）** に整理。X 固定・Threads 固定の行と、固定ポスト日次の週増分・固定期間中クリックの集計コードを削除
- **X bio の値をすべて日次記録の週合計に統一**（日付基準）
  - 総インプ ＝ 日次記録 R「インプ」
  - プロフアクセス ＝ 日次記録 S「プロフ」（10/1 以降は毎日入っている）
  - フォロー ＝ 日次記録 M「新規フォロワ数」。見出しが「新規フォロヷ数」と表記ゆれしているので正規表現で探す
  - note 到達 ＝ note流入元 X bio（従来どおり）
  - クリック（bioクリック X bio）は CSV に残すが、ページには出さない
- **ページの X bio 表**：週 | 総インプ | プロフアクセス | フォロー | フォロー率 | CTR | note 到達。**CTR ＝ note 到達 ÷ プロフアクセス**、フォロー率 ＝ フォロー ÷ プロフアクセス。クリック列と到達率列は削除
- **Threads bio 表**：週 | アカウント views | フォロー | クリック | 到達率 | note 到達。常に空だった 3 列（到達率・プロフ閲覧・CTR）を外し、フォロー列を追加。Threads は新規フォロー数が取れないので、日次記録 V「threads フォロワ数」の週末値の差（解除分を含む純増。FUNNEL_START 前日が最初の基準）
- CSV に「フォロー」列を追加（列名は変えていないので routine の変更は不要。データセット数は 8 のまま）
- 「数字の定義」とデータセット `funnel_weekly` の説明を書き直し、固定ポストを外した理由、CTR が厳密には「プロフを開いた人が note まで来た率」であること、ビーコンの自動アクセス混入（10/12 の 14 件）を記載

### ページのその他の変更（よーんの指示）

- 投稿ごとのファネル（X・Threads）の表を、見出しクリックで列ソートできるようにした（数値列は大きい順から、文字列は昇順から。空欄は末尾、▲▼ 表示）。汎用の `sortable()` を追加
- 転送クリック明細・固定ポスト履歴・note リンク付きの X 投稿の 3 表を、ページ最下部（数字の定義の下）へ移動
- 日別グラフを「note 到達の流入元（日別）」が左、「経路別の人のクリック（日別）」が右に入れ替え

## 設計判断

- **CTR の分子を note 到達にする**：転送サイトのビーコンは UA 偽装のスキャナを通してしまうが、note 側の参照元 PV はそれをほぼ数えない。厳密なクリック率ではないが、bio の役目は note まで連れていくことなので、実用上はこの率の方が知りたい値に近い（よーんの判断）。note流入元の同期が 1 日遅れることがあり、集計中の週は少なめに出る
- **ビーコン判定の強化はしない**：Accept-Language に ja を含むものだけを人と数える案もあったが、日本語以外の設定の本物の読者を落とす。クリック列を表から外す方を選んだ
- **固定ポストの日次スナップショット（`record_pinned_post.py`、05:50）は止めていない**：週増分を使う表は無くなったが、cron の停止はよーんの判断に委ねる
