## 背景・動機

競合アカウント `@galileo_fun`（フォロワー1.3万・開設2026-03-26）の全独立投稿90件を X API で取得し、10万IMP超えの13件を分析した結果、**タイムラインで実際に読者が見ているのは冒頭280weight分だけ**であり、そこでの引きがIMPを決めていることが分かった。

分析で確認した事実：

- 10万IMP超え13件のうち9件は**標準ツイート（280weight以内）**で、本文weightは262〜279。**上限280に対して余白1〜4しか残していない**（意図的に上限ぎりぎりまで使い、答えの直前で「…」で止め、答えはスレッド返信に置く設計）
- 残り4件は長文投稿（280weight超）で、可視部分は142〜149字で切れていた
- 形式別成績（挨拶7件を除く83件）：標準ツイート n=55 平均603,409／最大24,875,884、長文投稿 n=28 平均118,693／最大889,353

一方、こちらの既存 W003 投稿5本を280weightで実測すると、**5本すべてが助詞・動詞の途中で機械的に切れて**いた（「直径およそ8,000kmに達し」「pHは3から4の」「脈は2割ほどすっと落」「輪になっている」「その帯の内側の縁から5%しか」）。切れ位置が設計されておらず偶然に任されている状態だった。

W001（約600字）も W003（200〜260字）も必ず280weightを超えるため、全投稿が折り返される。**読者が最初に見る可視ブロックの終わり方を設計対象に加える**のが本変更の目的。

## 実施内容

- `scripts/x_fold_split.py` を新規作成。本文を280weightで分割し、可視ブロック・畳まれる部分・切れ目前後の文脈を返す
- `/check-reader` に **`--fold` モード**を新設。可視ブロックだけを読者役サブエージェントに渡し、「さらに表示」を押すか通り過ぎるかを二択で判定させる
- W001 に**ステップ5.5（本文執筆前に可視ブロックを確定）**と**ステップ6.4（ユーザー提示前に `--fold` を最大3ループ）**を新設、採点基準に**項目8「折り返し位置」**を追加
- W003 に**ステップ5.4（`--fold` を最大3ループ）**を新設、4段構成の段3に**折り返し制約**（「問い1行」を可視側・「端的な答え」を折り返しの向こうへ）を追加、採点基準に**項目7「折り返し位置」**を追加

## 設計判断

**1. 既存の `/check-reader` 通常モードを流用せず `--fold` モードを新設した**

通常モードは「疑問が出なくなるまで改稿」する設計で、終了条件が理解度8以上。意図的に途中で切れている可視ブロックを渡すと【フック未回収】が減点として出てしまい、**評価基準が反転する**。可視ブロックでは「謎が残っていること」が合格条件なので、別モードにした。`--plan` モードの前例に倣った3つ目のモードになる。

**2. weight の計算をスクリプトに寄せた**

全角2・半角1の混在で、同じ「140字前後」でも本文により146〜148字とぶれる。Claude が目視で数えると精度が出ないため、`x_fold_split.py` を必ず経由させる形にし、SKILL.md・spec.md・brand.md の各所に「目視で数えない」と明記した。

**3. galileo と同じ「標準ツイート＋スレッド返信」形式への変更は採用しなかった**

galileo の最高記録（2,488万IMP）を出しているのは標準ツイート形式だが、W001 は「本編＝X内完結の約600字1投稿／セルフリプ＝note導線」という2段構造で、スレッド返信（本文の続き）とセルフリプ（note導線）が競合する。`plan.md` の Funnel 設計そのものの見直しになるため、今回は現行の長文形式のまま切れ位置を設計する案を採用した。形式変更は別途検討する。

## 確認結果

- `python3 scripts/x_fold_split.py projects/w003/20260812_太陽が明るくなる/output/index.md` → 全303字/578weight、可視146字/279weight、切れ目「…その帯の内側の縁から5%しか」を正しく検出
- `--json` 出力で `visible`/`hidden`/`cut_before`/`cut_after` が取得できることを確認
- 280weight以内の短文を渡すと `折り返しなし` と返り、`--fold` をスキップできることを確認
- 既存 W003 直近5本すべてで折り返し位置を検出し、5本とも語・説明の途中で切れていることを確認（本変更の必要性を裏づけ）

## 今後の課題

- **実機での折り返し位置の確認**：280weight という境界は X API の長文投稿判定（`note_tweet` フィールドの発生位置）から確定させたもので、公式アプリ／Web の「さらに表示」表示位置が完全に一致するかは未検証。実投稿で数本確認すると精度が上がる
- **形式変更（標準ツイート＋スレッド）の検討**：galileo のデータ上、長文投稿の最大IMPは88.9万に対し標準ツイートは2,488万。バズの上限を作っているのは標準ツイート形式であり、W001 の Funnel 設計を含めた再検討の余地がある
- **効果測定**：本変更後の投稿でIMPが改善するかは未検証。数本の投稿後に `/ops_analyze-posts` で確認する
