## 背景・動機

9/24 分の日報（routine 実行）に対し、よーんから内訳の書き方について手直しが入った。いずれもその日限りの直しではなく、**毎回同じ形で必要になる記載ルール**だったため、スキル側に固定した。

| # | 指摘 | 生成側の原因 |
|---|---|---|
| 1 | 引用は `引用` の項目に書き、オリジナルポスト数に入れない | 日次記録シートの `ポスト数` は**引用を含んだ件数**（9/24 はポスト数3＝短文1＋引用2）。スキルはこれをそのままオリジナルポスト数に使い、引用RTも内訳に並べていた |
| 2 | 引用の内訳には「その他（〜）」などのラベルを付けない | 引用RTは outputs に記録が無いため、ラベル判定で必ず「その他」になっていた |
| 3 | 内訳の行末の「。」は不要 | SKILL と style-reporter.md の書式・例文が `[数値]。[一言]` 固定で、一言が無い行にも「。」が残った |
| 4 | 内訳はインプの大きい順に並べる。ただし並べ替えは型（長文・短文・ワンポイント解説など）ごと | 並び順の規定が無く、投稿時刻順に並んでいた |

#1 は [8/10 の記載ルール整備](./20260810_reporter_daily_format_rules/) の「今後の課題」に「`引用RT` を内訳に載せるかは触れていない」として残っていた論点で、今回よーんの判断で「内訳から外し、引用の項目の下に書く」に確定した。

#4 は当初「内訳全体をインプ順」で提案したが、よーんから「オリジナルポストや threads は型ごとにグルーピングしているので、インプ順は型の中で行う」と指定があり、型の中だけで並べ替える形に修正した。

## 実施内容

`.claude/skills/reporter-daily/SKILL.md`

- **STEP 2 にオリジナルポスト数の算出式を追加** — `originals = posts − quotes`。以降の X セクション・ファイルフォーマット・完了報告のサマリーを `posts` から `originals` に置き換え
- **STEP 4 で引用RTを分離** — `ポスト種類` が `引用RT` の行は `x_quotes_today` として別に持ち、オリジナルポストの内訳（`x_posts_today`）に入れない。引用はラベルを付けないため outputs との突合も不要とした
- **STEP 8 X セクション** — `引用` の下に引用の内訳を並べる。オリジナルポスト数に引用を含めないことを明記
- **「引用の内訳の項目フォーマット」を新設** — `　　・[要約]：[数値]`。ラベル・括弧なし
- **内訳の書式を2形に分割** — 一言なし `：[数値]`（末尾「。」なし）／一言あり `：[数値]。[一言]`。既存の例文からも行末の「。」を削除
- **「内訳の並び順」を新設** — オリジナルポスト（X・threads）は型ごとにまとめ、型の順は **長文ストーリー → ワンポイント解説 → 質問回答 → 短文 → その他** で固定。インプ（threads は views）の大きい順は同じ型の中だけ。引用は全体をインプの大きい順
- **保存前チェックに4項目を追加**（5〜8：引用の分離／引用の書き方／末尾の「。」／並び順）
- **STEP 9 のファイルフォーマット**に引用の内訳の行を追加

`style/style-reporter.md`（版 1.3 → 1.4）

- 投稿の項目フォーマットの例文から行末の「。」を削除し、一言を付けるときだけ「。」で区切る書き方を明記
- 引用の書式（ラベル・括弧なし）と「並び順」の小節を追加

`docs/reports/daily/2026-09-24.md`

- 上記ルールに沿って書き直し（引用2件を `引用` の下へ移動・ラベル削除・インプ順に並べ替え、オリジナルポスト数を3→1、行末の「。」を削除）。あわせて、よーんの指示で note の執筆進捗と特記事項を追記

## 設計判断

**オリジナルポスト数は日次記録シートの値から引き算で出す。** 投稿一覧から数え直す方法もあるが、既存ルールで「件数は日次記録シートの値を正とする」と決めているため、その値を基準にした（`ポスト数 − 引用数`）。

**型どうしの並び順を固定した。** 型の中だけインプ順にする以上、型そのものの並びを決めておかないと日によって順番が揺れる。発信の主力で note 導線も担う長文ストーリーを先頭に、what_id の対応表に近い順（長文ストーリー → ワンポイント解説 → 質問回答 → 短文 → その他）とし、よーんの了承を得た。

**文体ルールの例文も同時に直した。** SKILL.md だけを直しても、STEP 8 で読み込む style-reporter.md の例文が `。` 付きのままだと、例文につられて元に戻るおそれがあるため。
