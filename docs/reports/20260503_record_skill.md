## 背景・動機

変更・実装後の記録作業（報告書作成→変更ログ追記→git push）の手順が CLAUDE.md に長文で書かれており、Claude が毎回それを読んで実行する構造になっていた。手順をスキルとして独立させることで、CLAUDE.md の可読性を上げ、記録手順の管理を一元化した。

## 実施内容

- `/record` スキル（`.claude/skills/record/SKILL.md`）を新設：changelog.md と git log を照合して未記録の変更候補を特定し、よーんの承認後に報告書作成・changelog 追記・git push を自動実行する6ステップのスキル
- CLAUDE.md の「報告書・変更ログの記録ルール」セクションを25行から5行に削減し、詳細手順を `/record` スキルに委譲

## 変更ファイル

| ファイル | 変更内容 |
|---|---|
| `.claude/skills/record/SKILL.md` | 新規作成（6ステップ：changelog読込→git log取得→未記録候補提案→報告書作成→changelog追記→コミット）|
| `CLAUDE.md` | 「報告書・変更ログの記録ルール」セクションを簡潔化し `/record` への参照に変更 |

## 設計判断

- **STEP 3 でユーザー確認を挟む**：候補の自動記録は過剰記録のリスクがあるため、候補提示→ユーザー承認→記録実行 のフローにした
- **フィルタリングルールをスキルに内包**：`permissions.allow` 追記のみのコミット、日報・週報・月報、コンテンツファイルのみの変更は記録不要として除外ロジックをスキル内に定義した

## 確認結果

スキルが `/record` で呼び出せることを確認。changelog.md と git log の照合・候補提案・報告書作成・changelog 追記の一連の流れが正常に動作することを本セッションで確認した。
