## 背景・動機

オポチュニティ記事の図解・サムネ制作中、「作成する図の文字は必ず 36px 以上にしたい（スマホでも読めるように）」という要望が出た。

しかし **px は単体では可読性の指標にならない**。note の画像はスマホでは画面幅（約390px）まで縮小表示されるため、見かけの大きさは

```
見かけの大きさ = 文字px × (390 ÷ 画像の幅px)
```

で決まる。同じ 36px でも、1280px 幅の画像なら見かけ 11px、1920px 幅なら 7px にしかならない。「36px 以上」というルールは、キャンバス幅を決めないと守れているかどうかを判定できない。

そこで **画像幅に対する比率**で下限を定めることにした。1600px 幅で 36px 相当＝画像幅の 2.19%、これを 1280px 幅に換算すると 28px。この 2.19% を全画像共通の下限とした。

## 実施内容

- `image/brand.md`・`thumbnail_template/brand.md` に「最小文字サイズ（スマホ可読性の下限）」の節を新設
  - 下限＝**画像幅の 2.19%**（1280px 幅なら 28px）
  - 幅ごとの早見表（1280 / 1600 / 1920px）と、見出し級（幅の2.7%）・タイトル級（幅の5%）の目安を併記
  - **例外**: 出典クレジット等の但し書きは下限を適用しない（読めなくても支障がない情報）
  - 図解・サムネのキャンバスは **1280px 幅を基本**とする（幅を固定すれば「28px 以上」の判断がそのまま使える）
- 図解の生成スクリプトに、指定サイズが下限を下回ったら自動で引き上げるクランプを実装

  ```python
  MIN_FONT = round(CW * 0.0219)
  def F(size): return ImageFont.truetype(FONT, max(size, MIN_FONT), index=0)
  ```

- サムネイルの生成プロンプト・デザイン指示書にも下限を明記（生成AIに任せる画像は数値で指定しないと小さくなるため）

## 設計判断

**px の絶対値ではなく比率で規定した。** 絶対値だと、キャンバス幅を変えるたびにルールを読み替える必要があり、実際に「1600px で 36px は 1280px でいくつ？」という換算が毎回発生する。比率にすれば幅が変わっても同じ1つの数字で判定できる。

**クレジットを例外にした。** 出典表記は「読めなくても記事の理解に支障がなく、必要なら拡大すればよい」情報であり、これを下限に合わせると図中で不必要に目立つ。

**スクリプト側でクランプまでかけた。** ルールを文書に書くだけでは、ラベルが増えたときに「収めるために小さくする」判断が入り込む。下限未満を指定しても自動で引き上がるようにして、破れない形にした。

## 確認結果

- オポチュニティ記事の図解①（構造図）・図解⑥（軌跡マップ）を 1280px 幅で生成し、最小ラベルが 28px 以上になることを確認
- サムネイル（1280×672）は、最小要素である右上のメタ情報「Opportunity / 2004-2018」を 28px で指定して生成
