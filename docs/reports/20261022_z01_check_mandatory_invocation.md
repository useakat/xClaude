## 背景・動機

z01（X 短文投稿）のルーティンで、newsTopics[29]「ナンシー・グレース・ローマン宇宙望遠鏡」の投稿を作成した際、逆説フック「広く撮れば画質は落ちる」を採用した。この「常識」は〈画素数が一定のとき〉にのみ成立する前提付きのもので、ローマンは画素を約300倍（約3億画素）積むことで鮮明さを保ったまま視野を100倍に広げている。つまり常識を覆したのではなく、前提条件を伏せたままの"覆し"になっており、ミスリードだった。

この前提の欠陥は、本来 STEP 4.5 の `/check-critic`（知識ある読者役）を実起動していれば「それは同じ画素数のときの話では？ローマンは3億画素では？」と即座に突かれたはずの指摘だった。しかし無人フローで `/check-critic` を含む各チェックを実エージェントとして起動せず、「check-critic 相当の自己検品」で済ませたため、自分が書いたフックの前提という盲点を見抜けず通してしまった。

spec には「STEP 3〜6 を順序どおり1回ずつ実行する」という鉄則はあったが、「自己検品で代替してよいか」が明文化されておらず、エージェントが「相当の自己検品」と解釈してスキップする余地があった。プロンプトの文言だけでは再発を防げないため、「証跡がないと先に進めない」形で省略を検知可能にする。

## 実施内容

- **鉄則ブロック**に、各 `/check-*`（reader / fact / critic / brand / yohn）を Skill または Agent として**実起動する**ことを必須化。自己検品・インラインでの代替、および「◯◯相当の自己検品」等の表現による工程スキップを禁止と明記。各チェックの最大ループ回数（reader 3・fact 5・critic 3・brand 5・yohn 3）も併記。由来にローマン望遠鏡の逸脱を記録。
- **Naming 本文フォーマット**に `[チェック証跡]` ブロックを `[最終原稿]` の直前に新設。5チェックとも「実行 / ループ回数 / 収束可否」を統一形式で記載。空欄＝未実行（違反）、ブロック内にタグ文字列（`[投稿文]` 等）を含めない旨も明記。
- **STEP 6A** の Write 対象一覧に `[チェック証跡]` ブロックを追加。
- **STEP 7 完了報告**テンプレに「チェック実行」行（reader/fact/critic/brand/yohn の回数と○×、未実行・自己検品代替は×と理由）を追加。
- **Verification** に「各 `/check-*` を実起動しており、証跡ブロックと完了報告に実行結果が記載されている」ことを検証項目として追加。

## 設計判断

enforcement の方法として3層（Layer 1: spec 明文化、Layer 2: 証跡の義務化、Layer 3: hook による機械ゲート）を検討し、今回は **Layer 1+2** を採用した。Layer 3（Gmail 下書き作成ツールの PreToolUse hook で証跡の有無を検証しブロック）が最も確実だが、hook とスクリプトの新規作成になるため、まず低リスク・即効の 1+2 を入れ、効果を見てから 3 を検討する。

証跡ブロックは当初「critic だけ改稿しない単発検出なので別項目」とする案だったが、spec の STEP 4.5（2026-10-21 イカロス由来）に「反映→再 critic を最大3ループ」の記述があり critic もフローとしてはループするため、5チェックを「実行 / ループ回数 / 収束可否」で統一した。

## 確認結果

`git diff` で5箇所の編集を確認。Markdown の太字入れ子が壊れる1箇所（`を**実起動した**結果`）を「実起動した」に修正済み。master へ push 済み（`9440fc4`、rebase 後）。

## 今後の課題

- Layer 3（hook による機械ゲート）は未実装。自己検品での省略を物理的に不可能にするには、各 check スキルが起動時にマーカーを書き、下書き作成の PreToolUse hook で5マーカーの有無を検証してブロックする設計が必要。
- 初稿→確定稿の差分から出た他の学び（先人の矮小化回避・時間帯を特定する締めの回避・逆説フックの成立条件検証・驚きの数字への物理の回収）の persona-yohn_z01.md / z01-phrasebook.md への追記は、今回の対象外（別途判断）。
