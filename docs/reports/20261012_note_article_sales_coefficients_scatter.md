## 背景・動機

note 導線ダッシュボード（10/11 新設）の「note 記事別」には購入数と CVR しか無く、「何ビュー集めれば 1 本売れるか」「何スキにつき 1 本売れるか」がすぐに読めなかった。よーんの指示で、記事ごとに ①販売係数 ＝ ビュー数 ÷ 購入数、②スキ購入係数 ＝ スキ数 ÷ 購入数 を表に足し、あわせてスキ数（縦）× 購入数（横）の散布図を置くことになった。

散布図は「有料部分のない記事は省く」との指示で、記事が有料かどうかの情報が要る。note投稿一覧 には価格が無いため note 公開 API（`/api/v3/notes/{key}` の `price`）から取る。ただし routine（cloud）環境は note.com に届かない（プロキシが 403）ことが実行して分かり、取得をローカル cron に移した。

また、表の購入数で「もしも空が赤かったら（後編）」が 0 件になっていた。note購入記録 には 4 件あるのに、記録の題名が副題「〜限りあるハビタブルゾーン」を省いた 14 文字で、「完全一致か先頭 15 文字一致」の突合規則から外れていた。

## 実施内容

- `scripts/note_funnel_export.py`
  - `articles.csv` に 販売係数（`round(views / buys)`）・スキ購入係数（`round(likes / buys, 1)`）・価格 の列を追加。購入 0 件の記事は空欄
  - 価格は note投稿一覧 の N 列「価格」をまず読み、無い記事だけ公開 API へ（7 日キャッシュ）。routine 環境では API に届かず空のまま
  - 購入記録の題名突合を「完全一致 → 記事題名が記録の題名で始まる（8 文字以上）→ 先頭 15 文字一致」の 3 段にし、副題を省いた記録も拾う
- `scripts/note_article_daily.py`（ローカル cron 05:55）
  - `update_prices()` を追加。note投稿一覧 の全記事の価格を公開 API で取り、N 列（ヘッダー「価格」）に差分だけ書く。`--prices-only` で単独実行可。初回 29 件を書き込み
- ダッシュボードページ（`files/index.html`、ArtifactData で差し替え）
  - 「note 記事別」の表に 販売係数・スキ購入係数 列を CVR の後ろに追加
  - 散布図を 2 枚（`scatterArticles(box, data, opts)` を共通化）：「スキ数 × 購入数」と「100PV あたりのスキ × 購入」（＝ スキ率 × 100、CVR × 100）。有料記事（価格 > 0。価格が取れない行は売上か購入があれば有料扱い）だけ。購入のある記事にラベル、点に触れると PV・スキ・購入・価格と 100PV あたりの値
  - 「数字の定義」に販売係数・スキ購入係数の説明を追記
- `datasets/articles` の description を更新

## 設計判断

- **価格の取得をローカル cron に置く**：routine の環境からは note.com に届かない（Tunnel 403）。VPS からは届くので、毎朝の記事別スナップショット（`note_article_daily.py`）に同乗させ、書き出し側はシートを読むだけにした。API 直叩きのコードは「シートに無い記事だけ」の保険として残した
- **有料判定は価格 > 0**：売上や購入の有無で判定すると「有料だが 0 件」の記事が落ちる。価格が取れていない行だけ売上・購入で補う
- **購入記録の突合に前方一致を足す**：記録の題名は手入力で副題が省かれることがある。短い題名の誤一致を避けるため 8 文字以上に限定

## 確認結果

- 購入記録 31 件すべてが記事に結び付いた（冥王星 10、時代遅れ 6、天王星 7、空が赤かったら（後編）4、ハッブル 1、チャンドラ 3）
- 有料記事は 10 件（上記 6 件と、購入 0 件の 90日の命・iPad mini・SCE・ケプラー）
- 100PV あたりの値：チャンドラ 購入 2.56 / スキ 2.6、空が赤（後編）1.78 / 3.1、天王星 1.77 / 5.1、ハッブル 0.79 / 4.0、時代遅れ 0.56 / 1.9、ニューホライズンズ 0.45 / 0.7。PV が多い 2 記事ほど両方の率が低い
- routine を手動実行し、articles のデータセット差し替えが成功（v11）
