## 背景・動機

日報の旧形式は「① オリジナルポスト数 / ② 引用 / ③ リプライ数 / ④ 特記事項」の番号付き構成で、数値（X のみ）と投稿の内訳が離れた場所にあった。そのため：

- **どの媒体の数値なのかが読み取りにくい。** ①〜③ は X の実績だが、④ 特記事項の中に X 投稿・threads 投稿・note が混在しており、媒体の切り分けが見出しの有無に依存していた
- **threads の投稿件数がどこにも出ない。** 日次記録シートは X 専用のため、threads は内訳が並ぶだけで「何本投稿したか」が一目で分からなかった
- **note の状況が「・note 執筆」の1行だけ**で、記事ごとの進捗が書けなかった

よーんから「媒体ごとにまとめ、各媒体の件数の下に内訳をぶら下げる形にしたい」と新形式の指定があったため、それに合わせて skill とスタイルガイドを改訂した。

## 実施内容

- **日報を媒体別の4セクション構成に変更**：`**note**` / `**X**` / `**threads**` / `**特記事項**`
  - note：`・記事執筆中` を無条件で出力（進捗の詳細はよーんが括弧書きで追記する運用。skill 側では推測しない）。note 記事公開があればこのセクションに置く
  - X：`引用` → `リプライ数` → `オリジナルポスト数` の順に並べ、投稿の内訳をその下に入れ子で列挙
  - threads：`オリジナルポスト数` と内訳のみ（引用・リプライ数の行は出さない）
  - 特記事項：投稿以外の活動と運用変化だけを書く。投稿の数値はここに入れない
- **threads の投稿件数の算出元を定義**：日次記録シートは X 専用のため、Threads投稿一覧シートの当日行数を数えて `threads_posts` とする
- **件数の食い違いルールを明文化**：日次記録シートの `ポスト数` と X投稿一覧シートの当日件数が食い違う場合、件数表示は日次記録を正とし、内訳は投稿一覧の全件を出す
- **0件の日の扱いを明文化**：note・X・threads の見出しは0件でも省略せず数値 `0` を書く。特記事項のみ、書く内容が無ければ見出しごと省略する
- **Wiki 描画の制約を「必ず守るルール」として skill とスタイルガイドの両方に明記**（下記「設計判断」参照）
- スタイルガイドに threads 用の数値表記順（`viewsXXX・いいねXXX・リポストXXX・引用XXX・リプXXX`）を追加。従来は skill 側にしか書かれていなかった
- 週報スキルの日報読み取り箇所の文言を「特記事項から」→「各セクションから」に修正し、新旧形式が混在しうる旨を注記

## 設計判断

- **入れ子のインデントは全角スペース2個（U+3000）を使う。** 半角スペース4個は Markdown がインデントコードブロックと解釈して描画が崩れる。週報が既に全角スペースで入れ子にしていた前例に合わせた
- **箇条書きの間に空行を1行入れるルールは新形式でも維持。** Starlight の markdown 設定に改行変換（remark-breaks 相当）が入っていないため、空行が無いと単一改行が無視され全項目が1行に連結される。既存の週報ファイルは実際にこの状態になっている
- **note の進捗は skill 側で推測しない。** 記事の進捗（本文作成中／図解画像作成中など）を機械的に判定する材料が無いため。`projects/w002/` には直近1週間のコミットが無く、リモート実行環境では clone 直後でファイル更新時刻も当てにならない。よーんが後から括弧書きで追記する運用とした
- **過去の日報は旧形式のまま残す。** 週報・月報は日報ファイルを全文読み込んで AI が要約する方式のため、形式が混在しても支障がない。移行コストを払う理由がない
