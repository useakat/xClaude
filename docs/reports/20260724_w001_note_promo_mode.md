## 背景・動機

公開済みの note 記事（w002）への流入を増やすため、「本編（X長文ストーリー）＋セルフリプ（note リンク）」の販促投稿を作れるようにしたい。運用は **1記事につき2〜3ヶ月に1回程度の定期販促**（同じ記事を繰り返し販促する）。

調査の結果、新スキルは不要で、W001 の既存モードB（note記事あり）が制作フローの大半をカバー済みだった。ギャップは3点：

1. **セルフリプが手動運用**（spec.md「セルフリプは cron の対象外」）。一方 `post_from_email.sh` には `[リプ]` タグ→本体投稿直後にリプ自動投稿する機能が既にあり、公開済み note なら URL 確定済みなので全自動化できる。
2. **note 公開 URL の取得元が未定義**。ローカルに公開URLの記録は無く、唯一の取得元は「note投稿一覧」シート B列。
3. **導線分析に自動で載らない**。Xnote導線記録の紐付けキーは outputs シート F列（note_url）だが、`post_from_email.sh` は `[note_url]` タグを抽出しておらず、`record_output.py` にも `--note-url` が無かった。

また定期販促では「毎回同じ文面になる」リスクがある。ブリーフ（funnel-brief.md）の設計図どおりに毎回作ると同じ文面が量産されるため、**継承するのは「note の売り（あえて出さない核）」だけ、フォーカス・フック・セルフリプは毎回新規に作る**方針とした。writer-xstory の「場面3候補→選択」構造がバリエーションを担い、outputs の note_url 紐付けで過去の販促投稿を引いて重複を除外する。

## 実施内容

- **spec.md モードB を「note販促モード（定期・繰り返し対応）」に再定義**：
  - note 公開 URL の取得を必須手順化（note投稿一覧シート B列からタイトルマッチ、無ければユーザーに確認）
  - 売りの温存：ブリーフありは `## note の売り（有料の引き）` **だけ**を参照（X長文の範囲・セルフリプ文面は流用しない）。無しは記事正本から課金壁以降の核心を特定し本編に書き切らない
  - 重複回避：制作前に outputs で同 note_url の過去 W001 投稿→X投稿一覧から過去本文を取得し、フォーカス3候補は過去と異なる場面・切り口から出す
  - セルフリプは毎回新規作成（今回の本編フォーカスに合わせる・実URL入り）
  - モードC（ブリーフ確定文面使用）は **note 公開直後の初回投稿専用**と明記。2回目以降は必ずモードB
- **セルフリプの cron 自動投稿化**：メールテンプレに `[リプ]` タグを追加し、「セルフリプは cron 対象外・手動」→「URL確定済み（モードB/C）は cron が本体投稿直後に自動投稿。モードAのみ手動」に改訂
- **note_url の自動記録**：`record_output.py` に `--note-url` を追加（outputs F列に書き込み）。`post_from_email.sh` が `[note_url]` タグを抽出して連携。これで投稿と同時に Xnote導線記録の集計対象になり、次回販促の重複回避の材料にもなる

## 設計判断

- **新スキルを作らず既存モードB を強化**：制作フロー（writer-xstory・check-fact-lim・check-brand・サムネ・Gmail下書き）は全て既存資産で足り、ギャップは導線まわりの3点だけだったため。
- **ブリーフから「売り」だけ継承**：ブリーフの「X長文の範囲」「セルフリプ確定文面」を毎回使うと同じ投稿が量産される。不変の制約（ネタバレ防止）と可変の設計（切り口）を分離した。
- **重複回避を outputs の note_url 紐付けで機械化**：過去の販促本文を人が覚えておく必要をなくし、シートから自動で引けるようにした。

## 確認結果
