## 背景・動機

マーズ・パスファインダー投稿（2026-10-01 制作）で、`/check-fact-lim`・`/check-reader`・`/check-critic`・`/check-yohn` をすべて通したにもかかわらず、よーんへの提示後に**文章の意味が取れない・事実の裏が取れていない指摘が大量に出た**。原因を1件ずつ潰した結果、個別の原稿の問題ではなく**手順と規範の穴**だと分かったため、恒久ルールとして反映した。

露呈した穴は5つ。

1. **接続関係の省略**: 逆接・因果でつながる2文を句点で切り、関係語を省いていた。文法は正しいので reader も yohn も素通りする。例:「同じ再起動は打ち上げ前にも1、2回出ていた。そのときは再現できず〜」
2. **転換語の誤用**: brand.md の「よく使う表現・口癖」表に転換語が並んでいたため、用法を検討せずリストから選んでいた。例:「原因が分からない。…ところが、JPLには切り札があった」（切り札は JPL 自身の持ち物で、予期しない事態ではない）
3. **裏の取れない一般論で落差を作る**: 「ふつうは本番前にデバッグ機能を外す」という一般論を物語の落差の土台にしたが、notebook のソースに該当記述がなかった。`check-fact-lim` は本文が明示した主張しか照合しないため、最終段階まで残った
4. **字数を文の圧縮で作る**: 700字の上限を意識しながら書いたため、削る対象が文の中身（目的語・接続語・主語）になった。情報量は変わらないまま語だけ減り、その復元コストが読者に回った。よーんの指摘「意味の分かりにくい文章が多すぎる。省略した書き方や変な表現が多いせい」はこれが原因
5. **チェック工程の運用不全**: fact-lim・critic・yohn を**同時に**走らせ、しかも各1回で次へ進んだ。3つとも「もう存在しない版」への指摘になり、反映後の版は誰も読んでいない状態で残った。さらに、対話の中で書き足した段落はどのチェックも通っていなかった

加えて、「最後に残ったのは1人のエンジニア」「数行の修正」が**二次資料（Mike Jones 版の解説記事）にしかない脚色**だったことが、よーんによる一次資料（Reeves 原文・Wikipedia）の確認で判明した。notebook のソースに一次・二次が混在しており、`check-fact-lim` がそれを区別せず ○ を出していた。

## 実施内容

- **接続のルールを共通 brand.md に新設** — 逆接・因果でつながる2文は接続助詞で1文に畳む。句点で切ってよいのは①転換の合図の超短文②並列・時系列で関係が自明な文の2つだけ。主語が切り替わる文も橋を架ける
- **転換語を「よく使う表現・口癖」表から削除** — 語ごとの用法条件を「言葉遣いの共通ルール」に移した。とくに「ところが」「なのに」は**主体にとって予期しない事態が起きたとき**だけ。リストから選ぶ動きを構造的に断つのが狙い
- **共通 brand.md の NG に2項目を追加** — 裏の取れない一般論で落差を作らない／劇的なディテール（人数・時間帯・具体的な数量）を二次資料だけで書かない
- **W001 spec にフロー5.7（字数の調整は「削除」で行う）を新設** — 執筆中は字数を見ず全要素を書き切り、実測してから**段落または文を丸ごと落として**調整する。落とした後、残った文には手を入れない。削除の優先順位も明記
- **W001 spec のフロー6（check-fact-lim）に2点追記** — 抽出対象に「本文が前提として置いている一般論・比較の基準」を含める／一次資料と二次資料を区別し、劇的ディテールは一次資料で裏が取れるものだけ使う
- **W001 spec にフロー6.9（チェック工程の進め方）を新設** — 1ステップずつ順に回す・同時実行禁止／各ステップ内で収束ループを完走してから次へ／対話で本文を書き換えたら `/check-reader` と `/check-yohn` を再実行／論理構成を組み替えたら `/check-critic` も回し直す
- **W001 brand.md の採点基準 項目6 を書き換え** — 字数調整を「ピンポイントで調整」から「段落・文の削除で調整し、残った文に手を入れない」に変更
- **check-yohn の W001 ペルソナに W14〜W18 を追記** — 接続の省略／転換語の用法条件／裏の取れない一般論／劇的ディテールの出典／比喩を実体に置き換えたか

## 設計判断

- **転換語は「リストから消す」を選んだ。** 用法注記を添えるだけでは、リストに並んでいる限り「この中から選べばよい」という動きが残る。転換語は他の口癖（「ちなみに」「まじで」）と違い、**文と文の論理関係そのものを宣言する語**なので、誤用がそのまま論理の破綻になる。よって表から外し、都度判断させる形にした。
- **字数調整の単位を「段落または文」に固定した。** 当初「要素」としていたが曖昧で、文の一部を「要素」と称して削る逃げ道が残る。単位を段落・文に固定し、さらに「**削ったあと残った文に手を入れない**」を条件に加えることで、圧縮への逆戻りを塞いだ。この条件がないと、削除と称して情報を残りの文に詰め込める。
- **チェックの同時実行を禁止した。** 時間短縮のために3本同時に走らせたが、事実が変われば論理が変わり、論理を組み替えれば表現が変わるため、順序（fact-lim → reader → fold → critic → yohn）に意味がある。所要時間は延びるが、無検査の版が残るほうが損害が大きい。

- 一次資料ベースの指摘6件（観測は止まった→その日の作業／そっくり同じ探査機→同じソフトウェアが動く試験機／18時間→18時間も経たない／「1人のエンジニア」「数行」の削除／順番の決め方を変える→優先度継承の有効化）をすべて反映
