## 背景・動機

2026-11-19 に z01・販促（W007）を「予約ファイル → postcal インポーター」方式にした結果、**git に push された本文は、よーんの確認を経ずに自動で予約（`queued`）に登録され、枠の cron がそのまま X / Threads に投稿する**経路ができていた（インポーターは新規 uid を直近の空き枠へ `queued` で登録していた）。z01 は無人のルーチンで原稿を作るため、よーんが本文を見る前に投稿される。

よーんの要望（2026-11-21）：登録はするが、投稿予約まではされていない状態を作り、`post.usephys.net` で確認・修正してから「投稿予約」ボタンを押すと予約状態になる、という確認ゲートを置く。

## 実施内容

- **下書き状態（`draft`）を追加**：`postcal_import.py` は予約ファイルを必ず `draft` で登録する。`post_scheduled.py`（枠の cron）は `status='queued'` の行しか拾わないため、下書きは投稿されない（ランナー側は無改修）。
- **仮の日時**：下書きにも従来どおり「今日以降の最も近い空き枠」を仮の日時として付ける（カレンダーで見渡せるように）。下書きは枠を占有しない（`slot_taken` は既定で draft を除外）。ただしインポーターが仮枠を選ぶときだけ draft も埋まっているとみなし、複数の下書きが同じ枠に重ならないようにする（`include_drafts=True`）。
- **「投稿予約」ボタン**：画面の更新フォームから `action=approve` で `draft → queued`。枠が過去・すでに埋まっている場合はエラーにし、日時を直して再度押してもらう。「下書きを保存」（状態を変えずに保存）と、予約済みを戻す「下書きに戻す」（`unapprove`）も追加。
- **画面編集の保護**：下書きの本文をファイルの変更で更新するのは、画面で未編集のときだけ。取込時の内容ハッシュ（state）と DB 行の現在のハッシュを比べて、食い違えば「画面で編集済み」とみなして上書きしない（画面の編集が正）。予約済み（queued）・投稿済み・失敗は、ファイルを変えても本文を動かさない。
- **カレンダー表示**：凡例に「下書き（未予約）」、点線枠のチップを追加。一覧の状態ラベルに「下書き」を追加。
- **仕様書の更新**：z01 の `spec.md`（Output・STEP 6・STEP 7・その他・Verification の更新ルール）、`docs/workflows/x-auto-post.md`、`writer-xpromo`（SKILL.md）を下書き方式に書き換え。

## 設計判断

- **下書きに仮の枠を持たせる（取込時に枠を割り当てない案は採らなかった）**：DB の `post_date` / `slot` は NOT NULL で、カレンダーも日付ごとに並べるため、仮の日時があるほうが見渡しやすく、既存の表示・編集をそのまま使える。枠の取り合いは「draft は枠を占有しない」「投稿予約時に空き・過去を検証する」で解決した。
- **枠の自動繰り下げはしない**：投稿予約時に枠が使えなければ、パターンを app 側に複製して自動で動かすのではなく、エラーにして日時を選んでもらう。短文・販促の枠パターンを `postcal_import.py` と `app.py` の二重管理にしないため。
- **画面の編集を正にする**：ファイルでの再 push が画面の修正を消すと、確認の意味がなくなる。ファイルと DB の内容ハッシュで「画面編集済み」を検知し、上書きしない。
- **販促（W007）も下書きにした**：インポーターは共通で、「確認前の本文を自動投稿しない」という原則は販促にも当てはまるため。販促だけ自動予約を残す例外は、よーんに確認していないので入れていない。

## 確認結果

- 一時 DB と一時ディレクトリで 23 項目のテストを実行し、全件合格（cron の枠取得が draft を拾わない／仮枠が重ならない／ファイル変更の反映は未編集の draft のみ／画面編集済みは上書きされない／過去枠・枠衝突の投稿予約は 400／日時を直せば投稿予約できる／下書きに戻す／queued はファイルで動かない／画面から手で登録したものは従来どおり即 queued）。`py_compile` OK。
- **未確認**：VPS への配備後の実画面・実インポーターでの動作（配備は VPS で `git pull` → `sudo systemctl restart postcal`。取込タイマーは次回実行から新コード）。
