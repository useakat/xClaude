## 背景・動機

W002（note 記事）の画像工程は、spec 上で生成手段が2つに分かれていた。

- **図解** … NotebookLM で各3枚生成
- **イメージ・サムネイル** … Claude はプロンプトファイルを提示するところまでで、**ユーザーが外部の画像生成AI（nano banana 等）で生成する**

この分担は「リポジトリに画像生成ツールが無い」という前提に基づいていた。しかし 2026-08-04 の W001 側の移行（[lovart スキルによる画像生成を W001 制作フローに導入](./20260804_lovart_image_generation_w001.md)）で、ユーザーレベルに lovart スキルが導入済みで **Claude が直接画像を生成できる**ことが確認されている。W002 側だけが旧前提のまま残っていた。

加えて、NotebookLM 生成の図解は参照画像を渡せないため、ケプラー望遠鏡のような**実機の形状を忠実に描かせる**用途に向かない。実際、ケプラー記事では機体形状の再現のために 3D モデル（`.glb`）からレンダリングした多視点シートを参照画像として使う必要があり、旧フローでは対応できなかった。

そこで W002 の画像生成を、図解・イメージ・サムネイルとも `/lovart` に一本化した。

## 実施内容

- `projects/w002/spec.md` の画像生成に関する記述3箇所を Lovart 前提に書き換えた
  - 画像種類の注記 … 「図解は NotebookLM／イメージは外部AIでユーザーが生成」→「図解・イメージとも `/lovart` で生成」
  - フロー12-(c)（セクション画像の実画像化） … 承認済みプロンプトで `/lovart` を使って図解・イメージを生成する手順に変更
  - フロー13-4（サムネイル生成） … 「画像生成（手動・外部）」→ Claude が `/lovart` で生成し、複数枚提示して採用案を決めてもらう手順に変更
- 参照画像の渡し方を明記した … 実機・実物の形状を再現したい場合は `upload` で Lovart CDN に上げ、`--attachments` で渡す
- 修正の反復方法を明記した … 同一スレッドで `--thread-id` を指定して修正依頼、または複数枚生成を繰り返し、採用案が決まるまで対話で詰める
- ケプラー記事（`projects/w002/2026-07-04_kepler-k2-revival/`）で初運用し、図解8点・イメージ1点・サムネイル1点を生成した

## 設計判断

**図解も NotebookLM から Lovart に寄せた。** NotebookLM の図解生成はソースに基づく正確さが利点だが、参照画像を渡せないため実機形状の再現ができない。W002 は宇宙機を主題にすることが多く、形状の忠実さが読者の理解に直結する。正確さはプロンプト側（design-brief で内容を確定してからユーザー承認を取る2段階）で担保できるため、生成手段は Lovart に統一するほうが利点が大きいと判断した。

**写真案は引き続きスキップ。** 実機写真は NASA 等の公式素材を Web 取得するほうが確実で、生成する意味がないため。

## 確認結果

ケプラー記事の制作で全工程を通した。

- セクション画像 … 図1〜図10 のうち図解8点・イメージ1点を Lovart で生成（各3案生成 → 採用案を `_final` として確定）。図5 のみ NASA 公式素材を Web 取得
- 参照画像の受け渡し … ケプラー機体の 3D モデルからレンダリングした多視点シート（`reference/kepler_10views_sheet.png`）を `upload` → `--attachments` で渡し、機体形状を再現できることを確認
- サムネイル … `/lovart` で複数案生成し、採用版を `output/images/thumbnail.png`（1280×672px）として保存。plan の失格条件（タイトル可読・日本語崩れなし・CTAなし）を満たすことを確認
- 記事は 2026-08-09 に公開済み（<https://note.com/takaesu7431/n/ndaeed905f827>）
