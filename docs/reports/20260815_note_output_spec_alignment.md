## 背景・動機

[8/13 に下書きがエディタで開けない問題を解決](./20260813_note_draft_figcaption_fix/)し、オポチュニティ記事の下書きを実際に note で開けるようになった。そこで初めて、**生成した本文が note 上でどう見えるか**を目視できるようになり、note 側の表示仕様と噛み合っていない箇所が4点見つかった。

いずれもローカルの HTML 変換テストでは発見できない種類の不一致で、**note のエディタで開いて初めて分かる**ものだった。8/13 の報告書で「note の非公開 API を使う実装は、ローカル検証だけを確認結果にしない」と書いた、その具体例にあたる。

| ユーザーからの指摘 | 実際の原因 |
|---|---|
| 目次が本文のいちばん上にある | 変換時、`table-of-contents` を無条件に先頭へ置いていた |
| タイトルが本文冒頭に残っている | `# タイトル` の H1 が `<p>` として出力されていた（タイトルは note 側で別に設定するため重複） |
| `---` が本文に出ている | 水平線を `<p>---</p>` として出力していた |
| **画像に黒文字（キャプションとは別の説明）が入っている** | **`alt` 属性に説明文を入れており、note のエディタがそれを画面に表示していた** |

最後の1点が分かりにくかった。画像ファイル自体には文字が焼き込まれておらず、本文にもその文字列は無い。調べると、こちらは画像ごとに `alt="オポチュニティの構造図。太陽電池パネル・6輪・…"` という説明文を入れていた一方、**note 自身が書き出す画像は `alt=""`（空）**だった（ケプラー記事の公開済み HTML で確認）。note のエディタは alt を可視要素として扱うため、アクセシビリティのつもりで入れた説明文が画面に露出していた。

あわせて、画像の説明・クレジットを本文の段落として画像の下に置いていたことも「本文と同じ黒字で見にくい」という指摘につながった。note には画像のキャプション欄（`figcaption`）があり、そこに入れれば小さいグレー文字で表示される。

## 実施内容

`md_to_note_html()` に4点の修正を入れた。

1. **目次の位置** — 変換中に最初の `## ` が現れた位置を覚えておき、最後にそこへ `table-of-contents` を差し込む。H2 が無い記事では従来どおり先頭に置く
2. **H1 を出力しない** — `# ` で始まる行はスキップ（記事タイトルは `name` として別に送っている）
3. **水平線を出力しない** — `---` / `***` / `___` の行はスキップ
4. **`alt` を空にする** — `alt=""` で出力し、note 自身の出力に合わせる
5. **キャプション記法を新設** — 画像の**直後の行**が `> ` で始まる場合、その内容を直前の `figure` の `figcaption` に流し込む

```markdown
![](images/dust_devil.jpg)
> 火星のダスト・デビル（高さ約20km）／NASA/JPL-Caltech/Univ. of Arizona
```

画像の直後**以外**の `> ` 行は、これまでどおり通常の段落として扱う（既存記事への影響なし）。

| ファイル | 変更内容 |

| `scripts/send_note_draft.py` | 目次を最初の H2 の手前へ挿入。H1 と水平線をスキップ。`img` の `alt` を空に。画像直後の `> …` 行を `figcaption` に流し込む記法を追加（`caption_pattern` / `last_figure_index`） |

## 設計判断

**キャプションの記法に `> ` を選んだ。** Markdown の引用記法を流用することで、`output/index.md` を素の Markdown として読んだときも「画像に添えられた文」として自然に読める。専用の記法（`caption:` 等）を作るより、原稿を書く側の負担が少ない。

**`alt` は空にし、説明文は figcaption に寄せた。** アクセシビリティを考えれば alt に説明を入れたいところだが、note のエディタがそれを表示してしまう以上、実害のほうが大きい。figcaption は視覚的にも読み上げにも機能するため、説明はそちらへ集約するのが妥当と判断した。

**今回のオポチュニティ記事の下書きには適用していない。** ユーザーの指示により、この修正は次回の記事から有効にする。既存の下書きを作り直すと、有料エリア設定などの手作業をやり直すことになるため。

## 確認結果

- 変換のユニット確認で、次を確認した
  - 画像の直後の `> …` が `figcaption` に入る
  - `alt` が空で出力される
  - キャプション行が本文段落として二重に出力されない
  - 画像の直後**以外**の `> ` 行は通常の段落のまま
- 目次が導入の末尾（最初の H2 の手前）に入り、H1 と `---` が出力されないことは、オポチュニティ記事の実データで確認済み（8/14 に下書きを更新して反映）

## 今後の課題

- **画像に説明文を添える運用を spec に書いていない。** `visual_section-imager` や w002 spec の画像埋め込み手順に、`> ` でキャプションを書く記法を追記しないと、次の記事でも本文段落として書かれてしまう
- note のエディタが alt を表示する挙動は、note 側の仕様変更で変わりうる。alt を空にする方針は、あくまで現時点の note に合わせたもの
