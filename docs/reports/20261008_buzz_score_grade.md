## 背景・動機

投稿の結果（IMP・いいね・エンゲ率）は X投稿一覧シートに毎日記録されているが、「この投稿は当たりだったのか」を一目で判定する指標が無く、次の投稿作成に結果を戻す導線も無かった。よーんが見つけた「フィードバックタブに結果を書くと自動でバズスコア・グレードが出る」仕組みを参考に、同じループ（投稿 → 結果 → スコア → 次の投稿の参考例）を自分のワークフローに入れることにした。

スコアは**相対スコア**のみとした。フォロワー数の増加やアルゴリズム変動で IMP の水準自体が動くため、絶対値で「1万IMP以上 = S」と決めると時期によって意味が変わる。「その投稿が出た時点での、同プロジェクトのいつもの実力」と比べることで、時期をまたいでも「いつもの何倍伸びたか」で比較できる。よーんの判断で絶対スコアは追加しなかった（「使い所がよく分からない」）。

## 実施内容

- `scripts/buzz_score.py` を新規作成
  - 対象: outputs シートで what_id（W001 / W003 / W006 / z01 など）が付いた X 投稿。outputs の URL から tweet_id を取り、X投稿一覧の行と結合する
  - 基準値: **投稿ごとに**、同プロジェクトでその投稿より前 56 日（8週）以内の投稿の中央値（IMP・エンゲ率それぞれ）。5本未満ならそれ以前の全投稿を含め、それでも5本未満なら採点しない
  - スコア = 0.7 × log2(IMP ÷ 基準IMP) + 0.3 × log2(エンゲ率 ÷ 基準エンゲ率)。+1 = いつもの2倍、+2 = 4倍、−1 = 半分
  - グレード: S ≥ 2 / A ≥ 1 / B ≥ −1 / C < −1
  - 投稿から 2 日未満は IMP がまだ伸びるため未採点（空欄）
  - 出力: X投稿一覧の **AJ 列（バズスコア）・AK 列（グレード）** を全行ブロックで上書き（ヘッダーが無ければ書く）、`logs/buzz_scores.csv` を毎回全件再生成（git で履歴を追える）
  - `--dry-run` でプロジェクト別の S/A/B/C 集計だけ表示
  - Sheets の読み書きは `scripts/sheets_values.py`（サービスアカウント認証）経由で、routine から無人実行できる
- `.claude/skills/reporter-daily/SKILL.md` に **STEP 10.6** を追加。毎日 21:00 JST の日報 routine で `buzz_score.py` を実行し、`logs/buzz_scores.csv` を日報コミットの対象パスに追加。スクリプトがエラーでも日報は止めない
- X投稿一覧シートの列数を 35 → 37 に拡張（AJ:AK が存在しなかったため）

## 設計判断

- **中央値ベースライン**: 平均だと円周率バズ（1,098万IMP）のような外れ値で基準が跳ね、その後8週間の投稿が全部 C になる。中央値なら1本のバズで基準が動かない
- **log2**: IMP は桁で変わるので線形比だと S/A の閾値が決めにくい。log2 にすると「いつもの何倍か」がそのまま整数になり、閾値の意味が直感的
- **IMP 0.7・エンゲ率 0.3**: 伸びた投稿を主に拾いたいが、IMP だけだとアルゴリズム配信に乗っただけの投稿も S になる。エンゲ率を3割混ぜて「読者が反応した」投稿を優先する
- **プロジェクト別の基準**: z01（長文ストーリー）と W003（ワンポイント）では IMP の水準が違うため、全体で比べると型の差がグレードの差になってしまう
- **AJ:AK を全行ブロック上書き**: 行単位の更新だと API 呼び出しが行数分になる。対象外の行は空欄で埋めるため、outputs から外れた投稿のスコアも自然に消える
- **CSV を毎回再生成**: スコアは過去の投稿が増えても変わらない（基準は「その投稿より前」のみ）が、X投稿一覧の IMP 更新で変わりうる。差分管理より全件再生成の方が単純で、git diff で変化が追える

## 確認結果

- `--dry-run` で 131 本を採点（対象外: 投稿2日未満・基準5本未満）
- 実行後、X投稿一覧の AJ2:AK1328 と `logs/buzz_scores.csv` に書き込まれたことを確認
- プロジェクト別の S/A/B/C 分布（2026-10-08 時点）

| プロジェクト | n | S | A | B | C |
|---|---|---|---|---|---|
| z01 | 47 | 3 | 4 | 36 | 4 |
| W003 | 48 | 4 | 3 | 29 | 12 |
| W001 | 28 | 3 | 3 | 12 | 10 |
| W006 | 8 | 0 | 3 | 5 | 0 |

- S が各プロジェクト 3〜4 本（6〜11%）、B が過半で、閾値 S ≥ 2（いつもの4倍）が「当たり」を絞る水準として妥当と判断
- 初回の実行で `Range ('X投稿一覧'!AJ1:AK1) exceeds grid limits. Max columns: 35` が出たため、シートの列数を 37 に拡張して再実行した
