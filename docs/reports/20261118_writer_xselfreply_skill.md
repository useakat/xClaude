## 背景・動機

note 導線レジスタの未着手最上位だった N4 は「7/3 ボイジャー投稿のセルフリプ（1,215 クリック）を固定テンプレにする」という施策だったが、よーんから「投稿文と誘導先（プロフ画面・note 記事）を与えるとセルフリプ文を作成するスキルにして、反応を見ながら改善していく方がよいのでは」という提案があった。

W46 までのデータで、セルフリプ CTR は文面の型そのものより**本編との題材一致度**に強く依存している（同一題材の深掘り 2.0〜3.3% vs 別題材販促 0.3〜0.5%。2026-10-11 実績）。毎回本編のフォーカスに合わせた1文を生成するスキルは、この勝ち筋を確実に踏む仕組みとして理にかなう。ただし「反応を見ながら改善」で生成ルールを途中で変えると N4 の before/after 比較が濁るため、**生成ルールの版管理**を条件に採用した（テンプレ化 vs スキル化は対立せず、スキル＝型の実行装置＋バージョン管理）。

## 実施内容

- `.claude/skills/writer-xselfreply/SKILL.md` を新設
  - 入力: 本編（テキスト/ファイルパス）＋誘導先（note 記事 URL・タイトル・売り／プロフ）。欠けていたら無人実行では創作せずエラー報告
  - 生成ルール **v1（ボイジャー型・2026-11-18 固定）**: 同一題材の深掘りを1文で予告→直後にリンク／予告は 20〜60字／本編に書かなかった**具体要素を1つ**入れる（抽象予告は不可）／別題材・直接 CTA 禁止／プロフ誘導はリンク無しの案内文
  - 3案生成→推奨1案を採用（無人実行は自動採用）、W001 フロー14 に貼れる `[リプ]` ブロック形式でも出力
  - 採用案と版を `logs/selfreply_records.csv`（新設。`日付,プロジェクト,版,誘導先,本編冒頭15字,リプ文面`）に記録。本編冒頭15字が X投稿一覧との突合キー
  - ルール改善時は v2 を SKILL.md に追記して別窓で判定（検証中の版は変えない）。版の履歴表を設置
- `projects/w001/spec.md` フロー11: モードB のセルフリプ作成を `/writer-xselfreply` 利用に変更（モードA の後日回収も同様）。モードC はブリーフ確定文面のままで版の対象外
- `docs/plans/note_funnel_measures.md` N4: 状態を**実施中（v1）**・実施日 2026-11-18 に更新（順位表・施策節とも）。施策欄にスキル化と版単位判定の運用を追記。判定条件（after n≥6・CTR 中央値が before 2.37% 超え・6本中4本以上）は事前固定のまま変更なし
- `.claude/skills/metadata.yaml` に追記し、`update_wiki_skills.py` で Wiki スキルページを生成

## 設計判断

- **版管理を必須にした**: N4 の判定条件は事前固定済み。v1 を「ボイジャー型」の実装として固定し、N4 の検証＝v1 の検証とする。改善は v2 として別窓で n を貯める。これが無いと「反応を見ながら改善」が検証を壊す
- **プロフ誘導は参考値扱い**: プロフアクセス（Q列）は本体投稿由来と混ざり、セルフリプ単独の効果を分離できない。判定は note 誘導（リンククリックで CTR が測れる）で行う
- **改善ループの速度**: W001 は週2本・判定に n≥6 のため、1バージョンの検証に約3週。改善の回転は実質月1回

## 確認結果

- スキルが `/writer-xselfreply` で呼び出せることを確認（スキル一覧に登録済み。Wiki ページも生成）
- `note_funnel_measures.py` は指標キー `w001_selfreply_ctr` を実装済みで、N4 を実施中にしたため次回の週次振り返り（11/22）から ⑧ に数値が出る
- `logs/selfreply_records.csv` のヘッダ作成を確認

## 今後の課題
