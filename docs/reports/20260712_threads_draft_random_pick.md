## 背景・動機

過去の X 投稿を Threads にも転載したいが、毎回 X投稿一覧シートから投稿を選んで【threads投稿】メールに整形するのは手間。これを自動化し、毎朝 Gmail 下書きを用意 → よーんが確認・送信 → 既存の Threads 投稿 cron（7/12/17/20時）が投稿、という流れに接続した。

「一度 Threads に投稿した X投稿は選ばない」重複管理は、outputs シートが Threads permalink しか持たず元X投稿に紐づけられないため、**X投稿一覧に「threads転載日」列（AH）を新設**して下書き作成時にマークする方式にした（下書き段階でマークするので未送信でも重複しない）。

処理は LLM 不要の機械的コピーのため、クラウド routine ではなくプレーン Python＋ローカル cron で実装（安価・確実）。

## 実施内容

- `scripts/make_threads_draft.py` を新規作成
  - X投稿一覧を全取得し、候補を抽出: **ポスト種類=通常ツイート / 目的=有益 / 親ポストURL 空 / threads転載日 空 / 本文あり**（告知・誘導投稿や返信は除外）
  - `random.sample` で **重複なしに `--count` 件**選択（cron は `--count 4`）
  - セルフリプ（親ポストURLが選択投稿を指す行）があれば先頭1件を `[リプ]`/`[リプ画像URL]` に取り込む
  - `[投稿文]`/`[画像URL]` タグ形式でメール本文を組み立て、`create_gmail_draft.sh` で Gmail 下書き作成（件名 `【threads投稿】＋本文先頭20字`）
  - 成功したら選択行の `threads転載日` に当日日付を記録（重複防止マーク）
  - `--dry-run` 対応、IPv4 固定パッチ標準装備、ログは `logs/threads_draft.log`
- `scripts/run_threads_draft.sh` を新規作成（cron ラッパー、`--count 4`）
- X投稿一覧に **AH列「threads転載日」** を新設（スクリプトが冪等に作成）
- cron 登録: `0 8 * * *`（よーん実施。Claude からの crontab 変更はセーフティ判定でブロックされたため）

## 設計判断

- **重複管理はX投稿一覧のマーク列**: outputs シート（Threads permalink のみ）や Threads投稿一覧の手動 X投稿URL 列では自動突合できない。下書き作成時マークなら未送信でも重複しない。再選択したい場合は AH を手動クリア。
- **目的=有益のみ**: 初回テストで「note 50スキ超え」告知（目的=誘導・t.co リンク入り）が選ばれ、転載に不向きだったため絞った（候補 189→56件）。
- **500字分割・返信チェーンは下書き側では扱わない**: 既存 `post_threads.py` が投稿時に処理するため、本文はそのまま入れるだけでよい。
- 画像は pbs.twimg.com URL を `[画像URL]` タグで渡す（Threads が直接参照。添付不要）。

## 確認結果

- dry-run: 候補 55件から4件を重複なく選択、タグ形式の本文組み立てを確認
- 本番実行: Gmail 下書き作成 → AH 列マーク（`2026-07-12`）→ exit 0 の完走を確認（`list_drafts` とシートで実在確認）
- 再実行時にマーク済み行が候補から除外されることを確認

## 今後の課題

- セルフリプは直下1件のみ取り込み（メール形式が `[リプ]` 1つのため）。多段セルフリプ・引用は対象外。
- 候補が尽きたら何もしない（ログのみ）。再転載したい投稿は AH 列をクリアすれば再選択可。
