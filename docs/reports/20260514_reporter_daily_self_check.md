## 背景・動機

`style/style-reporter.md` には「専門用語・略号は使わず一般語で言い換える」「何を実装したかではなく運用がどう変わるかを書く」というルールが明記されているが、`reporter-daily` の実行時にこのルールを守りきれず、`git push` / `MCP` / `プロキシ` / `403` といった専門用語が混じった特記事項を生成してしまうことがあった。ルール本体は存在するのに参照が薄く、生成直後の自己点検手順がないために漏れが起きていた。

## 実施内容

- `reporter-daily` SKILL.md の STEP 5 に「自己チェック（保存前に必ず実施）」サブステップを追加
- 保存（STEP 6）前に必ず以下の3項目を1つずつ確認し、1つでも引っかかったら書き直すフローに変更
  1. 専門用語チェック（`git push` / `MCP` / `プロキシ` / `403` / `hook` / `フック` / `commit` / `master` / `branch` / `API` / `ID` などの混入を検出）
  2. 「何を」ではなく「どう変わるか」チェック（実装行為の動詞が主役になっていないかを検出）
  3. 読者想定チェック（「システムを知らない友人」に読ませて伝わるか）

## 設計判断

ルールを `style/style-reporter.md` に増やすのではなく SKILL.md の STEP 内に「自己チェック」として明示的に組み込んだ。スタイル定義は読み飛ばされやすいが、STEP として手順化されていれば実行フロー上で必ず通過するため、ルールが効きやすい。

## 確認結果

`/reporter-daily` を次回実行時に、特記事項の生成 → 自己チェック → 保存の順で進むことを確認する。
