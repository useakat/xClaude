## 背景・動機

X ワンポイント解説（W003）の原稿作成は、専用スキル `writer-xonepoint` に依存していた。一方、z01 は同種の役割を共通スキル `writer-xpost`（作業フォルダの `spec.md`/`plan.md`/`brand.md` に完全委譲する汎用 writer）に統合済みで、W003 だけが個別スキルに取り残されていた。

さらに、W003 には 2026-08-12 に導入された「X の折り返し位置（280weight）を設計対象にする工程」があり、原稿を書き上げたあとの検品として `/check-reader --fold` を回す運用になっていた（spec フロー5.4）。しかし検品時点では既に本文が確定しているため、折り返し位置の不備（語の途中で切れる等）が見つかると本文の後半を書き直す手戻りが発生していた。「太陽が明るくなる」投稿の制作で、この手戻りが複数回発生したことが直接のきっかけとなり、折り返し設計を執筆段階に前倒しする必要があると判断した。

## 実施内容

- W003 の spec.md フロー4を `/writer-xonepoint` から `/writer-xpost` 呼び出し（文字数範囲 200〜260字を指定）に切り替え、`/writer-xonepoint` を廃止予定と明記した
- `writer-xonepoint` にのみ存在した実データ知見（冒頭の入り口が日常かどうかでインプレッションが約80倍変わる実測4件、推奨字数レンジの実測根拠、高フォロー率投稿は明示CTAなしという実測知見）を、`writer-xpost` が参照する W003 の `brand.md` へ移植した
- 原稿の保存先をテーマフォルダのパス（`projects/w003/YYYYMMDD_[topic]/draft/draft.md`）まで明示し、タイトル案10個の出力は不要と spec に明記した（図解タイトルは `output/index.md` の冒頭1文を使う運用のため重複していた）
- `writer-xpost` に「ステージ2.5: 可視ブロック設計」を新設した。発動条件は「作業フォルダの `brand.md`/`spec.md` に折り返し制約の定義があるか」とし、無ければスキップする（z01 には折り返し制約が無いため影響を受けない）。定義がある場合のみ、冒頭フック決定の直後に可視ブロック（タイムラインで実際に表示される先頭部分）だけを先に書き切り、`x_fold_split.py` 等で切れ位置を機械確認したうえで `/check-reader --fold` にかけ、判定「押す」かつ引きの強さ8以上になるまで最大3ループ書き直す

## 変更ファイル

| ファイル | 変更内容 |
|---|---|
| `projects/w003/spec.md` | フロー4を `/writer-xpost` 呼び出しに切り替え、保存先パス明示、タイトル案不要を明記 |
| `projects/w003/brand.md` | `writer-xonepoint` 固有の実データ知見（インプレッション実測4件・字数レンジ根拠・CTAなし根拠）を移植 |
| `.claude/skills/writer-xpost/SKILL.md` | ステージ2.5（可視ブロック設計）を追加。判定基準・書き直しループ・出力形式を新設 |

## 設計判断

**スキル側に W003 固有の分岐を書かず、判断基準を brand.md 側に持たせた。** `writer-xpost` は「本文の内容・構成は spec.md、読者は plan.md、文体・NG・字数は brand.md に従う」という全面委譲の設計になっており、z01 と W003 の両方で同じスキルが機能している理由もそこにある。ここに「W003 のときは可視ブロックを設計する」という条件をハードコードすると、この設計が崩れる。そこで「作業フォルダの brand.md/spec.md に折り返し制約の定義があるか」を発動条件にし、W003 の brand.md にはすでに折り返し制約（段3の「問い1行」までを280weight以内に収める・採点項目7）が存在する一方、z01 の brand.md には該当記述が無いことを利用して自然に分岐させた。

## 確認結果

「太陽が明るくなる」投稿の制作で、ステージ2.5導入前の運用（検品としての5.4のみ）を実際に踏んだ。最初の確定稿は可視ブロックが「そして太陽は、少しずつ明るさを増」という語の途中で切れており、5.4の検品で発覚。素朴な読者役による判定は1ループ目が引きの強さ7/10で不合格、可視ブロックに期待の裏切り（「まん中にいると思っていた。違った。」）を追加した2ループ目で8/10に到達し収束した。この経験に基づき、同じ手戻りを執筆段階で防ぐためステージ2.5を新設した。ステージ2.5自体は次回以降のW003制作で初めて通ることになる（今回の投稿はステージ2.5導入前のフローで完走済み）。
