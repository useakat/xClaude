## 背景・動機

ケプラー記事（`projects/w002/2026-07-04_kepler-k2-revival/`）の初稿（7/12・`9074bba`）と最終稿を比較したところ、改稿コストの大半が**執筆前に決められたはずの判断**に起因していた。

差分の内訳：

1. **構造の組み替え（最大コスト）** — 薄いH2（436字）が隣と重複して統合が必要になった。また「なぜ黄道面上の星なら姿勢を保てるのか」という読者最大の難所が本編で理由なしに断言されており、最終的に付録H2（約1,800字）を新設して丸ごと書き下ろすことになった
2. **主筋に効かない技術詳細の削除（約1,000字）** — funnel-brief の深掘りメモを「使うべきリスト」として消化してしまい、星自身のノイズの説明（出典2本ごと）・ホイールの運動量の詳細・使わない固有名などを書いてから削った
3. **読者の疑問の先回り** — 「実証テストで5%以内 vs 測光精度3〜4倍悪化」の見かけの矛盾など、読者の疑問をセリフで先に立ててから答える形への直しが執筆後に発生した
4. **トーンの微修正** — 過剰断定の緩和など。これは既存の2周目セルフチェックが機能しており、コストは小さかった

1〜3 はいずれも agenda（構成承認）段階または執筆直前に判断できる。また難所の特定を書き手が自分で行うと知識の呪いで漏れるため、よーんの提案により、**plan.md の想定読者ペルソナになりきった読者役エージェントに構成案を読ませて疑問を出させる**方式とした。新スキルは作らず、既存の `/check-reader`（執筆後の検品）に構成モードを追加してロジックの二重管理を避けた。

## 実施内容

- `projects/w002/spec.md` に**構成フェーズ共通ルール**（A5・B7・C6 に適用）を新設
  - **難所マップ**: `/check-reader --plan ../plan.md {タイトル＋構成案}` で読者役に「章ごとの疑問・期待する種明かし・難所の予感」を列挙させ、writer が各疑問の扱いを**本編で解く／付録に送る／断言で流す**から決めて agenda に明記する。主筋を止めるが省くと論理が飛ぶ説明は「付録」H2 に切り出してよい（記事末尾・参考情報の前）
  - **H2統合チェック**: 文字配分600字未満のH2は隣接H2との統合を検討し、分けたまま残す場合は理由を添える
- `projects/w002/spec.md` の**本文フェーズ（共通フロー6）**に執筆前ルールを追加
  - **事実の採用マーク**: 深掘りメモ・notebook の事実は「使える在庫」であり「使うべきリスト」ではない。「主筋（執念の物語）にどう効くか」を1行で書けた事実だけ採用する
  - **読者疑問への回答割り付け**: agenda の難所マップで「本編で解く」とした疑問に回答段落を割り付けてから書く。見かけの矛盾は読者の疑問をセリフで先に立てる
  - **図番号は本文の登場順に採番**（funnel-brief・image-plan の番号と食い違えば本文側で振り直す）
- `projects/w002/spec.md` の Verification に検証項目2つを追加（難所マップ・統合判断への準拠／図番号の登場順）
- `.claude/skills/check-reader/SKILL.md` に**構成モード（`--plan`）**を新設
  - 引数の先頭が `--plan` なら構成モード。ペルソナ確定は通常モードと同じ（第1引数の `.md` → 作業フォルダの `plan.md` の Audience → デフォルト）
  - 読者役エージェントには**タイトル＋構成案のみ**を渡す（制作文脈を渡さない隔離は通常モードと同じ）
  - 出力は H2 ごとの疑問リスト表＋期待される種明かし。**扱いの決定は呼び出し元 writer の仕事**と線引きし、改稿ループは行わない（1回で完了）

## 設計判断

**新スキルではなく check-reader の拡張にした。** 疑問リスト作成に必要な中核の仕組み（plan.md の Audience からのペルソナ確定・制作文脈を渡さない隔離・疑問の列挙フォーマット）は通常モードと同一で、新スキルにすると同じロジックが二重管理になる。入力（構成案 vs 原稿）と出力（疑問リスト vs 改稿済み原稿）だけが異なるため、`--plan` フラグでのモード分岐が最小の変更で済む。

**疑問の列挙と扱いの決定を分離した。** 読者役は「何が分からないか」の専門家だが、「どう扱うか」（本編／付録／断言）は構成・字数・課金壁の設計に依存する writer の判断のため、スキルの責務を列挙までに限定した。
