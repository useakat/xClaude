## 背景・動機

同日実施した「測定量を読者の意味に翻訳するルール」（[→報告書](../reports/20260815_z01_metric_translation_rule/)）の続きの推敲で判明した問題。DART（noteNeta[84]）の初稿は、ネタ元が持つ2つの驚き——「合格ラインを大きく超えて進路を変えた」と「放出された岩塊の反動が探査機本体の一撃を上回った」——を両方 140 字に詰め込んでいた。

読者役チェック（`/check-reader`）にかけたところ、「本体の3倍の勢いを持ち去った」の一文で読者が理解を放棄し、理解度は3ループとも4/10で頭打ちになった。原因は物理の難度ではなく、**1投稿に2つの驚きを入れたことで、どちらも説明を割く余地がなくなった**こと。最終的に反動の要素を削り「進路が変わった」1つに絞ったところ、テキストとしての誤解・曖昧さは解消した。

この教訓は Z01（140字固定・軽量高頻度枠）に固有の制約から生じるため、共通 `brand.md` ではなく z01 プロジェクトの `brand.md` に置いた。

## 実施内容

- `projects/z01/brand.md` の Writing Rules に「驚きは1投稿に1つ」セクションを新設。
  - 1投稿で読者に渡す驚きは1つに絞る（2つ入れると両方説明不足になる）
  - ネタ元に驚きが複数ある場合は最も強い1つを選び、残りは**昇格先（W001/W002/W003）候補**として扱い本文には入れない
  - 今回の DART の実例（進路変更を採用、岩塊の反動は割愛）を例示として明記

## 確認結果

- DART 投稿の確定稿（138字、Gmail 下書き反映済み）は、驚きを「進路変更の成功」1つに絞った状態で `/check-reader` の指摘が解消していることをセッション内で確認済み。
- 新ルール自体は次回以降の Z01 制作（無人 routine）で `/writer-xpost` 呼び出し前の `brand.md` Read 時に適用される。

## 今後の課題

- 「ネタ元の驚きが複数あるとき、どちらを残すか」の判断基準（インパクトの強さ・読者の反応しやすさ等）は現状 writer の裁量に委ねている。複数件の実運用で判断が割れるようなら、選定基準を明文化する。
