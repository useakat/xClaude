## 背景・動機

`research_xhook` スキルで @russianblue2009 の814投稿を分析し、IMP平均上位の4型（逆説・常識覆し型／知識提示型／ドラマ・場面描写型／問いかけ型）を構文レベルで帰納化した（[分析報告書](./20260530_research_xhook_russianblue2009/)）。

この知見を分析報告書に埋もれさせず、X投稿の冒頭フックを書く実作業で即座に引き出せるようにしたい。各 writer スキルが冒頭1文を作るたびに、構文バリエーションの引き出しとして参照できる共通アセットが必要だった。

note 系（writer-note）はフォーマット・狙いが異なるため対象外とし、X系 writer に限定して参照を追加する方針とした。

## 実施内容

- `style/hook-patterns.md` を新設。4型それぞれを「構文テンプレート／実例／物理・宇宙への応用例」の3列テーブルに整理し、横断技法（引用符強調・数字スケール・①×④の組み合わせ）と「避けるべき冒頭」も収録した。
- ヘッダーで「共通の人格・NG表現は `brand.md` 参照」「各スキル固有のフック制約が優先・本ファイルはバリエーションの引き出し」という位置づけを明記。
- X系 writer 4スキルのフック関連セクションに、`style/hook-patterns.md` への参照を1行ずつ追加。いずれも「各スキル固有の形式が最優先・本ファイルは引き出し」と明記し、既存ルールを上書きしない設計にした。
- 分析報告書（russianblue2009）末尾にも「冒頭フック 表現テンプレート集（応用可能形）」を追記し、報告書単体でも参照できるようにした。

## 設計判断

- **配置先を `style/` にした理由**：複数スキルが共有する文体アセットは `style/style-*.md` に置く既存慣習（例：`style-xonepoint.md`）に合わせ、1ファイルを4スキルから参照する形にした。各スキルにテンプレートを直書きすると重複・更新漏れが発生する。
- **優先順位を明示した理由**：各 writer は既に固有のフック制約（writer-xonepoint の「実は〜」形式など）を持つ。共通テンプレートがそれを上書きすると各スキルの個性が崩れるため、「固有制約が最優先・本ファイルは引き出し」と全参照で統一した。
- **note 系を対象外にした理由**：note は長文ナラティブで冒頭設計の狙いが X と異なるため、ユーザー指示通り X系のみに限定した。
