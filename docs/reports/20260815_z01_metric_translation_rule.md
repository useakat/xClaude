## 背景・動機

Z01（X 短文投稿）の DART 投稿制作で、無人 routine が作った初稿に対しユーザー推敲が7往復発生した。修正の内訳を見ると、個別の好みではなく**一般化できるルール**が大半だった。

初稿と最終稿の差分：

```
（初稿）
いつか地球を狙う岩に備えた予行。人類は1100万km先の小惑星に探査機をぶつけた。相棒の星を回る周期が、
合格ラインのわずか73秒に対し32分も縮んだ。しかも砕け散った無数のかけらが反動で押し返し、機体の
一撃以上に星をずらした。地球は守れると初めて知った、誤算まじりの勝利だ。

（最終稿）
いつか地球に衝突する小惑星に備えた実験として、2022年、NASAは1100万km先の小惑星に探査機をぶつけた。
狙いは、進路をずらせるか。結果、進路を目標以上に変えることに成功。いつか来る小惑星も、自分たちの手で
逸らせるかもしれない。人類が初めてその手応えを感じた一歩だった。
```

差分から抽出した問題は5種類：

1. **5W1H の欠落** — 年（2022年）も実施主体（NASA）も書かれていなかった。
2. **途中経過を結論として書いた** — 「周期が32分縮んだ」は軌道変更を地球から測るための**中間指標**であって、読者が受け取るべき意味は「進路を変えられた」。読者役チェックでも「何の周期？」「縮むとなぜ守れるの？」が3ループとも解消せず、理解度は4/10 で頭打ちだった。
3. **要素の詰め込み** — 「32分短縮」と「放出された岩塊の反動」の2つの驚きを 140 字に入れ、どちらも説明不足になった。
4. **言い換えのやりすぎ** — 「イメージのわく表現に置き換える」ルールを適用しすぎ、一般に通じる「小惑星」まで「岩」に変えて、脅威と破片が同じ語になり混乱を生んだ。
5. **達成の誇張** — 「守れると知った」「勝利だ」と言い切っていた。

このうち 2 は Z01 固有ではなく**全プロジェクト共通の書き方の問題**のため、継承の根であるルート `brand.md` に置いた。1・4・5 は Z01 の検証項目・語彙帳に落とした。

## 実施内容

- ルート `brand.md`「言葉遣いの共通ルール」に、測定量・中間指標を読者の意味・意義に置き換えるルールを追加した。既存の「数値・年月日・人物名は具体的に書く」の直後に隣接させ、両者が対で読めるようにした（離すと「具体的に書け」と「意義に翻訳しろ」が矛盾して読める）。
- `style/z01-phrasebook.md` を v1.2 に更新し、「語彙・言い換えの範囲」カテゴリを新設（一般に通じる語は言い換えない）、「帰結・達成の描写」に控えめな断定の好みを追記した。
- `projects/z01/spec.md` の Verification に2項目を追加した（`/check-critic` 通過、ストーリー型・ニュース型での「いつ・誰が」明記）。

## 設計判断

**測定量ルールの置き場所をルート `brand.md` にした理由**

| 候補 | 判断 |
|---|---|
| ルート `brand.md` | **採用**。各プロジェクトの `brand.md` が `Inherits` で継承する根であり、CLAUDE.md が制作前の Read を義務づけているため読み落としが起きない |
| `style/story-check.md` | 見送り。物語型（W001/W002/Z01 の物語型ソース）限定のチェックリストで、ニュース・解説系に効かない |
| 各プロジェクトの `brand.md` | 見送り。4プロジェクトに同じ記述が分散し、更新が揃わなくなる |

**ルールを禁止形にしなかった理由**

「測定量・中間指標は書かない」という禁止形にすると、日報・週報のように生の測定量が必要な文書まで巻き込む。「**対象読者がその意味・意義を理解できるかを判定する**」という判定形にしたことで、レポート類は読者がよーん自身であり判定を通るため、例外規定を書き足さずに済んでいる。

**制作フローの順序は変更しなかった**

検討の過程で `/check-fact` → `/check-reader` の順に入れ替えたが、最終的に既存の `/check-reader` → `/check-fact` → `/check-critic` → `/check-brand` に戻した。

## 確認結果

- `brand.md`・`style/z01-phrasebook.md`・`projects/z01/spec.md` の3ファイルを master に push 済み（`e13d09f`・`81f7dd7`）。
- 今回の DART 投稿の Gmail 下書きは、確定稿（138字）で `[最終原稿]`／`[投稿文]` の両ブロックを更新済み。spec.md の「1投稿1下書き」に従い、新規下書きは作成せず `update_draft` による同一下書きの in-place 更新で対応した。
- ファクトチェックで、ネタ元 `noteNeta[84]` D 列の「地球から680万km」が誤り（NASA の 7 million **マイル** を km と取り違えた値）と判明し、本文は約1100万kmに訂正した。**シート側の数値は未修正のまま**。

## 今後の課題

- `noteNeta[84]` の D 列「680万km」→「約1100万km」の修正（再利用時に同じ誤りを引き込むため）。
- 今回の推敲で残った「驚きポイントは1投稿1つ」ルールは未反映。140 字に驚きを2つ入れると両方が説明不足になる問題で、Z01 の `brand.md` に入れる候補。
- 読者役チェックが3ループとも理解度4/10 で収束しなかった件は、`/check-reader` の収束条件（理解度8以上）に届かないまま下書きに進む経路が残っている。Z01 の 140 字制約では構造的に回収できない疑問があり、その場合の扱い（昇格先へ送る判断）をフローに書くかは未決。
