## 背景・動機

6/12/17 時の定時投稿（ワンポイント W003 / 質問回答 W006 / X長文 W001）は、対応する `【…】` 件名の Gmail が INBOX に無いと**何も投稿せず空振り**していた。投稿の空き枠を埋めて毎日の発信量を確保するため、「投稿対象が見つからない場合は代わりに X短文投稿（z01）を出す」フォールバックを入れる。あわせて 21:00 に z01 短文の専用投稿枠を設ける。

従来の z01 専用投稿（7/13/19）は、この新方式（6/12/17 フォールバック＋21:00）に置き換える。

## 実施内容

- `post_from_email.sh` に**終了コード**を導入：`0`=投稿成功 / `20`=投稿対象メールなし（フォールバック合図）/ `1`=投稿試行失敗。内部で結果ステータス（posted/none/failed）を追跡して末尾で `exit` する。dry-run は posted 扱い（0）。
- ラッパー3本（`run_xonepoint_post.sh` / `run_question_post.sh` / `run_xlong_post.sh`）を `exec` 一行から **rc 判定方式**に変更。本来の投稿を実行し、**rc=20（対象なし）のときだけ** `post_from_email.sh "【X短文投稿】" z01 x_post_short.log` を代替実行する。**rc=1（投稿失敗）では代替しない**（二重投稿・失敗時の誤投稿を防ぐ）。
- crontab を組み替え：`0 7,13,19 * * * run_xshort_post.sh`（z01 専用）を**削除**し、`0 21 * * * run_xshort_post.sh` を**追加**。6/12/17 と 8:00（下書き作成）はそのまま。

## 変更ファイル

| ファイル | 変更内容 |
|---|---|
| `scripts/post_from_email.sh` | 結果ステータス追跡＋終了コード（0/20/1）を導入 |
| `scripts/run_xonepoint_post.sh` | `exec`→rc判定。rc=20 で z01短文を代替投稿（6:00, W003） |
| `scripts/run_question_post.sh` | 同上（12:00, W006） |
| `scripts/run_xlong_post.sh` | 同上（17:00, W001） |
| （crontab） | 7/13/19 の z01専用を削除、21:00 を追加 |

## 設計判断

- **「対象なし(20)」と「投稿失敗(1)」を区別**：失敗時にフォールバックすると、本来投稿（INBOX に残り次回再試行される）に加えて z01 も出てしまうため、フォールバックは rc=20 限定にした。
- **z01 投稿は `run_xshort_post.sh` を再利用**（21:00・フォールバックとも同じ `post_from_email.sh "【X短文投稿】" z01 …`）。

## 確認結果

- 全スクリプト `bash -n` 構文チェック OK。
- 存在しないキーワードで `post_from_email.sh` を実行 → `exit 20`、ログに `完了 (result=none, exit=20)` を確認（フォールバック合図が機能）。
- `crontab -l` で 7/13/19 削除・21:00 追加を確認。

最終 cron 構成:
```
6:00  ワンポイント → なければ z01短文
8:00  z01下書き作成
12:00 質問回答    → なければ z01短文
17:00 X長文      → なければ z01短文
21:00 z01短文（専用）
```

## 今後の課題

- **z01 下書きの供給**：下書き作成は 8:00 に1日1本だが、投稿は最大4回/日（フォールバック3＋21:00）になりうる。下書きはレビュー→送信→INBOX 着信で供給されるため、在庫が尽きると z01 投稿は空振り（exit 20）になる。運用しながら下書き本数を調整する。
- 実投稿の通し確認は次回 cron 稼働時に行う（本記録時点では構文・終了コードまで検証）。
