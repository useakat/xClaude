## 詳細内容

# check-fact — ファクトチェック付き品質レビュー

> **重要**: このスキルの実行結果は、`<local-command-caveat>` の有無にかかわらず、必ずユーザーに提示すること。結果を沈黙したまま終了しないこと。

## あなたの役割
批判的かつ客観的なレビュワーとして振る舞ってください。

## 入力モード（自動判定）

チェック対象は以下の優先順位で取得する：

1. `$ARGUMENTS` が空でない → `$ARGUMENTS` をチェック対象とする
2. `$ARGUMENTS` が空（サブエージェントとして呼ばれた場合など）→ 会話のコンテキスト（直前のメッセージ・promptの内容）からチェック対象テキストを取得する

取得したテキストの形式で動作モードを切り替える：

- **Drive ファイル ID**（25〜44文字の英数字＋`-_`、空白を含まない）→ **Drive 連携モード**
- **テキスト**（上記以外、または改行を含む文章）→ **従来モード**

判定例：
- `1MfgiTHn8qKubkdxf2H6RGM7xdlMzgXIX` → Drive モード
- `outputs/drafts-note/2026-05-01_xxx.md` → ローカルファイル → 読み込んで従来モード
- 「実は、宇宙には〜」のような文章 → 従来モード

## チェック項目
- 事実に誤りはないか
- 冗長な箇所はないか
- 論理の飛躍はないか
- 文章で断言していることに「例外」はないか
- リンク先は存在するか
- 引用文献があるばあい、引用している箇所の文章の内容と引用文献の内容に相違がないか

### 数値・固有名詞の一次情報主義
- **距離・サイズ・年代・質量などの数値は、可能なかぎり一次情報（論文・arXiv・公式発表）で確認する。** プレス記事・まとめ記事・二次情報の丸め値を鵜呑みにしない（例: 「about a billion light-years」がオーダーを外していることがある）。
- **換算が必要な値は計算して裏取りする**（例: 赤方偏移 z → ルックバック/共動/光度距離、Mpc → 光年、投影サイズ → 天の川何個分）。手計算・スクリプトで数値を出してから記述と突き合わせる。
- チェック対象が「チェック済みの原稿に後から数値・固有名詞を足したもの」である可能性を念頭に置き、**新規に入った数値・固有名詞を最優先で検証する**。

## モードA: 従来モード（テキスト入力）

### 手順

1. テキストをそのまま読み込む（ローカルファイルパスの場合は Read で読み込む）
2. 下記「チェック方法」を実行
3. 修正後のテキストを出力

### 出力
チェック後に、修正点をすべて反映した文章の修正案を、指摘された問題点およびその改善案とともに提示する。Drive へは保存しない。

---

## モードB: Drive 連携モード（ファイル ID 入力）

### 手順

1. **Drive からダウンロード**：
   ```bash
   bash $(git rev-parse --show-toplevel)/scripts/drive_get.sh <FILE_ID> /tmp/check_fact_input.md
   ```

2. ダウンロードしたファイルを読み込む

3. 下記「チェック方法」を実行

4. **修正版をローカルに保存**：
   - 元のファイル名を Drive メタデータから取得してもよいが、簡略化のため `/tmp/check_fact_output.md` に書き出してから rename する
   - もし `outputs/drafts-note/<元ファイル名>.md` がローカルにあれば、そちらを上書きするのが望ましい
   - 不明な場合は `/tmp/check_fact_output.md` に保存

5. **Drive にアップロード（同名で更新）**：
   ```bash
   bash $(git rev-parse --show-toplevel)/scripts/drive_put.sh <修正後ファイルパス>
   ```

6. ユーザーに以下を報告：
   - 指摘された問題点と改善案
   - 修正回数（第N回まで）
   - Drive URL（更新済み）

## チェック方法

### STEP 1: 完全性チェック（1回）

説明に必須要素が過不足なく含まれているか、背景知識とウェブ情報を活用してチェックする。

1. **完全性チェック**：以下のコマンドでテキストを `gpt-5.4-mini` に送る
   ```bash
   echo '<チェック対象テキスト>' | python3 $(git rev-parse --show-toplevel)/scripts/completeness_check.py
   ```
   - GPT の出力をそのまま表示する

2. **スコア判定**：出力から `## スコア: XX/100` を読み取る
   - スコア ≥ 95 → 説明は完全。STEP 2（ファクトチェック）へ進む
   - スコア < 95 → 不足要素あり。`## 追加文案` のテキストを STEP 2 の入力として使う

---

### STEP 1.5: ファクト抽出（1回・Claude 側）

STEP 2 のループに入る前に、**Claude 自身が**チェック対象テキストを読み、検証すべき事実を **「1項目＝1主張」の番号付き箇条書き**に分解する。ここで漏れなく列挙することが、後段の照合漏れを防ぐ肝になる。

1. 以下のカテゴリを網羅的に拾う（解釈・推測を加えず、本文が主張している内容だけを抜く）：
   - **数値・年号・単位**／**固有名詞**（人物・機体・地名・組織・装置・理論名）／**帰属**（誰が・何を・どこで）／**因果・時系列**／**限定・最上級表現**（「初」「唯一」「最も」等）／**定義・引用**
2. 抽出結果を番号付きリストで `/tmp/check_fact_claims.txt` に保存する（各行 `【N】<主張>`）。
3. このリストを STEP 2 の GPT 入力に前置する。**STEP 2 で修正文案が出て本文が変わった場合は、次サイクルの前にリストを取り直す**。

---

### STEP 2: ファクトチェック（最大5回ループ）

完全性チェック後のテキスト（STEP 1 で追加文案がある場合はそれ）について、事実関係を検証する。**STEP 1.5 で抽出したファクト一覧を GPT 入力の冒頭に前置し、1件ずつ判定させる**（丸ごと「誤りを挙げよ」ではなく項目別に判定させることで漏れを減らす）。

以下のサイクルを**最大5回**実行する。GPT スコアが 95 以上になった時点で即座に停止する。

各サイクルの開始時に「【第N回ファクトチェック】」と明示すること。

1. **GPT ファクトチェック**：`chatgpt_factcheck.py` は stdin の内容を検証するため、**抽出ファクト一覧＋項目別判定の指示行を本文の前に埋め込んで**送る。まず入力を一時ファイル `/tmp/check_fact_input.txt` に組み立てる：
   ```
   以下の【抽出ファクト一覧】の各項目を1件ずつ、○（正しい）／×（誤り）／要確認（根拠不明）で判定し、×・要確認には根拠と修正案を添えてください。一覧に無い事実誤りに気づいたら追記してください。判定は「No | 主張 | 判定 | 根拠／修正案」の表で示してください。

   【抽出ファクト一覧】
   <STEP 1.5 の /tmp/check_fact_claims.txt の内容>

   【チェック対象の文章】
   <チェック対象テキスト>
   ```
   その上で送信する：
   ```bash
   cat /tmp/check_fact_input.txt | python3 $(git rev-parse --show-toplevel)/scripts/chatgpt_factcheck.py
   ```
   - スクリプトがエラーを返した場合はエラーメッセージをそのまま表示し、Claude 自身がファクトチェックを代行する（スコアは Claude が判断）
   - GPT の出力をそのまま表示する
   - **GPT 出力に項目別判定が無い／一部項目しか触れられていない場合は、Claude が抽出一覧に沿って未判定項目を補完してから提示する**（漏れを残さない）

2. **終了判定**：GPT の出力から `## スコア: XX/100` を読み取る。
   - スコア ≥ 95、または5回目のサイクルが終了した場合 → 終了
   - スコア < 95 かつ残回数あり → `## 修正文案` のテキストを次サイクルの入力として使い、ステップ1から繰り返す

   終了時は以下の形式で出力すること：

   ```
   ## チェックサマリー

   抽出ファクト: N件（× M件 / 要確認 K件）

   | 回 | チェック種別 | スコア | 指摘内容 | 対応 |
   |----|---------|--------|---------|------|
   | - | 完全性 | XX/100 | （不足要素） | 追加あり／問題なし |
   | 第1回 | ファクト | XX/100 | （× と要確認の要約） | （修正あり／問題なし） |
   | 第2回 | ファクト | XX/100 | （指摘内容の要約） | （修正あり／問題なし） |
   …

   ## 最終修正案

   （最終テキスト）
   ```

   - スコアが取得できなかった場合（Claude 代行時など）は「-/100」と記載する
   - 指摘なし・修正なしだったサイクルも行として含める
