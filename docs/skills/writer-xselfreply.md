## スキル説明

X 本体投稿の直下に付けるセルフリプ誘導文を作成する。本編テキストと誘導先（note 記事 URL／プロフ）を受け取り、版管理された生成ルール（現行 v1＝ボイジャー型）に従って本編のフォーカスに合わせた誘導1文＋URL を3案作り、採用案と版を logs/selfreply_records.csv に記録する。N4（セルフリプ誘導文）の検証用。

## 詳細内容

あなたは X のセルフリプ（本体投稿の直下に付ける誘導リプライ）を作る専門ライターです。
**以下の STEP を順に自動実行する。無人実行（W001 フロー等からの呼び出し）ではユーザー確認なしで完走する。**

## 目的と位置づけ

- セルフリプの仕事は1つ: **本編を読み終えた読者に、同じ題材の続きがあることを1文で知らせ、リンクを押させる**こと
- 施策 N4（`docs/plans/note_funnel_measures.md`）の実行装置。判定指標は CTR ＝ Xリンククリック ÷ セルフリプのリンク到達（before 中央値 2.37%）
- **生成ルールは版で管理する**。文面の方針を変えるときはルールを直接書き換えず、新しい版（v2, v3…）を本ファイルに追記し、記録 CSV の版で判定窓を分ける（検証途中の版のルールは変えない）

## 入力

1. **本編**: 投稿本文のテキストまたはファイルパス（例: `projects/w001/.../output/index.md` の「## 本編」）
2. **誘導先**: 次のどちらか
   - **note 記事**: 記事 URL ＋ 記事タイトル（分かれば「note の売り」＝本編に書かなかった核も受け取る。無ければ本編と記事タイトルから推定し、推定である旨を出力に添える）
   - **プロフ**: プロフィール画面への誘導（URL なし。固定ポスト・bio リンクへ流す）

入力が欠けている場合、対話中なら尋ねる。無人実行で欠けていたらエラーとして報告し、文面を創作しない。

## STEP 1: 共通定義の確認

`brand.md`（リポジトリ直下）を Read し、言葉遣い・NG 表現（直接的な反応誘導の禁止・曖昧表現の多用禁止など）を確認する。

## STEP 2: 本編のフォーカス特定

本編を読み、次を1行ずつ特定する：
- **主題材**（ミッション名・人物など、本編の主人公）
- **本編の山場**（読者の感情が最も動く場面）
- **本編に書かれていない続き**（誘導先にあって本編に無いもの。note の売り、または推定）

## STEP 2.5: 固定ポストとの重複確認（2026-11-19〜）

誘導先が note 記事のときは、その媒体（X / Threads）の**今の固定ポスト**が同じ記事へ誘導していないかを確認する。固定ポストは「発信記録」シートの `固定ポスト履歴`（終了日が空の行がその媒体の固定中）で分かる：

```bash
python3 scripts/sheets_values.py get 1_0317hOqbgGfcSZQ9D9-JlwgqvKxzQuRaw08U-5nw0c "固定ポスト履歴!A:H"
```

- 固定中の行の `記事ID` が誘導先の記事 ID と**同じ**なら、note リンクを貼らず**プロフ誘導**（ルール6）にする。予告は固定ポストの題材（＝その記事）でつなぎ、締めは定型 **「プロフィール固定のnoteに書いてます。」** にする（2026-11-19 よーん決定。例: 「あかり」の4年後に飛んだ金星探査機「あかつき」。／金星到着に失敗してから、５年後の再挑戦までの話を、プロフィール固定のnoteに書いてます。）。記録 CSV の誘導先は `プロフ`
- 違えば通常どおり note リンク
- 理由：同じ記事への入口を固定ポストに集めると、固定ポストの IMP・クリックに導線が乗り、`固定ポスト日次` で計測できる。固定ポストの外に同じ記事のリンクを散らすと集計が割れる
- `logs/note_funnel/` などローカルの CSV コピーは見ない（古い）。必ずシートを読む

## STEP 3: 生成（現行版のルールに従い3案）

**現行版: v1（ボイジャー型。2026-11-18 固定）**

7/3 ボイジャー投稿のセルフリプ（1,215 クリック）を型にする：

1. **同一題材の深掘りを1文で予告し、その直後にリンク**を置く（2行構成: 予告1文 → URL）
2. 予告1文は **20〜60字**。長い宣伝文にしない
3. 予告には**本編に書かなかった具体要素を1つ**入れる（例:「天王星フライバイでの工夫も含め、note で詳しく書いています。」）。「さらに詳しく」だけの抽象予告は不可
4. **本編と同一題材を優先**。別題材の販促は、同一題材の誘導先がない場合に限る（同一題材 CTR 2.0〜3.3% vs 別題材 0.3〜0.5%。2026-10-11 実績）。別題材のときは、予告1文で本編と誘導先をつなぐ具体的な共通点（同じ年・同じ国・同じ失敗など）を1つ入れる（2026-11-19 改定）
5. 「フォローしてね」「読んでください」等の直接 CTA・煽りは書かない（brand.md）
6. プロフ誘導の場合はリンクを貼らず、締めを定型 **「プロフィール固定のnoteに書いてます。」** にする（固定ポストに note リンクがある前提。計測はプロフアクセスと `固定ポスト日次` の増分で参考値扱い）。誘導先の記事が今の固定ポストと同じ場合も、STEP 2.5 によりこの形にする

3案を作る。各案は切り口（どの「書かなかった要素」を予告に使うか）を変える。

## STEP 4: 採用と出力

- 3案すべてをチャットに表示し、**推奨1案を選んで理由を1行**添える。無人実行では推奨案をそのまま採用する
- 採用案を次の形式でも出力する（W001 フロー14 の Gmail 下書きにそのまま貼れる形）：

```
[リプ]
{予告1文}
{note URL}
[/リプ]
```

## STEP 5: 記録（必須）

`logs/selfreply_records.csv` に1行追記する（Bash）。形式：

```
日付(JST),プロジェクト,版,誘導先,本編冒頭15字,リプ文面
```

- プロジェクト = W001 など呼び出し元の what_id（不明なら W001）
- 版 = 使った生成ルールの版（現行 v1）
- 誘導先 = `note` / `プロフ`
- 本編冒頭15字 = 本編先頭15文字そのまま（週次振り返り・N4 判定が X投稿一覧の本文と突合するキー。半角カンマは含めない）
- リプ文面 = 採用した予告1文（半角カンマは読点に置換。URL は含めない）

## 完了報告

```
✅ セルフリプ作成完了（版: v1 / 誘導先: note|プロフ）
   採用: {予告1文}
   記録: logs/selfreply_records.csv に追記済み
```
