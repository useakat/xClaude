## スキル説明

ネタ選定の直後に、X長文（W001）→ note（W002）の導線を前提とした「分割設計」を対話で確定する上流スキル。X長文でどこまで書くか／有料 note の“売り”に何を温存するか／セルフリプ文面まで決め、共有ブリーフ funnel-brief.md に保存する。本文は書かず、W001・W002 の制作に委譲する。

## 詳細内容

# plan-xnote-funnel

X長文（W001・約600字＋note誘導セルフリプ）と 有料 note（W002・6000〜8000字）を、
**ひとつのネタから一体で設計する**ための上流スキル。

やること：**ネタ確定 → 共有 notebook 準備 → 物語アーク把握 → 分割設計（対話・承認）→ 共有ブリーフ保存**。
やらないこと：本文執筆（X長文は `/writer-xstory`・W001 spec、note は W002 spec に委譲）。

前提となる導線モデル（既存）：**note を先に仕上げて公開 → その URL を載せたセルフリプ付き X長文を投稿**（クロス週モデル）。
X長文でバズらせ、セルフリプで note へ誘導する。

## 入力

`$ARGUMENTS`：任意。ネタを指定したい場合はタイトル/ミッション名など（省略時は `noteNeta` の未使用ネタから選ぶ）。

## 手順

ルートは `ROOT=$(git rev-parse --show-toplevel)`。**ユーザーに判断を求めたら、必ず回答を待ってから次へ進む。**

1. **ネタ選定。** `noteNeta`（SS1: `1zCT0Kv0Q0qr83c6e_jQxUJeUQ1Y8iz0Zlm_0U5RMaEM`, `noteNeta!A:M`）を `sheets_get_values` で読み、L列「未使用」から1件選ぶ（行番号が最小・直近5回の使用済みと同一ミッション名は除外）。`$ARGUMENTS` で指定があればそれに一致する未使用ネタを優先。**【選定ネタ】**（No／タイトル案／主人公(ミッション名)／時代・背景／危機／逆転のポイント／科学的見どころ／人間ドラマ／展開のヒント／出典メモ）と**【行番号】**を記憶する。
   - 選定ロジックは `draft_xstory` STEP 1–2 / `w001/spec.md` step 2 と同じ。ここではステータス更新は**しない**（実際に使うのは W001/W002 側）。

2. **共有 notebook を準備。** `/research_setup-sources` を【選定ネタ】のテーマ（タイトル案／主人公）で実行し、NotebookLM の notebook を作成、Deep Research で信頼できるソースを収集・追加する。返ってきた `notebook_id` を控える。**この notebook は X長文・note の両方が根拠にする**（W001/W002 が継承）。

3. **物語アークを把握。** notebook のソースだけを根拠に、**困難 → 工夫 → 逆転 → 意味**の骨子を要約する（ここに無い事実を作らない）。数値・人名・日付・装置の帰属を確認しておく。

4. **分割設計【対話・承認】。** 以下3点を提示し、**ユーザーの承認を待つ**（承認前に本文・ブリーフ確定へ進まない）。
   - **X長文の範囲**：約600字で**物語として完結**する範囲（W001 は中断型にしない・本編に「続きは note で」を入れない）。到達点＝どこまで描くか、と、**あえて詳細を出さない核**（＝note に温存する要素の当たり）を決める。
   - **note の“売り”（有料の引き）**：クライマックスの詳細・種明かし・独自資料/証言/年表・図解・意味の宣言など、有料部分の payoff。**課金壁の位置イメージ**（無料＝どこまで／有料＝どこから）を決める。
     ※ **note は X長文と独立した完結記事**として書くため、**X で触れた範囲を note が再度描くのは可**。分割の主眼は「有料部分に何を温存するか」であって重複回避ではない。
   - **セルフリプ文面**：note の“売り”を**1文で予告**し、`[note URL]`（公開後に差し替え）を添える（W001 の `## セルフリプ` Format に合わせる）。売りに依存するのでここで確定する。

   **設計制約**：分割は「**X＝完結した短い物語／note＝“決定版・完全版”（深掘り・種明かし・独自要素）**」とし、**X をクリフハンガーにしない**。

5. **共有ブリーフを保存。** 確定内容を `funnel-brief.md` に書き出す。
   - 保存先：note を先に作るため **W002 側**。`ROOT/projects/w002/YYYY-MM-DD_<短いタイトル>/draft/funnel-brief.md`（`<短いタイトル>` は【選定ネタ】から短く）。フォルダが無ければ `draft/` ごと作る。
   - 雛形：
     ```
     # ふりわけ設計ブリーフ — <topic>

     ## ネタ
     - タイトル案: … / 主人公(ミッション): … / noteNeta 行番号: …

     ## notebook
     - notebook_id: …

     ## 物語アーク
     - 困難 → 工夫 → 逆転 → 意味（要点）

     ## X長文の範囲（無料・約600字で完結）
     - ここまで書く（到達点）: …
     - あえて出さない核: …

     ## note の売り（有料の引き）
     - 有料部分の payoff（詳細・種明かし・独自要素）: …
     - 課金壁の位置イメージ（無料=どこまで／有料=どこから）: …

     ## セルフリプ文面
     - <note の売りを1文で予告> → [note URL]

     ## 制作順序
     - W002(note) を先に仕上げ・公開 → W001(X長文) を投稿（セルフリプに実 URL）
     ```

6. **報告。** 保存した `funnel-brief.md` のパスと、次の手順を伝える：
   - まず **W002（note）を モードC（協調／ブリーフ起点）** で制作（`projects/w002/spec.md`）。ブリーフの notebook_id・note の売り・課金壁を根拠にする。
   - note 公開後、**W001（X長文）を モードC** で制作（`projects/w001/spec.md`）。ブリーフの「X長文の範囲」で書き、**セルフリプはブリーフ確定文面**を使い、実 URL に差し替える。

## 禁止事項

- 本文（X長文・note）をこのスキルで書かない。分割設計とブリーフ保存までに留める。
- notebook のソースに無い事実を作らない（物語アーク・分割設計とも notebook 準拠）。
- 分割を**クリフハンガー**にしない（X本編は完結させる。本編に「続きは note で」を入れない）。
- `noteNeta` のステータス更新をここでしない（W001/W002 側の責務）。
- 承認前にブリーフを確定・保存しない（ステップ4の承認ゲートを守る）。
