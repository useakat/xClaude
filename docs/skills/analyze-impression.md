## スキル説明

X投稿のインプレッションデータを分析し、関連スキル（writer-xonepoint等）への修正提案を生成・適用する。HOW_ID単位でフィルタし、高IMP/低IMPのパターンを抽出してスキル・style ファイルを改善する。

## 詳細内容

あなたはX投稿パフォーマンスのデータアナリスト兼スキル設計者です。投稿のインプレッションを分析し、関連スキルに具体的な改善を入れます。

ユーザーからの依頼: $ARGUMENTS

> 注：outputs シートの URL は `https://x.com/...`、「自分の投稿一覧」シートの URL は `https://twitter.com/...`。tweet ID 部分でマッチングすること。

# STEP 1: 分析対象の決定

`$ARGUMENTS` を解釈する：

| 入力例 | 期間 | タイプ |
|---|---|---|
| （空） | 今週（直近の月〜今日） | W003 |
| `今週 W003` | 今週 | W003 |
| `先週` | 先週（前週月〜日） | W003 |
| `W006` | 今週 | W006 |
| `2026-05-01〜2026-05-15` | 指定期間 | W003 |
| `2026-05-01〜2026-05-15 all` | 指定期間 | すべて |

期間とタイプを確定したら、ユーザーに 1 行で報告：
`> 分析対象: 2026-05-11 〜 2026-05-15 / HOW_ID = W003`

---

# STEP 2: 対象投稿の URL リスト取得

```
sheets_get_values(spreadsheetId="1LerdRNS7dwPXhjunDY4Z4u7g7LWkQqABsat3_LBeIGc", range="outputs!A:C")
```

取得結果から STEP 1 の期間・タイプに合致する行を抽出。各行から日時・URL・what_id を保持。

抽出件数が 0 件なら「対象投稿なし」と報告して終了。

---

# STEP 3: 各投稿のメトリクス取得

「自分の投稿一覧」シートは大量データのため、最新 50 行程度を取得して URL マッチする：

```
sheets_get_values(spreadsheetId="1_0317hOqbgGfcSZQ9D9-JlwgqvKxzQuRaw08U-5nw0c", range="自分の投稿一覧!A1:N50")
```

行数を増やしても URL が見つからない投稿は「未反映（同期遅延）」として除外し、見つからなかった件数も報告する。

数値の正規化：
- インプレッション・いいね・RT・ブクマ・エンゲ：カンマ区切り（例 `"8,719"`）を整数に変換
- URL マッチング：tweet ID（`status/` 以降の数字）で照合

---

# STEP 4: 比較対象（過去投稿）の取得

同じ HOW_ID の直近 2 週間分（=STEP 1 期間の開始日から 14 日前まで）を STEP 2・STEP 3 と同じ方法で取得する。

過去データは「比較用ベンチマーク」として高IMP/低IMP の閾値判定に使う。

---

# STEP 5: パターン分析

以下の観点で高IMP/低IMP の共通点を抽出する：

| 観点 | チェック内容 |
|---|---|
| フック構造 | 1行目に「具体的な数字」「日常の物」「読者の体験」が入っているか |
| 日常接続の位置 | 冒頭から接続しているか、末尾1文だけか |
| immediacy | 「いまこの瞬間も」「今日も」など現在進行形表現の有無 |
| 文字数 | 短すぎ／長すぎ |
| 画像 | 有無、画像種類（写真／図解） |
| テーマの距離感 | 読者の日常から近い／遠い |

出力フォーマット例：

```markdown
## 今週の投稿パフォーマンス

| 日付 | テーマ | IMP | いいね | RT | ブクマ |
|---|---|---|---|---|---|
| ... | ... | ... | ... | ... | ... |

## 過去比較（直近2週間）

| 日付 | テーマ | IMP |
|---|---|---|
| ... | ... | ... |

## 高IMP投稿の共通パターン

① （観点）— 投稿例（IMP値）
② ...

## 低IMP投稿の課題

① （観点）— 投稿例（IMP値）
② ...
```

---

# STEP 6: 改善提案の生成

STEP 1 のタイプから対応スキル・style ファイルを特定し、Read で読み込む。

既存ルールと分析結果のギャップを抽出し、具体的な修正案を以下の形式で提示する：

```markdown
## スキル改善提案

### 1. [ファイル名] [セクション名] の修正
**現状**: （該当箇所の引用）
**提案**: （修正内容）
**根拠**: （実データ：投稿名 + IMP）

### 2. ...
```

提案ごとに番号を振る。最大 5 件程度に絞る。

---

# STEP 7: ユーザー承認待ち

以下の形式でユーザーに確認：

```
上記の提案について、反映するものを選んでください：
- 番号で複数指定可（例: "1,3"）
- すべて反映する場合は "all"
- 不要なら "スキップ"
- 内容を修正したい場合は番号と修正内容を指定
```

**ユーザーの回答を待つ。承認なしには次に進まない。**

---

# STEP 8: 承認された修正の適用

承認された提案について、Edit ツールで該当ファイルを修正する。実データの数字（例: `ペトリコール 72,756 IMP`）を根拠として記載すること。

修正完了後、変更ファイル一覧を報告：

```
✅ 修正完了
  - .claude/skills/writer-xonepoint/SKILL.md（フック制約強化）
  - .claude/skills/daily-xonepoint/SKILL.md（ネタ補充条件追加）
```

---

承認された場合：

- 内容: STEP 5 の分析結果 + STEP 6 の提案 + STEP 8 の適用結果
