# note 導線 改善施策レジストリ

X / Threads から note 到達、購入までの導線をどう直すかの順位付きリスト。施策ごとに検証方法を実施前に固定し、週次の判定をここに積む。

## 運用ルール

- このファイルが施策定義・検証方法・判定履歴の**単一の正**。週次運用振り返り（`/reporter-weekly-ops` の「⑧ note 導線 施策の検証」）はここからの転記
- 状態は 未着手 → 実施中（実施日を記入）→ 判定済み（支持／反証）。途中で 中止／保留 にできる
- 判定条件は実施日より前に固定し、以後は変えない。変えたいときは新しい ID で登録し直す
- 比較の原則：生 IMP を期間をまたいで比べない。率と中央値で比べる。W001 は地力 IMP（直前 14 日の非 W001 親ポストの IMP 中央値）を併記する。転送サイトのビーコンと X アナリティクスのリンククリックは定義が違うので混ぜない（期間をまたぐ比較は X リンククリックを主、ビーコンを副）
- 週次更新：`scripts/note_funnel_measures.py` が施策ごとの数値を出し、`/reporter-weekly-ops` STEP 5.7 が判定して「判定履歴」に 1 行追記する。数値の推測はしない
- 順位・条件の見直しはよーんが行う。見直したら日付付きで注記する
- 週単位の指標で実施日を含む週は、実施日が土日ならその週を before、月火なら after、水〜金なら混在として除外する（2026-10-22。ヘルパー `split_weeks`）
- 拡散週（9/14・9/21・9/28 の週。娘の円周率の投稿で宇宙探査と無関係の客層が来た）は N1〜N3 の窓から外す（2026-10-22 よーん判断。ヘルパー `VIRAL_WEEKS`）。今後も同種の拡散があれば日付付きで追加する
- 順位表の「目的」「判定 KPI」列は施策の狙いと成功条件の要約（2026-10-22 追加。正は各施策の節の「比較方法・判定条件」）。ヘルパーは順位表を列位置で読むため、先頭 8 列の順序は変えない
- CVR は必ず価格付きで書く（例：CVR¥300 ＝ ¥300 で売っていた期間の 購入 ÷ 同期間の PV。`note価格履歴` の区間、`article_price_cvr.csv`）。価格をまたぐ累計 CVR は判定に使わない（2026-10-21）

## 段階の定義（共通）

| 段階 | 意味 | データ（CSV・列 / シート） |
|---|---|---|
| S1 露出 | 本体ポストの IMP、週の総インプ、Threads views | `funnel_posts` 本体IMP、`funnel_weekly` インプ |
| S2 プロフ | プロフアクセス（X のみ） | `funnel_weekly`（X bio）リンク到達 ＝ 日次記録「プロフ」の週合計 |
| S3 リンク到達 | note リンクを貼ったセルフリプの IMP / views | `funnel_posts` リンク到達 |
| S4 クリック | X リンククリック（主）、転送サイトのビーコン（副） | `funnel_posts` Xリンククリック・クリック、`click_detail` クリック |
| S5 記事到達 | note 側で数えた到達、記事 PV | `funnel_weekly` note到達、`note_referrers`、シート `note記事日次` PV |
| S6 購入 | 購入数、価格区間ごとの CVR¥ | `articles` 購入数、`article_price_cvr`（記事 × 価格区間の PV・購入・CVR¥）、シート `note購入記録`・`note価格履歴` |

CSV は `scripts/note_funnel_export.py` が発信記録シートから書き出す（ヘルパーが実行のたびに最新を作る）。

## note 記事の価格設定ルール（2026-10-22 よーん決定）

有料 note 記事の価格は、次のはしごで動かす。狙いは、記事自体を改稿して高い価格で売れるものにする挑戦を続けること。N6（同一価格での改稿効果の検証）とは方向が違い、N6 は保留のまま。価格の変更は `note価格履歴` に区間として残り、`article_price_cvr.csv` / `price_cvr_compare` で価格区間ごとの PV・購入数・売上/1,000 PV が出る（価格を上げる・戻す判断の材料。ダッシュボードの「価格別 CVR」の表と散布図で随時見る）。

1. 有料 note 記事は **¥100** から始める
2. その価格で **2 部以上購入 かつ 200 PV** に達したら価格を上げる
3. その価格で 200 PV に達しても **1 部以下**なら、有料記事の冒頭（無料部分）と有料ラインを見直し、さらに 200 PV 溜まるのを待つ
4. 上げた価格で 200 PV 溜まった時点の 売上/1,000 PV（CVR¥ × 価格）が前の価格を下回ったら、**価格を戻すか、記事をその価格で売れるものにブラッシュアップするかをその時に判断する**

注記：最初の 200 PV は公開投稿（W001）の温かい客が中心で CVR が高く出やすいが、今の時点では気にしない（2026-10-22 よーん判断）。

運用（自動。`scripts/note_article_daily.py`、毎朝 05:55）：
- 現在価格の区間（改稿日があればそこから）の PV と購入数を毎朝数え、200 PV に達した時点で規則 2〜4 のどれに当たるかを `note価格履歴` の「通知日」「通知内容」に記録し、よーんにメールする（【note価格】。同じ動作は 1 回だけ）
- 改稿は note の公開 API の本文ハッシュ（題名＋無料部分＋有料部分の文字数・画像数）で検知し、変わった日を「改稿日」に自動記録してメールで知らせる。誤字修正など軽微な変更で記録されたら改稿日を消す。有料部分だけの修正は検知できない
- 価格を変えると翌朝 `note価格履歴` に新しい区間が立つ（既存の自動更新）
- 判定は `scripts/note_price_rule.py` が正。ダッシュボード「価格別 CVR」の「次の動作」列（上げる／見直す／判断／あと nn PV）と、週次振り返り ⑨「note 価格のはしご」（通知済みで未対応の記事を毎週列挙）で状態を見る（2026-10-22）

2026-10-22 時点の当てはめ（`article_price_cvr`）：ニューホライズンズ ¥300 は 187 PV・1 部（200 PV で 1 部以下なら 3 へ）、赤い空（後編）¥490 は 233 PV・4 部（2 の条件を満たす）、ボイジャー再点火 ¥980 は 388 PV・0 部（¥490 の 売上/1,000 PV 3,500 円を下回り、4 の判断対象）、天王星 ¥390 41 PV・0 部、チャンドラセカール ¥200 16 PV・1 部、¥100 の 5 本はいずれも 200 PV 未満で待ち。
