### Claude *(11:14 JST)*

忘れない仕組みは「条件を満たした瞬間に知らせる」「未対応が残っていれば毎週思い出させる」「今の状態をいつでも見られる」の 3 層にすると確実です。データは全部そろっています（`note価格履歴` の区間、`note記事日次` の PV、`note購入記録` の価格付き購入）。

**1. 朝のメール通知（引き金）**
`note_article_daily.py` は毎朝 05:55 に価格と日別 PV を取っているので、その直後に各有料記事の現在価格の区間を規則と照合し、条件を満たした日に 1 回だけメールします。

| 条件 | 件名の例 |
|---|---|
| 200 PV かつ 2 部以上 | 【note価格】ニューホライズンズ ¥300 → 上げる |
| 200 PV かつ 1 部以下 | 【note価格】ニューホライズンズ ¥300 → 冒頭と有料ラインを見直す |
| 上げた価格で 200 PV、売上/1,000 PV が前の価格より低い | 【note価格】ボイジャー再点火 ¥980 → 戻すかブラッシュアップするか判断 |

二重通知を防ぐため `note価格履歴` に「通知日」列を足します。見直し後の「さらに 200 PV」を数えるには改稿日が要るので、「改稿日」列も足し、よーんが改稿したら日付を入れる運用にします（改稿日以降の PV で数え直す）。

**2. 週次振り返りで未対応を列挙（取りこぼし防止）**
日曜 20:00 の `/reporter-weekly-ops` に「⑨ note 価格のはしご」を足し、通知済みで価格も改稿日も変わっていない記事を「未対応」として毎週書きます。対応するまで消えません。

**3. ダッシュボードに「次の動作」列**
「価格別 CVR」の表に、記事ごとの現在区間の PV・購入数と「上げる / 見直す / 判断 / あと nn PV」を出します。開けば今の状態が分かります。

**変更の範囲**
- `scripts/note_article_daily.py`：規則の照合とメール送信（`send_gmail.sh`）、`note価格履歴` の通知日・改稿日列
- `.claude/skills/reporter-weekly-ops/SKILL.md`：⑨ の追加
- ダッシュボード v31：次の動作列
- `docs/plans/note_funnel_measures.md`：価格設定ルールの節に運用（通知と改稿日の記入）を追記

1 だけでも機能します。全部やるか、1 と 2 だけにするか、指示してください。
