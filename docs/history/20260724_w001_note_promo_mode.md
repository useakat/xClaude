## 「plan-xnote-funnel の設計制約を後追い適用する簡易版」とは

**背景**：X長文とnoteの分割で一番の失敗リスクは「本編で全部語りきってしまい、noteを読む動機が残らない」ことです（w001/plan.md の Risks にも明記）。

これを防ぐ仕組みとして、既に `/plan-xnote-funnel` スキルがあります。これは**記事を書く前（上流）**に、

- X長文でどこまで書くか（あえて出さない核）
- note の売り＝有料部分の payoff に何を温存するか
- セルフリプ文面

を対話で確定して `funnel-brief.md` に保存するものです。つまり「ネタバレ管理を事前に設計する」仕組みです。

**今回のケースの問題**：既に公開済みの note 記事は、多くが funnel-brief を作らずに書かれています（実在するのは kepler の1件だけ）。つまり「X長文にどこまで書いてよいか」の設計図が無い。

**そこで提案した簡易版**：モードB では、ブリーフを後から正式に作るのではなく、**制作時のルールとして**「記事正本を読んだら、課金壁以降の核心（オチ・payoff）を本編に書き切らない。X内で完結する一場面にフォーカスし、裏側は note に残す」を spec に1行入れる、という意味です。ブリーフ作成の工程を増やさず、同じ目的（売りの温存）だけを達成します。

## 「funnel-brief.md がある記事はモードC を使う」とは

kepler のように**ブリーフが既にある**記事なら、そこに「X長文の範囲」「セルフリプ確定文面」が既に書いてあるので、簡易ルールで判断するより、それを起点にする既存の**モードC**を使う方が正確、という交通整理です。

- ブリーフあり → モードC（設計図どおりに作る）
- ブリーフなし（大半の公開済み記事）→ モードB（簡易ルールでネタバレ管理しつつ作る）

この整理で進めてよいですか？あるいは「公開済み記事でも毎回ブリーフを簡易作成してから書く」方式（1工程増えるが設計が残る）に変えることもできます。

整理すると、ブリーフの中身は2種類に分けられます。

- **不変の制約（毎回守る）**：「note の売り／あえて出さない核」。何度販促しても課金壁以降をバラさない、という守りの情報。これは繰り返し使ってよい、むしろ使うべき。
- **可変の設計（毎回変える）**：どの場面・切り口で書くか（フォーカス）、フック、セルフリプ文面。これを固定すると同じ投稿が量産される。

つまり「ブリーフあり→設計図どおり」が間違いで、**ブリーフから継承するのは『出さない核』だけ、フォーカス以降は毎回新規に作る**のが正解です。幸い writer-xstory は「記事から引きの強い場面を3候補→選択」する構造なので、1本の記事から違う切り口を出す仕組みは既にあります。
