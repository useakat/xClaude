## 何が起きているか（応答の中身）

チャット応答はストリーミング形式で、**「長さ」＋「JSONチャンク」の繰り返し**です。Q1（詳細な単問）の実測:

```
RAW_CHARS  32,371,795   (32MB)
CHUNKS     76           (うち wrb.fr が 74)
```

チャンクを並べるとこうなっています（短い質問での実例）:

```
chunk1: len=      455  [["wrb.fr",null,"[[\"\",null,...     ← 回答まだ空
chunk3: len=  427,555  [["wrb.fr",null,"[[\"\",null,...
chunk6: len=  428,061  [["wrb.fr",null,"[[\"**1995\",...   ← 回答が育っていく
chunk9: len=  434,342  [["wrb.fr",null,"[[\"**1995年12月2日**です [1, 2]。\",...  ← 完成版
chunk10: len=      58  [["di",43450],["af.httprm",...]]
```

**各チャンクは「その時点までの回答全文＋引用メタ全部」のスナップショット**です。引用メタ（約430KB）が更新のたびに丸ごと再送されるため、74回の更新 = **同じ430KBが74回**送られて32MBになります。最終的に使うのは最後の1つだけです。

さらにローカルのパーサは全チャンクに対して `_parse_citations()` を回すので、32MB の入力が RSS 391MB に膨らみます。

## 案Aの中身

**修正場所**：Windows 側 `nbrpc_server.py` の `FETCH_JS`（ブラウザ内 JS）

```js
const t = await r.text();
return {status: r.status, text: trim(t)};   // ← ここで捨てる
```

`trim()` の規則:
1. 長さプレフィックス付きチャンク列に分解する
2. `"wrb.fr"` チャンクは**最後の2つだけ**残す
3. それ以外（`di` / `e` / `af.httprm` などの小さいチャンク）は残す
4. `UserDisplayableError` を含むチャンクは無条件で残す（レート制限エラーの検出用）
5. 長さプレフィックスを再計算して組み直す

**ブラウザの中で捨てる**のがポイントです。32MB の文字列はもともと Chrome の中にあるので、そこで削れば ssh を渡るのは 1MB 弱で済みます。

## 実測した効果（Q1 の実応答で検証済み）

| | 無加工 | トリム後 |
|---|---|---|
| 転送データ | 32,371,795 文字 | **994,830 文字（3.1% / 33分の1）** |
| 回答本文 | 2,219 文字 | **2,219 文字（同一）** |
| references | 32 件 | **32 件（保持）** |

回答も参照も完全に同じものが取れることを確認しました。5問まとめ（推定100MB超）でも 1〜3MB に収まり、OOM は起きなくなります。

## 「最後の2つだけ」で安全な理由

- 各チャンクが完全なスナップショットなので、最後のものが完成版
- パーサは「最も長い marked answer」を採用する実装なので、最後の2つを残せば従来と同じ結果になる（上表のとおり実測で一致）
- エラー応答は `item[2]` が null のチャンクに入るため、`UserDisplayableError` を含むチャンクを別途残せば取りこぼさない
- 長さプレフィックスの数値はパーサが読み飛ばすだけなので、再計算しても問題ない

## 注意点

**1. ローカルでトリムしても意味がない**（検証済み）
同じトリムをローカル側で試したところ、ピーク RSS は **518MB と逆に増えました**。32MB が ssh を渡って `json.loads` された後では手遅れだからです。**リモートで捨てる**ことが本質です。

**2. `nbrpc_server.py` が Git 管理外**
現在 Windows 側にしか存在しません。修正するなら `scripts/nbrpc_server.py` としてリポジトリに入れ、デプロイ手順を残すべきです。

**3. 適用範囲を限定する**
`list` / `deep-research` などの batchexecute 応答は形式が違うので、URL に `GenerateFreeFormStreamed` を含むとき（＝チャット）だけトリムする分岐にします。

**4. フォールバックを入れる**
Google が構造を変えるとトリムが壊れます。トリム後に wrb.fr チャンクが1つも残らなければ無加工で返す、という保険を付けます。

## さらに削る選択肢（案A2）
