この通知機能をほしいと言っている人がいるんだけど、その人はclaude はおろか、自分のPCすら持っていない。どうすればいいと思う？

### Claude *(19:51 JST)*

*[ツール: `Bash`]*

結論から言うと、**よーんのこのサーバーで代行して監視し、その人のメールに通知を送るのが現実的**です。相手に必要なのは X のユーザー名と通知先メールアドレスだけで、PC も Claude も要りません。

**なぜそれで済むか**
- 今の `x_imp_alert.py` は、よーんのアプリの Bearer トークン（app-only 認証）で `/2/users/{id}/tweets` を叩き、public_metrics のインプ数を読んでいます。相手にログインしてもらう必要がない仕組みです。
- 変更は「監視対象ユーザー ID と通知先メールをリスト化して回す」程度で、cron や通知の作りはそのまま流用できます。

**先に確認が必要な点が1つ**
- app-only 認証で**他人の投稿**のインプ数が返るかどうかです。自分の投稿では返っていますが、他人の投稿では 0 や欠損になる可能性があります。相手のユーザー ID で API を1回叩けば確認できます。返らなければ、相手に一度だけスマホのブラウザで X の OAuth 認可をしてもらう方式に変える必要があり、手間が一段増えます。

**その他の注意**
- 無料で代行し続けることになるので、サーバーが止まれば通知も止まる点は相手に伝えておくべきです。
- X API の呼び出し回数は1人追加なら余裕があります。ただ希望者が増えると Basic プランの上限や料金に当たるので、「数人まで」と線を引いておくのがよいと思います。
- 閾値（3時間・1,000インプ）はよーん基準なので、相手の規模に合わせて変える前提で設計した方がよいです。

よければ、まず相手のユーザー名で API の確認テストから進めます。

## よーん *(20:48 JST)*

僕の代行はだめだな。GASでなんとかするのがいいのかな？他のやりかたはある？

### Claude *(20:48 JST)*

*[ツール: `Bash`]*

GAS は選択肢として妥当です。ただ、どの方法を選んでも**本当の関門は実行環境ではなく X API の利用権**です。そこを先に押さえた上で、方法を並べます。

**前提：X Developer アカウントが必須**
- インプ数は X API でしか取れません。相手自身が developer.x.com でアプリを作り、Bearer トークンを発行する必要があります。これはスマホのブラウザだけで完結します。
- 投稿の読み取りには有料プラン（Basic、月200ドル前後）が必要になる可能性が高いです。Free プランは書き込み中心で、投稿一覧の読み取りはほぼ不可です。ここを相手が許容できるかが最初の分岐です。
- X 側がブロックされるなら、残念ながら他の方法でも代替できません。公式アプリに「インプ到達通知」はなく、ログイン必須のページをスマホで自動巡回するのも現実的ではありません。

**実行環境の候補（すべてスマホのブラウザだけで設定可能）**
1. **GAS（Google Apps Script）** — Google アカウントだけで動き、10分ごとの時間トリガーと Gmail 送信が標準で揃っています。無料枠で十分です。相手が Google ユーザーなら一番敷居が低いです。難点はスマホでのコード編集画面が使いにくいこと。
2. **val.town** — ブラウザ上で JS を書き、cron 実行とメール送信が標準機能です。GAS よりスマホ編集が快適で、無料枠あり。ただ国内では知名度が低く、相手に説明が要ります。
3. **Cloudflare Workers / GitHub Actions** — どちらも無料で定期実行できますが、メール送信に外部サービスの追加設定が要るので、相手の負担は増えます。

**おすすめ**
- 相手が X API の費用を許容できるなら、**GAS 一択**です。よーんの `x_imp_alert.py` をそのまま GAS に移植したコードを用意し、相手はトークンとメールアドレスを貼って保存、トリガーを1回設定するだけ、という形にできます。
- 相手が費用を許容できないなら、この機能自体が成立しないので、X のアナリティクス画面を自分で見てもらう以外にありません。

まず相手に「X API の有料プランを使えるか」を確認するのが先だと思います。使えるなら、GAS 版のコードはすぐ作れます。

## よーん *(20:51 JST)*

developer.x.com でアプリを作り、Bearer トークンを発行　ってめんどくさかったっけ？

### Claude *(20:51 JST)*

面倒ではありません。慣れていなければ10〜15分程度です。

**手順の実態**
1. developer.x.com に X アカウントでログインし、「Sign up for Free Account」を押す。
2. 利用目的を英語で250字ほど書く欄があります（審査ではなく、即時承認です）。ここが唯一の「書く作業」です。
3. 自動で Project と App が1つ作られるので、App の「Keys and tokens」を開いて Bearer Token を「Generate」する。表示は1回きりなので、その場でコピーして保存する。
4. インプ読み取りに Basic プランが必要なら、Developer Portal の「Products」からクレジットカードを登録してアップグレードする。

**スマホでの注意点**
- 画面が PC 向けのレイアウトなので、スマホのブラウザだと少し操作しづらいですが、完結はできます。
- 利用目的の文面は、よーんが定型文を渡してあげれば相手の負担はほぼゼロです。

つまり「アカウント作成とトークン発行」自体は軽く、相手にとって重いのは**Basic プランの月額料金**だけです。費用さえ了承してもらえれば、GAS の設定を含めても30分以内で動かせます。

- 状態保存はファイルではなくスクリプトプロパティ。

- API エラー（トークン無効、クレジット切れ等）は同じ内容なら1回だけメールで知らせる機能を追加しました。無人運用で止まったことに気づけるようにするためです。

## よーん *(22:13 JST)*

僕の bearer token はどのファイルを見たら書いてある？

### Claude *(22:14 JST)*

リポジトリ直下の `.env` に `X_BEARER_TOKEN=...` として書いてあります（`x_imp_alert.py` と `post_to_x.py` が読んでいるのと同じファイルです）。

値そのものを確認するなら、ターミナルで次を実行してください。

```
grep X_BEARER_TOKEN /root/xClaude/.env
```

`.env` は gitignore 対象なので GitHub には上がっていません。GAS 版を自分のアカウントで試す場合は、この値を CONFIG の `X_BEARER_TOKEN` に貼ればそのまま動きます。

## よーん *(22:34 JST)*

似たような機能を提供しているサービスってある？

### Claude *(22:34 JST)*

*[ツール: `WebSearch`, `WebSearch`, `WebSearch`, `WebSearch`]*

「インプ数の閾値でメール通知」そのものを提供する既製サービスは見つかりませんでした。ただ、**近い機能**ならいくつかあります。

**いちばん近いもの：Hypefury / Tweet Hunter / Typefully の「オートプラグ」**
- 自分の投稿が「いいね◯件」などの閾値に達すると、自動でセルフリプ（商品リンクや note 導線）を付ける機能です。
- 通知ではなく「自動で行動する」仕組みですが、よーんが通知を欲しがった理由（伸びた投稿に早く導線を付ける）はこれで直接満たせます。
- 閾値は「いいね・リポスト・リプライ数」で、インプ数ではありません。X の投稿にログイン連携するだけで、API 登録やクレジット購入は不要です。
- 料金は月 $20〜50 程度のサブスク。スマホのブラウザから設定できます。

**通知系（用途が少しずれる）**
- Fedica の Post Alerts は「指定キーワードを含む投稿」をメールで知らせる機能で、自分の投稿の伸びを見る用途ではありません。
- Sprout Social / Meltwater / Talkwalker は企業向けで、エンゲージメントの異常検知アラートはありますが月数万円以上です。

**日本の SocialDog**
- 予約投稿と分析が中心で、閾値通知の機能は確認できませんでした。

**まとめ**
- 「通知が欲しい人」の本当の目的が「伸びたら自分で何かしたい」なら、Hypefury 系のオートプラグが設定も費用も一番軽いです。
- 「数字をメールで受け取ること自体」が目的なら、既製品はなく、今回作った GAS 版が現実的な選択肢になります。
