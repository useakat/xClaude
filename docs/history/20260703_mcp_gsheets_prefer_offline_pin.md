**結論：設定・認証・env処理はすべて正常。原因は起動コマンドの `@latest` です。**

`scripts/mcp_gsheets_launch.sh` の最終行 `npx -y mcp-gsheets@latest` が、reconnect のたびに npm レジストリへ問い合わせに行き、レジストリが一時的に到達不能だと **60秒フルにハング**します（実測）。これで Claude Code の初期化がタイムアウトし `-32000` になります。ネットワーク正常時は1.7秒で動くため間欠的に見えます。

`npx --prefer-offline -y mcp-gsheets@1.8.1` に変えると、レジストリ遮断下でも1.45秒でキャッシュ起動することを検証済みです。

*[ツール: `ToolSearch`, `ExitPlanMode`]*

修正します。

*[ツール: `Edit`]*

検証します（通常起動 + レジストリ遮断下の起動）。

*[ツール: `Bash`]*

修正・検証が完了しました。

**修正内容**（`scripts/mcp_gsheets_launch.sh` 最終行）：
```bash
exec npx --prefer-offline -y mcp-gsheets@1.8.1
```

**検証結果**：
- 通常起動：1.29秒で正常 ✅
- **レジストリ遮断下（-32000 の再現条件）：1.28秒で起動** ✅（従来は60秒ハングして失敗）

これで再接続時のハングがなくなり、`-32000 / Failed to reconnect` は解消されます。反映には Claude Code の再起動（または `/mcp` での再接続）が必要です。

なお現在このセッションの mcp-gsheets 接続は失敗表示のままなので、次回起動時に効きます。
