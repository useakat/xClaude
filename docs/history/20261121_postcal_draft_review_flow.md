## よーん *(21:48 JST)*

投稿文を作成した際に、投稿文を登録するんだけど、このルーチンは自動化対応してるので、僕が本文の確認をする前に予約登録されてしまう。予約登録は僕の確認後にされるようにしたいので、登録はするけど、投稿予約まではされていない状態というのがあるといい気がする。それを予約投稿サイトで僕が確認して、必要な修正を行った後に、「投稿予約」ボタンを押すと予約投稿状態になる。どう思う？

### Claude *(21:48 JST)*

良い案だと思います。今の仕組みでは、確認前の本文が自動投稿される経路が実際にあります。

- 今の流れ: push → 10分ごとの `postcal_import.py` が直近の空き枠に `queued` で登録 → cron が投稿する。
- この間によーんの確認が入る保証がありません。

**提案する形**
- 取り込み時は新しい状態（`draft`）で登録し、枠は割り当てません。cron は `queued` だけを拾います。
- カレンダーの画面で本文を確認・修正し、「投稿予約」ボタンで `queued` にします。

**設計で気をつけたい点**
1. **枠の割り当てはボタンを押した時点にします。** 取り込み時に割り当てると、確認が遅れた間に枠の時刻が過ぎます。下書きが複数あるときも、枠の取り合いが起きません。
2. **画面での修正を正にします。** 同じ uid を再 push したとき、取り込みが画面の修正を上書きしてはいけません。再 push で更新してよいのは「画面で未編集の draft」だけにするのが安全です。spec.md の「同じ uid を上書き更新」ルールの書き換えも必要です。
3. **放置された下書きの扱い。** 溜まっても害はありませんが、「未承認の下書きが N 件」と画面で分かるようにしておくと、予約し忘れに気づけます。

**今回の分について**
- 先ほど push した予約ファイル（uid=ae6b1374…）は、10分以内に取り込まれ、直近の空き枠に `queued` で登録されます。
- 修正したい場合は、`post.usephys.net` で確認して編集か削除をお願いします。仕組みを変えるまでは、この状態で入ります。

**実装の範囲**
- `scripts/postcal_import.py` と postcal 側（状態の追加、ボタン、cron の絞り込み）の変更、VPS への配備が必要です。
- 加えて、`spec.md` の STEP 6 と Verification の修正も必要です。
- スクリプトの編集は事前確認が必要なルールなので、まだ着手していません。進めてよければ、まず postcal 側のコードの場所を教えてください（このリポジトリの `scripts/` にあるものだけで足りるかが分かりません）。
