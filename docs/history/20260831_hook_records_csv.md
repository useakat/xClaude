## 提案：`logs/z01_hooks.csv` に制作フローから自動追記

**推奨案**: z01 の spec.md に1ステップ追加し、Gmail 下書き作成の直後に repo 内の CSV へ1行追記させる。

```csv
作成日,フック型,冒頭15字,ソース
2026-08-31,口火型,火星の機械は誰も直しに,noteNeta[12]
```

理由は3つです：

1. **人の記憶に頼らない**。3週連続未達の原因は「投稿時によーんがメモする」設計だったこと。z01 は Claude セッションが spec.md どおりに作るので、spec に書けば必ず実行されます。しかも型の判定は既にフロー内でやっているので、追加コストはほぼゼロ。
2. **ops-weekly がそのまま読める**。振り返りは repo ファイルを Read するだけで済み、Sheets の列追加やスクリプト改修（cron の post_from_email.sh に手を入れる案）が不要。ツイート URL は作成時点で存在しないため、突合は「冒頭15字」で X投稿一覧の本文と照合します（週次集計で機械照合可能なことは確認済み）。
3. **消化確認が git で検証できる**。CSV への追記はコミットに乗るので、来週の③消化確認で「やったか」を痕跡で判定できます。

検討して外した案：outputs シートに列追加（記入者が cron スクリプトになり、フック型を知らないため要スクリプト改修）、Gmail 下書きから事後回収（下書きは投稿後の扱いが不定で恒久記録に不向き）。

進めてよければ、`projects/z01/spec.md` への1ステップ追記と `logs/z01_hooks.csv` のヘッダ作成を行います。あわせて W003/W001 も同じ CSV に記録対象を広げるかだけ判断ください（週次の型別比較は本数が多いほど早く効きます）。
