## skill への修正提案

修正対象は `style/style-xonepoint.md`（writer-xonepoint が参照）。

### ① 文字数ルールを強制化（最大の差分原因）
現状「推奨200〜260字、最大300字」だが守られていない。**出力前の自己チェック手順**を追加：

> 本文を生成したら必ず字数カウントし、260字を超えていたら "削る対象優先度リスト"（後述）に従って削る。再カウントし260字以内になるまで繰り返す。

### ② 「削る対象優先度リスト」を新設
削るときの優先順位を明示：

1. 専門用語の言い換え注釈（「〇〇の重い兄弟」「正確には〜」括弧注）
2. 中間メカニズムの細部（「パイオンが崩壊して」など本筋に不要な機構説明）
3. 補強的な数値（同じ事実を別の単位で言い直すもの。例：22μs と 10倍 は片方で十分）
4. 理論・学者の名前（現象が伝わるなら名前は出さない）

### ③ 数値ルールの上書き
style §1軸4 と §4 が矛盾気味。**「冒頭の直感比較数字1つ + 本文中は最大1〜2個」** に上限を明記。「2.2マイクロ秒」のような専門単位は **使うなら分数化する（45万分の1秒）** を例示。

### ④ 構成テンプレ「問答リズム」を追加
writer-xonepoint SKILL.md の「4段構成」に下記サブパターンを追加：

> 仕組み段は **「問い1行 → 端的な答え1行 → 短い説明」** のリズムを推奨。
> 例：「では、なぜ届くのか？／鍵は『時間の遅れ』。／地上から見ると…」

### ⑤ 締めルールの拡張
現 §「日常接続必須」だけだと数値締めが許容される余地がある。**「数値締め禁止」を明記**し、許容する締め形を3型に整理：
- A: 日常接続型（既存）
- B: 詩的余韻型（「時間の不思議を秘めた…」のように現象を擬人化して閉じる）
- C: 問いかけ余韻型

### ⑥ writer-xonepoint SKILL.md の「冒頭1行例」を差し替え
現状「皮膚1cm²あたり毎秒650億個」のような **濃い数値型** が例示の主流で、AIがそれを真似ている。「45万分の1秒の粒子が、今日も僕らを貫いている」のような **分数・体接続型** を1番目の例に置く。


修正を実装するか、まずは ① と ② だけ先行で入れるか、どう進めますか？
