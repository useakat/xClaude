## 2. 「プロフアクセス × 固定ポスト閲覧率」の閲覧率は出せません
X アナリティクスが出すのは固定ポストの IMP とリンククリック数だけで、その IMP が「プロフィールを開いて見た人」か「タイムラインで流れてきた人」かは区別されません。なので閲覧率という中間指標は作れません。経路2 は分解せず、**固定ポストのリンククリック数（CSV の実測値）**をそのまま使うのが正解です。中間の率は、ボトルネック探しに必要になったときだけ考えれば足ります。

## 3. 「Threads はプロフと投稿を分けられない」の意味
note 側に届く情報は「`l.threads.com` から来た」という参照元のドメインだけで、プロフィールの bio リンクを押したのか、投稿の中のリンクを押したのかは note には分かりません。X なら投稿側のリンククリック数が CSV で取れるので引き算できますが、**Threads の insights API は投稿ごとの views・いいね・リプ・リポスト・引用・シェアしか返さず、リンククリック数が無い**ため、投稿側からも引けません。結果として、Threads の 48 件は「プロフ＋投稿の合計」としてしか扱えない、という意味です。

分けたいなら、着地点を変えるしかありません（プロフの bio リンクは投稿で一度も貼らないページにする、など）。ただ月48件なので、まずは合計で見れば十分だと思います。

## 4. 引き算で他人の引用RT・リポスト経由も引くべきか：ご指摘のとおりです
正確には引けません。内訳は次の通りです。

- **他人のリポスト**経由のクリック：元投稿（自分のセルフリプ）のリンククリックとして X アナリティクスに計上されるので、**CSV の数に含まれていて、引き算で消えます**

## ルールの全体
月ごとに、次の数字を使います。

| 記号 | 意味 | 出どころ |
|---|---|---|
| D | 直接・不明 | note流入元 |
| X, N, T | X列・note.com列・Threads列 | note流入元 |
| C | 自分の note リンク投稿の X クリック | X投稿一覧（noteURL 列あり行の AB 合計） |
| B | ベース（メール・ブックマーク等） | 固定 20／月（X も Threads も無かった 2025年9〜12月の直接・不明の水準） |

### 手順
1. **配る量を決める**：P ＝ D − B（ベース分は「その他」として先に除く）
2. **比率で配る**：X, N, T の見えている数の比で P を分ける
   - X への配分 sX ＝ P × X ÷ (X＋N＋T)、note・Threads も同様
3. **X だけ上限で頭打ち**：X の隠れ分は「クリックしたのに X列に出なかった数」より多くはなりえないので、上限 capX ＝ C − X とする
   - sX ≦ capX なら、そのまま
   - sX ＞ capX なら、sX ＝ capX にして、**はみ出した分を note と Threads に N : T の比で回す**
4. **推定値**：X 経由 ＝ X＋sX、note 経由 ＝ N＋sN、Threads 経由 ＝ T＋sT、その他 ＝ B

### 9月で計算すると
- D 235、B 20 → P ＝ 215
- X 447、N 164、T 48（合計 659）
- 比率配分：sX ＝ 215 × 447/659 ＝ **146**、sN ＝ 215 × 164/659 ＝ **53**、sT ＝ 215 × 48/659 ＝ **16**
- X の上限：capX ＝ 603 − 447 ＝ 156。sX 146 ≦ 156 なので頭打ちは発生せず
- 推定：**X 593、note 217、Threads 64、その他 20**（合計 894 ＝ X＋N＋T＋D ＝ 659＋235 ✓）

7月なら D 259 → P 239、X 948・N 149・T 0 → sX 207・sN 32・sT 0、capX ＝ 1,270 − 948 ＝ 322 で頭打ちなし → **X 1,155、note 181、Threads 0、その他 20**。

### 頭打ちが効くのはどんな月か
X の見えている数が大きいのに、X クリックとの差が小さい月です。たとえば8月は X 123・C 135 で capX ＝ 12。もし比率配分で X に 60 配られたら、12 で止めて残り 48 を note と Threads に回します。「X アプリで参照元が落ちた分は、クリック総数を超えられない」という実測の制約を、唯一の歯止めとして入れている、という意味です。

### 例外の扱い
- **C が無い月**（CSV 未取込）：上限なしで比率配分だけ行い、その旨を注記
- **C ＜ X の月**（3月のように X 側の記録が欠けている月）：上限が負になるので配分せず「検証不能」と表示
- B は固定なので、note フォロワーが増えて通知メール経由が増えたら見直す

### この方法の限界
比率配分の部分（手順2）は「見えている数に比例して隠れている」という仮定で、note アプリと Threads の実態は検証できていません。確かなのは手順3の上限だけです。10月以降、Threads に note リンクを置かなくなった結果 Threads列と直接・不明がどう動くかで、仮定の妥当性を後から確認します。

この内容でよければ `--reconcile` に実装します。
