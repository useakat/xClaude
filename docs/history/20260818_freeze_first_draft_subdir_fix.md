## 最初から最終稿に近づけるための提案

**1. フック候補に「回収コスト」を添える（差分A対策・効果最大）**
比喩・問いかけ型のフック候補には「この問いの答えを本文で書くのに何字必要か／正確に書くには何の説明が要るか」を1行添えて提示する。今回の平衡感覚フックは、回収に医学的正確性（感覚統合・再重みづけ）が要求される高コスト案だったが、選定時にはそれが見えていなかった。**回収コストが字数予算の1割を超える候補は、その旨を明記して提示する**。→ `writer-xstory` ステージ2に追記

**2. カギ括弧付きの「セリフ・合言葉」は一次ソースの現物確認を必須にする（差分B対策）**
「」で括った発言・合言葉・スローガンは、当事者の発言として実在する表現のみ使う。要約・翻案から演出として作らない。→ `writer-xstory` か `story-check.md` に追加

**3. 執筆前に「時系列表」を固定する（差分C対策）**
W003 には「原典の代表値・極値・測定条件を表にしてから書く」ルールが既にある。W001 モードBにも**「事故・故障・復旧の日付と順序を表にし、初稿前に notebook で確認する」**を追加する。今回の時系列誤りは、書く前に表を作っていれば防げた。→ `spec.md` 手順5に追記

**4. 双方向の機構説明には往路・復路それぞれに理由を書く（差分D対策）**
「AするとBが動く。逆にBが動くとAが変わる」型の説明では、**往路と復路それぞれに理由を1文**つける。「逆に」「つまり」だけで物理を渡らない。読者役が3ループ詰まった原因はこれ一点だった。→ `story-check.md` に8項目目として追加（W001/W002/Z01 共通で効く）

**5. Z01 の固有名詞ルールを W001 に移植する（差分E対策）**
Z01 brand.md には「物語の登場人物となる固有名詞は初出時の一言補足付きで実名を使ってよい（記号的な型番のみ言い換え）」というルールが既にあり、今回のよーんの編集はまさにこれだった。→ W001 `brand.md` の採点基準・項目2に同じ例外を追記

**6. 期間・日数には起点を必ず添える（差分F対策）**
「40日後」「3日後」のような相対時間は、直前の文と起点が一致している場合を除き起点を明示する。→ `story-check.md`【時系列】項目に追記

**7. プロセス面：読者チェックが3ループで収束しないときは「構成の変更」を提案する**
今回、同じ構成のまま磨き続けて4ループ消費し、よーんの「作り直そう」の一言でピボットした後は2ループで完成した。check-reader の上限3ループに達したら、**微修正の継続ではなく「フック・構成レベルの変更案」をユーザーに提示する**選択肢を spec に明記する。

## 発見したバグ：初稿凍結 hook が動いていなかった

まさにこの分析のために作った `first-draft.md` 凍結が、今回働いていませんでした。原因は特定済みです。

hook のコマンドが `$CLAUDE_PROJECT_DIR/scripts/freeze_first_draft.sh` を指していますが、このセッションは作業ディレクトリが `projects/w001/` のため、`$CLAUDE_PROJECT_DIR` がリポジトリルートではなく **`projects/w001` を指し、スクリプトのパスが存在せず `|| true` で無音で握り潰されていました**。サブディレクトリから起動したセッション全てで凍結が死んでいます（リポジトリルート起動のセッションでは動作）。

修正案：settings.json の hook コマンドを `bash "$(git -C "$CLAUDE_PROJECT_DIR" rev-parse --show-toplevel)/scripts/freeze_first_draft.sh"` に変える（3箇所）。
