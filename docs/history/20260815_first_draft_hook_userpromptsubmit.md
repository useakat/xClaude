`first-draft.md` 凍結の仕組みと、今回それが効かなかった理由を整理します。

## 仕組み（`scripts/freeze_first_draft.sh`）

2段階のフックで動きます。

1. **PostToolUse（Write/Edit のたび）** — 書き込み先パスが `projects/w00{1,2,3}/*/draft/draft.md` に一致すれば、リポジトリ共通の記録簿 `.claude/.draft-touched` にそのパスを1行追記する（**パスだけ**で、内容のスナップショットは取らない）
2. **Stop（ターン終了のたび）** — 記録簿にあるパスを順に見て、`first-draft.md` がまだ無ければ、**その時点の** `draft.md` をコピーして `first-draft.md` を作る。既にあれば何もしない（＝最初の1回だけが「初稿」）。処理後、記録簿は空にする

つまり「初稿として固定される内容」は、**Write した瞬間ではなく、次に Stop が正常に発火した瞬間の中身**です。

## 確認した事実

- `20260812_オポチュニティ販促/draft/draft.md` は、このセッション中に **Write 1回＋Edit 1回＋Write 7回**（計9回）更新されていた
- それでも `draft/first-draft.md` は一度も作られていない（フォルダに存在しない）
- 記録簿 `.claude/.draft-touched` は現在0バイト（今回のターンの Stop で空にされたもの。過去の履歴は残らない）
- このセッションのトランスクリプトに、フックの成功メッセージ「✓ 初稿を凍結: …」が**実行結果として出力された痕跡が無い**（見つかった1件はスクリプトのソースコードを Read した際の引用で、実行ログではない）

## 推定される原因

パスのマッチングやファイル書き込み権限自体は手元で再現テストして問題なし（`case` パターンも日本語フォルダ名を含めて正しくマッチする）でした。したがって考えられるのは、

- **Stop フックが一度も「正常発火」しなかった** — このセッション中に少なくとも1回、ユーザーによる明示的な中断（`[Request interrupted by user]`）が発生しています。中断されたターンでは Stop フックが呼ばれない、または呼ばれても記録簿の処理が完了する前に途切れる可能性がある
- 記録簿 `.claude/.draft-touched` は **リポジトリ共通の1ファイル**（w001/w002/w003 兼用）なので、他プロジェクトの draft.md 操作と時系列が絡むと、狙った内容のタイミングでコピーされない余地がある（今回はそこまでは確認できていません）

正直なところ、**hook の実行ログが残っていないため、上記より先の断定はできません**。「9回の書き込みのどこかで Stop が一度も走らなかった」というのが最も辻褄が合う説明ですが、確証は取れていません。

## 影響

実害としては、`first-draft.md` が無いため「初稿→最終稿の差分から学ぶ」という本来の目的（`brand.md`/`spec.md` への反映）がこの記事ではできなかった、という点だけです。最終稿・note記事本体には影響ありません。直前の回答で示した「初稿」はトランスクリプトから手動で復元したものです。

必要であれば、フックに実行ログ（成否をファイルに記録する程度の追記）を足す対応もできますが、`.sh` の編集にあたるので、対応する場合は着手前に確認します。

## 現状の弱点

いまは「Stop（ターン終了）＝ユーザーに提示した瞬間」とみなして凍結しています。ただし Stop フックは、**ターンが中断されると発火しません**。今回の w001 のケースのように、途中で `[Request interrupted by user]` が挟まると、記録簿にパスは残っているのに、それを消化する Stop が一度も来ないまま終わってしまう可能性があります。

## 提案：UserPromptSubmit を追加する

「僕が原稿を確認するタイミング」を技術的に一番確実に捉えられるのは、**次によーんがメッセージを送った瞬間**（`UserPromptSubmit` フック）です。これは、

- 中断があっても・なくても、よーんが次に何か発言すれば必ず発火する（Stop と違って取りこぼさない）
- 「提示された内容を読んでから返信する」という会話の構造上、この時点では確実に提示済みの内容を読んだ後になっている

`freeze_first_draft.sh` の凍結ロジック（引数なしモード）はそのまま使えるので、**スクリプトの中身は変更不要**です。`.claude/settings.json` に以下を追加するだけです（Stop は保険として残す）。

```json
"UserPromptSubmit": [
  {
    "hooks": [
      { "type": "command", "command": "bash \"$CLAUDE_PROJECT_DIR/scripts/freeze_first_draft.sh\" || true" }
    ]
  }
]
```

- Stop が正常に発火すればそこで凍結（今まで通り、いちばん早いタイミング）
- 中断などで Stop が飛ばされても、よーんが次の発言をした時点で確実に回収・凍結される

スクリプト本体は変えず、`settings.json` への追記とスクリプト冒頭コメントの更新（トリガーが2つになった旨）だけです。この対応を進めてよいですか。
