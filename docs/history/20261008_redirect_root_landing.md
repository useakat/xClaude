## よーん *(22:54 JST)*

usephys.net/ 直下を自動転送しない　とはどういうこと？

### Claude *(22:55 JST)*

今の仕組みはこうなっています。

- `usephys.net/note` … bio に貼っている URL。転送ページが開き、ビーコン（クリック1件）を送ってから note のボイジャー記事へ飛ぶ
- `usephys.net/` … パス無しのホスト直下。ここも同じ転送ページが開き、ビーコンのキーが `_root` になるだけで、**note へは同じように飛ぶ**

bio のリンクはパス付きなので、人が `usephys.net/` 直下に来ることは基本ありません。来るのは、証明書の透明性ログでホスト名を知ったスキャナです（1日 100〜200 件）。その一部は JS を実行するので、転送ページの `location.replace()` を実行して note まで到達し、参照元 `usephys.net` 付きの PV として note に数えられます。これが note 流入元の「X bio 9」やボイジャー記事 PV の半分の正体です。

クリック数の方は「`_root` は数えない」ルールで 10/4 に除外済みですが、note へ飛ばす動作自体は残っているので、note 側の数字だけが汚れ続けています。

「直下を自動転送しない」は、`usephys.net/` に来たときは note へ飛ばさず、リンク一覧を載せた簡単な案内ページ（note・X・Threads へのリンク）を表示するだけにする、という変更です。パス付き（`/note`、`xpost.usephys.net/<記事ID>/...`）の動作は変わりません。

効果と副作用：
- スキャナが note に到達しなくなるので、note 流入元の usephys.net 系の列と記事 PV から偽の到達が消える
- 失うものは「URL を手打ちで `usephys.net` とだけ入れた人が自動で note に行く」動作だけ。bio の表示は `usephys.net/note` なので実害はほぼ無く、案内ページにリンクがあれば辿れます
- 対象は `usephys.net` と `threads.usephys.net`（bio 用）。`xpost` / `tpost` の直下も同じ扱いにできます

変更箇所は `redirect/redirects.json` の各ホストの `target` と、`scripts/redirect_build.py` が直下用に案内ページを出す分岐の追加、それと `--apply` での Caddy 反映です。やる場合はご指示ください。
