## 実現可能性（確認済み）
- **インプ取得**：X API `GET /2/users/:id/tweets`（`public_metrics.impression_count`）が現在の bearer token で取得可能。レート上限は 10,000 回/15分 なので、10分おきのポーリングでも余裕です
- **メール送信**：既存の `scripts/send_gmail.sh`（gws 経由）がそのまま使えます
- **定時実行**：VPS の cron に追加するだけ

## 設計案
**新規スクリプト 2本 ＋ cron 1行**

1. `scripts/x_imp_alert.py`
   - 直近の自分の投稿（RT除外・リプライ除外）を取得
   - **投稿から3時間以内**かつ **インプ ≥ 1,000** で、まだ通知していない投稿があればメール送信
   - 通知済み ID を `logs/x_imp_alert_state.json` に保存（二重通知防止）、実行ログは `logs/x_imp_alert.log`
   - メール内容：投稿URL・投稿時刻・経過時間・現在のインプ／いいね／RT／リプ／ブクマ・本文冒頭
2. `scripts/run_x_imp_alert.sh`（ログ・多重起動防止のラッパー、既存 cron と同じ作法）
3. cron：`*/10 * * * *`（10分おき。閾値到達から最大10分遅れで通知）

**しきい値・時間窓はスクリプト先頭の定数**にして変更できるようにします（デフォルト 1,000 インプ／3時間）。

## 決めておきたい既定値（このまま進めてよければ返事だけで結構です）
- 通知先：useakat@gmail.com
- 対象：オリジナル投稿のみ（セルフリプ・引用RTは除外）
- 追加オプション：**3時間経過時点の最終値も1通送る**（「3時間で何インプだったか」が毎回残るので、フックの検証に使えます）。不要なら外します
- 参考：現状の1投稿あたりインプ中央値は最終値で 1,356 なので、「3時間で1,000」は伸びている投稿の早期検知としてちょうどよい水準です

スクリプトの新規作成になるため、この設計で作ってよいか確認をお願いします。

## 検証結果
- dry-run で API 取得・対象判定・メール本文の書式を確認（件名例：`【Xインプ通知】投稿から3時間16分で450インプ到達`、本文は URL・種類・投稿時刻・経過時間・インプ／いいね／RT／引用／リプ／ブクマ・本文冒頭100字）
