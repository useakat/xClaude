## 2. 反応が良かった要因

既存ルール（口火型フック・1行の転換合図・合いの手・抽象化した締め）はこの投稿も当然満たしています。それだけでは他の4本と差がつかないので、**この投稿だけにある要素**を挙げます。

**① 1行段落の密度が突出している。** 15字以下の1行段落が 10個あります。他の高反応投稿は 0〜3個、直近の投稿も 2〜3個です。平均段落長も 31字で最短です（他は 36〜53字）。「その瞬間、信号ロスト。」「——1時間半後。」「ゼロからの復旧。残り3日。」「使命はたった一つ。」のように、**山場では描写をやめて短行を畳みかける**構成になっていて、スマホで読んだときの速度感が違います。

**② 「締切つきの危機」である。** 他の高反応投稿は 15年・37年・175年という長い時間軸の執念の話です。この投稿だけ「残り3日」という締切があり、7月4日→1時間半後→3日→7月7日と時刻が進む。読者は「間に合うのか」を追って最後まで読む。詳細表示率が高いのはこの構造が効いています。

**③ 危機の原因が読者の職場と同じ。** 「準備作業が重なって CPU が限界を超えた」「休暇中に全員が駆けつけた」「寝食を削って3日で完遂」は、宇宙の話でありながら、過労・納期・優先順位という読者自身の経験に直結します。W001 の中でいちばん自分事に近い題材でした。

**④ 教訓が「粘れ」ではなく「捨てろ」。** 他の投稿の締めは「あきらめない執念」に収束します。この投稿は「30件の観測を全部捨てた」という代償を具体的な数で示し、「何を捨てて何を守るかを決められる静かな強さ」で締めています。執念シリーズの中で**直感を裏切る教訓**で、しかも明日から使える判断原則になっている。ブクマ率が最高なのはここです。ハッシュタグの「#守るために捨てる勇気」も教訓を1語にしていて、共有時のラベルになっています。

**⑤ セルフリプが「同じ話の続き」だった。** リンク先は同じニューホライズンズの note 記事で、文面も「note でもさらに詳しく書いています」のひと言だけです。比較すると傾向がはっきり出ます。

## 4. 今後の X 長文作成への活かし方

既存ルールを壊さず、**上乗せする候補**として整理しました。採用するなら `projects/w001/brand.md` の「高反応投稿の型」と `spec.md` に反映します。

1. **山場は1行段落を連打する（構成ルール）。** 危機発生から復旧開始までの区間は、1段落1情報・15字以下の行を 5個以上置く。描写を積む前半と、短行で畳みかける山場の「速度差」を意図的に作る。現状の採点基準には段落の長さを見る項目が無いので、項目として追加できます。
2. **フォーカス選定で「締切」のある場面を優先する。** フォーカス3候補を出す工程で、「残り◯日」「あと◯時間」と書ける場面があればそれを第1候補にする。長期スパンの執念話でも、中に締切つきの局面（打ち上げ窓・通信窓・電力切れ）があれば、そこを切り出す。
3. **危機の原因は読者の仕事に翻訳できるものを選ぶ。** 「過労」「納期」「準備のしすぎ」「休暇中の招集」のように、読者が自分の職場に置き換えられる原因を持つ題材を優先する。候補出しの段階で「読者の生活のどこに当たるか」を1行書かせる（hook_records の「自分事」欄を候補選定の判定に前倒しする形です）。
4. **締めの教訓は「執念」の一本調子にしない。** 「捨てる」「待つ」「頼る」「引き返す」など、執念の中身を具体的な判断行動に落とす。そのとき**代償を数で書く**（30件を捨てた、◯日分を諦めた）。教訓が判断原則の形になっていると保存されます。
5. **セルフリプは必ず同じ題材の深掘りにする（データで確定）。** 別題材の販促を本体直下に置かない。文面は1文で十分で、長い宣伝文はむしろ下がっています。これは spec のモードB/C ではすでにそうなっていますが、モードA（note 未作成）のときも、後日 note を書いたらその記事でリプを追加する運用にすると回収できます。
6. **Threads 転載は「転換の合図」で分割する。** 500字で機械的に切るのではなく、「ここからが熱すぎる。」「ただし、代償があった。」のような合図の直後で1投稿目を終える。X で IMP 10万超の W001 は 9本あり、まだ転載していないものから順に出せば、Threads のフォロワーを伸ばす再現性のある手段になります（threads_draft のセルフリプ1件制約の緩和はスクリプト修正になるので、やるなら別途確認します）。

一点だけ注意です。この投稿の本文は 798字（タグ除く）で、現在の spec の「約600字・500〜700字」より長い。IMP 20万超の5本は 657〜912字で、600字以内は1本もありません。3月は全体のインプが高かった時期なので字数だけが原因とは言えませんが、「山場に1行段落を10個置く」余地は 600字だと作りにくいので、ルール1を入れるなら字数上限の見直しとセットで考える必要があります。

## 2. 「threads_draft のセルフリプ1件制約」とは

Threads 転載は2本のスクリプトで動いています。

- `make_threads_draft.py` が X投稿一覧から未転載の投稿を選び、その投稿にぶら下がるセルフリプのうち**時刻が最も早い1件だけ**を Gmail 下書きの［リプ］に入れます。ログに「セルフリプが2件。先頭1件のみ取り込みます(v1 制約)」と出ていたのがこれです。今回は note リンク（07:24）が SF小説（07:26）より先だったので、たまたま note リンクが転載されました。順序が逆の投稿では note 導線が Threads に載りません。
- `post_threads.py` が本文を500字以内に**段落境界で自動分割**します。今回「ここからが熱すぎる。」で切れたのは偶然です。

つまりルール6「合図の直後で切る」を毎回成立させるには、`post_threads.py` に分割位置を明示するマーカー（例えば単独行の `=====`）を受け付ける修正が要ります。あわせて `make_threads_draft.py` も「note リンクを含むリプを優先する」よう直すと、導線の取りこぼしが消えます。どちらもスクリプト編集なので、やってよければ指示をください。

## 分割マーカーは誰がつけるか

**`make_threads_draft.py` が自動でつけます。** 人が毎回つける運用にはしていません。

- 本文が500字を超えるとき、1投稿目が500字以内に収まる段落境界のうち「直前の段落が15字以下の1行（＝転換の合図）」である最も後ろの境界に `=====` の行を入れます。
- 該当する合図行が無ければ入れず、従来どおり段落境界で自動分割します。
- `post_threads.py` はマーカー行で必ず切り、マーカー自体は投稿しません。
- 自動の位置が気に入らなければ、Gmail 下書き上で `=====` の行を手で動かせば、その位置で切れます。

あわせてセルフリプの取り込みを「最も早い1件」から「**note リンク入りを優先、無ければ最も早い1件**」に変えました。
