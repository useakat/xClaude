### Claude *(15:24 JST)*

まず報告書に表現テンプレート集を追記します。同時に writer 系スキルが現状どう style を参照しているか確認します。

*[ツール: `Read`, `Edit`, `Bash`]*

報告書に追記しました。次に writer 系スキルからの参照方法について。

現状を整理すると、各 writer スキルは `style/style-*.md` という共通スタイルファイルを参照する仕組みが既にあります。同じパターンに乗せるのが最も自然です。

**推奨案：`style/hook-patterns.md` を新設し、各 writer スキルから参照させる**

理由：
- 報告書（`docs/reports/`）はアカウント分析という性質で、汎用フック集の置き場としては不適。`style/` は既に「複数スキルが共有する文体資産」の置き場として機能しており（`style-note-story.md` 等）、ここに置けば1ファイル更新で全 writer に反映される
- トレードオフ：各 writer の SKILL.md に1行参照を足す手間が要る。`writer-xstory` のように既に独自フック集を持つものは、集約するか併存させるかの判断が必要

実装方針を確認させてください。

*[ツール: `AskUserQuestion`]*

→ よーんの回答：**style に新設し、X系 writer（xstory / xonepoint / xnews / xqa）にだけ参照を追加。今やる。**

`style/hook-patterns.md` を作成します。4型を「構文テンプレート／実例／物理・宇宙への応用例」の3列テーブルで整理し、横断技法・避けるべき冒頭も収録。ヘッダーで「各スキル固有のフック制約が優先・本ファイルはバリエーションの引き出し」と位置づけを明記しました。
