- インプ数は X API でしか取れません。相手自身が developer.x.com でアプリを作り、Bearer トークンを発行する必要があります。これはスマホのブラウザだけで完結します。

**実行環境の候補（すべてスマホのブラウザだけで設定可能）**
1. **GAS（Google Apps Script）** — Google アカウントだけで動き、10分ごとの時間トリガーと Gmail 送信が標準で揃っています。無料枠で十分です。相手が Google ユーザーなら一番敷居が低いです。難点はスマホでのコード編集画面が使いにくいこと。
2. **val.town** — ブラウザ上で JS を書き、cron 実行とメール送信が標準機能です。GAS よりスマホ編集が快適で、無料枠あり。ただ国内では知名度が低く、相手に説明が要ります。
3. **Cloudflare Workers / GitHub Actions** — どちらも無料で定期実行できますが、メール送信に外部サービスの追加設定が要るので、相手の負担は増えます。

**おすすめ**
- 相手が X API の費用を許容できるなら、**GAS 一択**です。よーんの `x_imp_alert.py` をそのまま GAS に移植したコードを用意し、相手はトークンとメールアドレスを貼って保存、トリガーを1回設定するだけ、という形にできます。
- 相手が費用を許容できないなら、この機能自体が成立しないので、X のアナリティクス画面を自分で見てもらう以外にありません。

まず相手に「X API の有料プランを使えるか」を確認するのが先だと思います。使えるなら、GAS 版のコードはすぐ作れます。

**現在の X API 料金（2026年2月6日に変更）**
- 新規開発者向けの Free プランと Basic などの定額プランは廃止され、**従量課金（pay-per-use）のみ**になりました。月額の最低料金や契約はありません。
- 自分の投稿を読む「Owned Read」は1投稿あたり $0.001、他人の投稿は $0.005 です。請求は「リクエスト回数」ではなく「返ってきた投稿の件数」単位です。
- 新規登録時に少額のお試しクレジットは付きますが、継続利用には Developer Console でクレジットを前払いする必要があります。

**この通知機能を動かした場合の目安**
今のスクリプトは10分おきに直近20件を取得しているので、そのまま移植すると以下のようになります。

| 取得件数/回 | 1日の読み取り数 | 月額目安 |
|---|---|---|
| 20件（現状） | 2,880 | 約 $9 |
| 5件 | 720 | 約 $2 |

直近3時間の投稿だけを対象にするので、`start_time` で時間窓を指定し取得件数を絞れば月数百円に収まります。相手に伝える金額としては「月に数百円〜千円強」が妥当です。

**整理すると**
- 相手に必要なのは、X Developer 登録＋クレジット前払い（少額）＋ GAS の設定です。Basic の月200ドルは要りません。
- 前回「Basic が必要」と言ったのは古い情報でした。訂正します。

よーんのこのサーバーが今どのプランで動いているかは、プロジェクト内に記録がなく確認できませんでした。もし Basic の定額を払い続けているなら、従量課金への切り替えで安くなる可能性があります。

## よーん *(21:34 JST)*

現行のように直近20件を毎回取る　これについて説明して

### Claude *(21:34 JST)*

現行の `x_imp_alert.py` の動きと、それが課金にどう響くかの説明です。

**現行の取得方法**
- 10分おきに `/2/users/{id}/tweets` を1回呼び、`max_results=20` で「直近20件の投稿」を必ず取得します。
- 取得した20件を手元で見て、投稿から3時間以内のものだけを選んでインプ数を判定します。つまり「絞り込みはスクリプト側」で、API には「全部ちょうだい」と頼んでいる形です。
- 作った時点では定額プランだったので、何件返ってきても料金は変わらず、この作りで問題ありませんでした。

**従量課金で何が起きるか**
- 従量課金は「返ってきた投稿1件ごと」に課金されます。20件返れば20件分です。
- 3時間以内の投稿が0件でも、3日前の投稿が20件返ってきて20件分課金されます。実際に使う分は数件なのに、残りは捨てるために払う状態になります。
- 1日144回 × 20件 = 2,880件/日 → 月 $8.6 ほど。しかもこの額は投稿頻度に関係なく固定でかかります。

**絞り込む方法**
- 同じエンドポイントに `start_time` パラメータがあり、「この時刻以降の投稿だけ返して」と指定できます。これを「今から3時間前」にすれば、返るのは時間窓内の投稿だけになります。
- 窓内に投稿が無ければ0件で返り、課金もゼロです。先ほどの「10投稿/日で月 $5.4」はこの前提での計算です。
- `max_results` は 5〜100 で指定できるので、10 程度にしておけば安全弁になります。

**よーん自身の環境への影響**
- よーんのアカウントが今も定額プランで動いているなら、現行のままで追加費用はありません。
- もし従量課金に移行するなら、この `start_time` の追加は先にやっておくべき変更です。1行の修正で済みます。

## よーん *(21:39 JST)*

start_time と インプレッション数でX側で絞って返せない？

### Claude *(21:39 JST)*

できません。X API v2 の投稿一覧エンドポイントで指定できる絞り込みは、時刻（`start_time` / `end_time`）と ID 範囲（`since_id` / `until_id`）、種別（リツイート・リプライの除外）だけです。インプ数やいいね数などの指標で絞る条件は存在しません。

**補足**
- 検索エンドポイント（recent search）にも、API 版には「いいね数以上」のような指標条件はありません。Web の検索窓で使える `min_faves:` は API では使えません。
- インプ数は「投稿を取得して初めて分かる値」なので、閾値判定はこちら側で行うしかありません。

**つまり今の修正が課金の下限です**
- 「監視中の投稿1件につき、1回のチェックで1読み取り」が最小単位です。
- これ以上減らすなら、チェック間隔を伸ばすか（15分なら1/3減）、通知済みの投稿を次回以降読まないかですが、後者は新規投稿の検知のために一覧取得が必要なので効果が薄いです。
