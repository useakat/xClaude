**① 「クローン」の中身の大半は、すでにルール化されて配線済みです。** 頻出8パターンのうち「像を結ばない表現」「因果の飛躍」→ `/check-reader`、「事実を超えた断定」→ `/check-fact-lim`・`/check-critic`、「前方参照」「誇張定型句」「固有名の脇道」→ brand.md、と分散配置されています。同じコメント群から素朴にクローンを作ると、既存チェックの劣化コピーになるリスクがあります。

**② それでもクローン agent には固有の価値があります。**
- ルール化しきれない**好みの判断**（例：擬人化の強弱 — 報告書でも「基準を作れず2度見送り」）は、ルールではなく**実際の指摘の実例（few-shot）**を持った読者役のほうが再現できる
- 分散した既存ルールを「よーんならどう見るか」という**一人の視点で最終検品**するゲートがない（現状、その役をよーんさん本人が務めている）
- 今後の差分分析の成果の**恒久的な置き場**になる：クローン通過後に出た指摘＝クローンの見逃し→実例コーパスに追記、で自己改善が回る

つまり「既存チェックの置き換え」ではなく、**フロー10.5（セクション別提示の直前）に最終ゲートとして追加**するのが正しい設計だと考えます。

## 提案する進め方

1. **コーパス抽出**: w002 のセッション履歴（jsonl 2本・ユーザー発言 約3,500件）から原稿への指摘コメントを抽出するスクリプトを作成（→ **スクリプト新規作成の承認が必要です**）
2. **ペルソナ蒸留**: 指摘を分類し、実例引用つきの「よーん検品ペルソナ」ファイルを作成。既存ルールと重複する項目は brand.md 参照に寄せ、未ルール化の好み判断を実例で持たせる
3. **`/check-yohn` スキル新設**: 別コンテキストの検品役が指摘を列挙→writer が改稿→再チェック（最大3ループ。既存 check 系と同型）。解消できない指摘はブロックせず、提示時に注記として添える
4. **spec.md に配線**（フロー10.5）＋ metadata.yaml 追記＋commit
5. **バックテスト**: オポチュニティの初稿を食わせて、実際の80件のうち何割を再現できるか（＋誤検知率）を測定して報告。的中率が低ければペルソナを調整

**期待値の注意**: 往復ゼロにはなりません。狙いは「既出パターンの再発をゼロにし、よーんさんの指摘を本当に新しい判断だけに絞る」ことです。

## バックテスト結果（ケプラー記事の初稿 vs 実際の指摘）

初稿スナップショット（7月中旬時点の版）に検品役を1回走らせ、その後よーんさんが実際に出した指摘（正解セット26件）と突き合わせました。

**的中: 17/26（約65%）**。主な的中例:
- 「ダグ・ウィーマー」固有名の削除、「やじろべえ」比喩の破綻、「危ぶまれていた」の誤解、「一点を粘る」の据わりの悪さ、ヴァンダーバーグ発見が1文で流れている（見せ場の熱量）、「一度の減光」と「3回必要」の矛盾、導入の約束2つが同じ answer である件、K2/元のケプラーの呼称揺れ、CME→ベアリングの出典疑義、導入の種明かし — いずれも実際の指摘と同じ箇所・同じ性質で検出
- うち3件はペルソナの実例そのまま（記憶）ですが、残り14件は**実例にない箇所への汎化**でした

**見逃し: 9件**。故障場面の熱量不足、緊迫場面に挟まる長説明（興ざめ）、黄道面説明の難所丸ごと、種明かし再開時の前提再掲、「命→使命」級の語の精度数件。カテゴリ自体はペルソナにあるが適用漏れ、という性質です（複数ループで拾われる余地あり）。

**誤検知**: 追加指摘の大半（「張本人」の語感、段落文数超過、図番号の順序、K2-18b の「スーパーアース」表記疑義など）は brand.md 準拠の正当な指摘で、明確なノイズはわずかでした。

**評価**: 最終ゲートとして実用水準です。往復ゼロにはなりませんが、同型指摘の再発をこの精度で先回りできれば、フロー11 の往復は大きく減る見込みです。コストは1ループ約6万トークン・12分でした。
