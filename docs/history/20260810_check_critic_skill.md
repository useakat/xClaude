## 推奨：独立 agent を別に立てる（check-reader へのペルソナ追加では不十分）

理由は2つあります。

**1. 指摘の後段が違う**
素朴読者の指摘は「報告→改稿」で完結しますが、知識読者の指摘は「**列挙→notebook で裏取り→反映**」という別の後工程を持ちます。同じスキルに2ペルソナを同居させると、後段の分岐が複雑になります。

**2. 機械的なファクト抽出では出ない論点を拾える** ← これが決定的

7/20 に入れた「ファクト抽出→項目別検証」は、**本文に書かれている主張**しか検証しません。しかし今回効いた質問の多くは、**本文に書かれていないこと**への問いでした：

- 「5と6は同時打ち上げ？なぜ2機も送った？」← 本文に無い
- 「4号が圧壊してるなら3号も途中で潰れたのでは？」← 本文に無い
- 「90気圧は当時分かってたの？」← 本文は「分かっていた」と断定 → その断定の**成立時期**を疑う

これは「本文の主張を照合する」チェックでは出ません。**"知識ある読者になりきって、本文が触れていない前提や、都合よく単純化した箇所を突く"** という敵対的な読みが要る。check-reader と同じ「別コンテキストのサブエージェントに原稿だけ渡す」仕組みを流用しつつ、**ペルソナを「宇宙クラスタの詳しい読者。スクショで晒す気で粗を探す」に変え、出力を check-fact-lim に流す**のが最も効きます。

初稿 →
1. **check-fact-lim**（notebook 限定・項目別）＝本文の主張の照合

→ ユーザー提示
