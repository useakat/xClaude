## 評価

**① 現行 spec は「未使用フィルタをかけない」を意図的に選んでいる**
spec.md 161行目に明記されています：「ネタは『未使用』フィルタをかけず、選んだシートの全データ行を対象に選ぶ（高頻度運用のため在庫を絞らない）」。今回の提案はこの設計判断を覆すものです。なので最大の論点は**在庫枯渇**。全ネタがチェック済みになったとき何を選ぶか（全解除してリセット／補充を促す／その時だけフィルタ無効）を決めないと、いずれ選べなくなります。

**② チェックを入れるタイミングが最大の落とし穴**
z01 は **Gmail 下書きを作るだけ**で、実投稿は cron が別途行います。
- 下書き作成時にチェック → 破棄・修正された下書きのネタも「投稿済み」になり、実際は未投稿なのに消費される
- 実投稿時にチェック → 正確だが、cron 側が「どのネタ由来か」を知る必要があり、下書きにネタ番号を埋め込んで cron に読ませる改修が要る（＝実装コスト増）

**③ thoughts シートが提案から漏れている**
STEP 1 は noteNeta / newsTopics / **thoughts** を 2:2:1 で選びます。2シートだけに列を足すと thoughts だけ無制限になり不整合。揃えるか、対象外にする理由を決める必要があります。

## 私の推奨

「使い切ってから再利用」が目的なら提案どおりでいいですが、高頻度運用との相性なら**チェック列より「最終使用日」列のほうが良い**と考えます。選定時に直近使用ぶんだけ除外（または古い順優先）すれば、在庫を絞らない現行方針を保ったまま重複を避けられ、枯渇管理も不要です。
