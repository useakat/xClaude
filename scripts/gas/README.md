# X 投稿インプレッション通知（Google Apps Script 版）

自分の X 投稿が「投稿から 3 時間以内に 1,000 インプ」に達したら、メールでお知らせする仕組みです。
PC は不要で、スマホのブラウザだけで設定できます。Google アカウントと X アカウントがあれば動きます。

- 本体: `x_imp_alert.gs`（このフォルダ）
- 通知は 1 投稿につき 1 回だけ。閾値・時間窓・チェック間隔は自由に変えられます

## 費用

X API は従量課金です（2026 年 2 月以降、無料枠はありません）。
課金は「取得した投稿 1 件ごと」で、自分の投稿は 1 件 $0.001 です。このスクリプトは時間窓内の投稿しか取得しないので、投稿していない時間帯は課金されません。

| 1 日の投稿数 | チェック間隔 | 月額目安 |
|---|---|---|
| 10 投稿 | 30 分 | 約 $2 |
| 10 投稿 | 10 分 | 約 $5 |
| 3 投稿 | 30 分 | 約 $0.5 |

Google Apps Script 側は無料です。

## セットアップ手順

### 1. X Developer に登録して Bearer Token を発行する（所要 10〜15 分）

1. スマホのブラウザで https://developer.x.com を開き、自分の X アカウントでログイン
2. 「Sign up」から開発者アカウントを作成。利用目的を英語で聞かれたら、次の文をそのまま貼ってよいです
   > I want to monitor the impression counts of my own posts and receive an email notification when a post reaches a threshold. Personal use only.
3. 自動で作られる Project / App を開き、「Keys and tokens」→「Bearer Token」の「Generate」を押す
4. 表示されたトークンをコピーして控える（**表示は 1 回きり**。失くしたら Regenerate で作り直せます）
5. Developer Portal の「Billing」（または Credits）からクレジットを少額購入する。残高がゼロになると監視が止まります

### 2. Google Apps Script にスクリプトを置く（所要 5 分）

1. スマホのブラウザで https://script.google.com を開く（Google ログインが必要）
   - スマホ表示だと操作しづらい場合は、ブラウザのメニューから「PC 版サイトを表示」に切り替えてください
2. 「新しいプロジェクト」を作成
3. エディタに最初から入っている `function myFunction() {}` を全部消し、`x_imp_alert.gs` の中身を丸ごと貼り付ける
4. 冒頭の `CONFIG` を書き換える

   | 項目 | 入れるもの |
   |---|---|
   | `X_BEARER_TOKEN` | 手順 1 で控えたトークン |
   | `X_USERNAME` | 自分の X ユーザー名（`@` は付けない） |
   | `NOTIFY_TO` | 通知を受け取るメールアドレス |
   | `THRESHOLD` | インプ閾値（初期値 1000） |
   | `WINDOW_HOURS` | 投稿から何時間以内か（初期値 3） |
   | `CHECK_INTERVAL_MIN` | チェック間隔の分。1 / 5 / 10 / 15 / 30 のいずれか（初期値 30） |

5. 保存（フロッピーのアイコン、または Ctrl+S）

### 3. 動かす

1. 画面上部の関数選択（「myFunction」などと表示されている所）で **`setup`** を選び、「実行」を押す
2. 初回は「承認が必要です」と出るので、自分の Google アカウントを選んで許可する
   - 「このアプリは確認されていません」と出たら「詳細」→「（プロジェクト名）に移動」で進めます
3. 「実行ログ」に `セットアップ完了` と出れば、30 分おきの自動実行が登録されています

### 4. 確認する（任意）

- **`testRun`** を実行 → メールは送らず、判定結果だけ実行ログに出ます（直近に投稿が無ければ「時間窓内 0 件」）
- **`sendTestMail`** を実行 → 通知メールの見本が届きます。迷惑メール扱いされていないか確認してください

## 止める・設定を変える

- 止める: **`teardown`** を実行
- 閾値などを変える: `CONFIG` を書き換えて保存し、もう一度 **`setup`** を実行（二重登録にはなりません）

## よくあるトラブル

| 症状 | 原因と対処 |
|---|---|
| `CONFIG を確認してください` | 書き換え忘れ。該当項目を直す |
| `HTTP 401 Bearer Token が無効です` | トークンの貼り間違い。Developer Portal で Regenerate して貼り直す |
| `HTTP 402 クレジット残高が不足` | X API のクレジットを追加購入する |
| `HTTP 429 レート制限` | 一時的なもの。次回の実行で回復します |
| メールが届かない | 迷惑メールフォルダを確認。Google の送信上限（1 日 100 通）は通常超えません |
| 監視が止まった | API エラー時は 1 回だけ「X API エラー」というメールが届きます。内容に従って対処し、`setup` を再実行 |

## 仕組み（興味がある人向け）

- 定期的に X API `GET /2/users/{id}/tweets` を呼び、`start_time` で「今から時間窓＋10 分前」以降の投稿だけを取得します
- リポストと自分のリプライは除外し、オリジナル投稿と引用 RT を対象にします
- 閾値に達した投稿は Google のメール送信機能で通知し、投稿 ID を記録して二重通知を防ぎます（記録は 7 日で自動削除）
- ユーザー名からユーザー ID への変換は初回だけ API を呼び、以降はキャッシュを使います
