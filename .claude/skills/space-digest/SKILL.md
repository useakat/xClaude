あなたは毎朝の「宇宙ダイジェスト」を書くエージェントです。無人実行（`claude -p`）なので、ユーザーへの質問・確認は一切せず、最後まで自分で判断して本文ファイルを書いてください。**メールの送信はしません**（ラッパーが送ります）。

引数: `$ARGUMENTS` ＝ 候補ファイルのパス（例 `logs/space_digest/2026-11-01_candidates.md`）。空なら今日の日付（JST）で `logs/space_digest/YYYY-MM-DD_candidates.md` を使う。
出力先: 候補ファイルの `_candidates.md` を `_digest.txt` に置き換えたパス。

# STEP 1: 判定基準を読む

`brand.md` と `plan.md` を Read する。★ネタ候補の基準はここから取る：
- 宇宙探査にかけた執念の人間ドラマ（故障・危機からの復帰、長期ミッション、諦めない運用）
- 直感を裏切る驚き（「えっ」と言わせる事実・数字）
- 物理的な理由まで分かりやすく解ける題材
- 素粒子・物理のトリビアは息抜き枠（★は原則付けない。付けるなら理由に「息抜き枠」と書く）

# STEP 2: 候補を読む

候補ファイルを Read する。構成は `## プレスリリース` `## ニュース・配信` `## 論文` の 3 節、各項目に タイトル／出典／URL／要旨。末尾に `## 取得状況`。

- 本文が `NO_CANDIDATES` なら、出力先に次の 2 行だけ Write して終了：
  ```
  【宇宙ダイジェスト】YYYY-MM-DD（曜）
  新着なし（直近 48 時間に未読の新着がありませんでした）
  ```

# STEP 3: 選別と要約

**件数の上限**：ニュース・配信 8、プレスリリース 6、論文 5（arXiv と Nature/Science を合わせて 5）。残りの論文候補はタイトルと URL だけを最大 10 件列挙。候補が上限より少なければ全部載せてよいが、宇宙・物理と無関係なもの（組織の人事、イベント告知、商品紹介など）は落とす。

**選ぶ順**：発信軸との相性 ＞ 新しさ ＞ 出典の一次性（機関のプレスリリース ＞ 科学メディア）。同じ出来事が複数ソースにあれば 1 件にまとめ、出典を併記する（例「NASA JPL／sorae」）。

**要約の書き方**（日本語、各 2〜3 行、体言止め可、ですます不要）：
- 何が・誰が（機関／探査機／装置）・どうした・なぜ重要か
- **候補ファイルに無い数字・固有名詞・主張を書かない。** 要旨が 1 文しか無ければ 1 行でよい。推測が要る場合は「〜とみられる」でなく、書かない
- 英語の固有名詞は原語のまま（Voyager 1、JWST）。日本の探査機は日本語名（はやぶさ2、みお、MMX）
- 論文は「何を・どうやって・何が分かった」。arXiv はプレプリント（査読前）であることを「arXiv」の表記で示す

**★ネタ候補**（最大 3 件）：STEP 1 の基準に合う項目に ★ を付け、本文先頭の「■ ★ネタ候補」に再掲する。各 1 行の「理由：」を添える（例「10 年前に故障した探査機を再起動。執念型」「直感に反する数字。驚き型」）。該当が無ければ「■ ★ネタ候補」に「該当なし」と書く。★ の項目に限り、WebFetch で元記事（候補の URL）を読んで要約を補強してよい（最大 3 本。失敗したら候補の要旨だけで書く）。他の項目では WebFetch を使わない。

# STEP 4: 本文を書く

出力先に次の形で Write する（平文。Markdown 記法は使わない。URL は行単体で置く）：

```
【宇宙ダイジェスト】2026-11-01（土）
ニュース 6・プレスリリース 4・論文 5（候補 38 件から）

■ ★ネタ候補
★ タイトル（出典・11/01）
  要約 2〜3 行
  理由：…
  URL

■ ニュース・配信
- タイトル（出典 11/01）
  要約
  URL

■ プレスリリース
- タイトル（機関 11/01）
  要約
  URL

■ 論文
- タイトル（arXiv astro-ph.EP 11/01 ／ Nature Astronomy 10/30）
  要約
  URL
その他の論文候補：
- タイトル — URL
```

- 1 行目はタイトル行（日付は候補ファイルの日付、曜日は日本語 1 文字）
- 2 行目は件数行。形式は必ず `ニュース n・プレスリリース n・論文 n（候補 N 件から）`（ラッパーが件名に使う）
- ★ の項目は該当する節にも載せ、行頭を `★` にする
- 候補ファイルの `## 取得状況` に「取得失敗」があれば末尾に `（取得失敗: ソース名）` を 1 行添える

# STEP 5: 終了

Write が終わったら、出力先のパスを 1 行出力して終了する。送信・コミット・シート登録はしない。

# 禁止事項

- ユーザーに質問・確認をしない
- 候補に無い情報を書かない（WebFetch で読んだ元記事の範囲は可）
- メール送信・git 操作・Sheets 書き込みをしない
- 本文ファイル以外を Write しない
