# check-brand

## 目的

- 受け取った本文を、指定 brand.md の **採点基準**で 0〜10 採点し、全項目8点以上になるまで書き直す（採点ループ）
- 合格本文を brand.md の Writing Rules / Do Not に合わせてトンマナ調整する
- 事実（数値・固有名詞・因果関係）は一切変えない
- 最終原稿・スコアサマリー・トンマナサマリーを返す

## 入力の解釈（引数規約）

`$ARGUMENTS` を次のように分解する：

- **先頭トークン（最初の空白まで）が `.md` で終わるパスなら、それを brand.md パスとして扱い、残りを本文とする。**
- 先頭が `.md` パスでなければ、`$ARGUMENTS` 全体を本文とし、brand.md は **`./brand.md`（カレントディレクトリ）** にフォールバックする。

例：
- `projects/w003/brand.md 実は、ミューオンは…` → brand.md=`projects/w003/brand.md`、本文=`実は、ミューオンは…`
- `実は、ミューオンは…`（パスなし）→ brand.md=`./brand.md`、本文=`実は、ミューオンは…`

## 手順

### 1. ブランド定義の読み込み

上記規約で決まった brand.md を Read で読み込む。
brand.md が継承元（`../../brand.md` 等）や style 定義を参照している場合、必要に応じてそれらも読む。

brand.md 内の **`## 採点基準`** セクションを探す：

- **ある場合** → そこに列挙された項目・各項目の合格ライン・OK/NG・字数目標を、フェーズAの採点項目・判定基準として使う（スキル側に数値や項目を持たない）。
- **無い場合** → brand.md の「Writing Rules」「出力前セルフチェック / Verification」「Do Not」から採点項目を動的抽出する。この場合は出力の冒頭に次の警告を必ず付す：

  ```
  ⚠️ brand.md に採点基準（## 採点基準）の明示記載なし（動的抽出で採点しました。人手レビュー推奨）
  ```

### 2. フェーズA — 採点ループ

採点基準の各項目を **各 0〜10 の 10段階で採点**する。汎用スケール：

| 帯 | 意味 |
|---|---|
| 9〜10 | 優（基準を完全に満たす） |
| 7〜8 | 合格（8点が合格ライン） |
| 5〜6 | 要改善 |
| 0〜4 | 不可 |

各項目の「何点で合格か」「OK/NG の具体」「字数の許容・推奨レンジ」は **brand.md の採点基準に書かれた値**に従う（採点基準にラインの指定があればそれを優先する）。

**全項目 8 点以上**で合格。1項目でも 8 点未満なら該当箇所を書き直して再採点する。最大 **5 回** ループ。

#### ループ手順

```
バージョン履歴 = [{"version": "V0", "text": V0, "scores": null, "total": null}]

For i in 1..5:
    現行バージョン = 履歴の最後のバージョン
    現行バージョンの本文に対して 採点基準の各項目を採点 → scores = [s1, s2, ...]
    total = sum(scores)
    履歴の最後のバージョンに scores と total を記録

    If all(s >= 8 for s in scores):
        合格 → 現行バージョンの本文を 【採点合格本文】 として確定
        ループ脱出

    Else:
        8 未満の項目を特定し、該当箇所のみ事実を変えずに書き直す
        新バージョン V{i} を履歴に追記
        ループ継続

If ループが 5 回完走しても合格しなかった:
    履歴の中で total が最大のバージョンを 【採点合格本文】 として採用
    警告フラグを立てる
```

#### 書き直しルール

- 事実は絶対に変えない（数値・固有名詞・因果関係）
- 8 点未満の項目に関連する箇所のみピンポイントで修正
- 既に 8 点以上の項目は触らない（破壊を防ぐ）
- 字数項目が 8 点未満の場合、brand.md に「削る対象優先度リスト」があればそれに従って上から順に削る。既に8点以上の他項目を壊さないようピンポイントで調整する

### 3. フェーズB — トンマナ調整

フェーズAで確定した【採点合格本文】を、brand.md と照合し、**事実は変えず**以下の観点で必要最小限調整する。観点・禁止項目は **brand.md の Writing Rules / Do Not の記載に従う**（スキル側で特定媒体の項目を固定しない）：

- 文体・語尾（brand.md が定める常体／ですます／感嘆の扱い）
- 余白（brand.md が定める1段落あたりの文数・段落間の空行）
- 冒頭・締めの着地（brand.md が定める型）
- Do Not 項目の除去（**brand.md が禁止しているものだけ**除去する。brand.md が要求している要素〔例：ハッシュタグ〕は残す）

調整後の本文を **【最終原稿】** とする。

## 出力形式

```
[最終原稿]

（採点合格 → トンマナ調整済みの本文）

[/最終原稿]

[スコアサマリー]

| ブランド適合-{項目名1} | X/10 | （観察ポイント） | 合格／要改善 |
| ブランド適合-{項目名2} | X/10 | （観察ポイント） | 合格／要改善 |
| …（採点基準の項目数だけ） |
| ブランド適合-合計 | XX/YY（N回目で合格 ／ 5回で不合格・最高得点版を採用） | — | 合格／不合格で採用（警告） |

[/スコアサマリー]

[トンマナサマリー]

| トンマナ | — | （調整内容の要約。変更なしの場合は「ブランド適合」） | 調整あり／変更なし |

[/トンマナサマリー]
```

- 項目名は採点基準の見出しを使う（`{項目名N}` を置換）。合計の分母 YY は `項目数 × 10`。
- スコアが初回から最終回で変化した項目は `X→Y/10` の形で記録する（例: `7→8/10`）。
- **5 回ループしても不合格だった場合は、ステータス列に必ず「不合格で採用（警告）」と明記し、出力の冒頭に警告行を入れる**：

  ```
  ⚠️ ブランド適合チェック不合格（最高得点版を採用しました。人手レビュー推奨）
  ```

- **採点基準の明示記載が無く動的抽出した場合**は、手順1の警告行も出力冒頭に入れる。

## 禁止事項

- 事実（数値・固有名詞・因果関係）を変えない。8点未満の項目に関連する箇所のみ書き直す
- 既に8点以上の項目を書き直して壊さない
- 採点根拠を示さずスコアだけ出さない
- 5回ループで不合格のときに警告を省略しない
- トンマナ調整で brand.md が要求する要素（ハッシュタグ等）を勝手に除去しない／brand.md が禁止する要素を残さない
