# visual_section-planner

記事の本文を渡すと、まずプロジェクトの画像方針（`image/plan.md`・`image/brand.md`）を読み、H2 セクションごとに、その内容を補強する画像案を 3 つずつ考え、各画像の説明を出力する。

対象記事（本文テキスト または 本文ファイルパス）: $ARGUMENTS

## 目的

- セクション画像の方針（`image/plan.md`・`image/brand.md`）に沿った画像案にする
- 各 H2 セクションに配置する画像案を 3 つずつ用意する
- 図解・イメージ・写真（Web取得）から、その内容に最も合う種類を案ごとに選ぶ
- 執筆後の画像準備工程を、再現性のある形で標準化する

## 手順

1. **入力を取得する。** `$ARGUMENTS` の形式を判定する：
   - ファイルパス（`/` を含み、空白・改行のないパス文字列。例 `…/draft/draft.md`）→ Read で読み込む
   - それ以外 → 本文テキストそのものとして扱う

2. **画像方針を読み込む。** プロジェクトの `image/plan.md`（セクション画像の目的・ターゲット・要件・KPI・失格条件）と `image/brand.md`（トーン・画像種類の方針・配色・禁止）を Read する。
   - 入力がファイルパスの場合 → draft のプロジェクトフォルダ（`draft/` の 2 つ上、例 `projects/w002/`）配下の `image/plan.md`・`image/brand.md` を読む（例 入力 `…/projects/w002/2026-…/draft/draft.md` → `…/projects/w002/image/plan.md`・`…/image/brand.md`）。見つからなければ `$(git rev-parse --show-toplevel)/projects/w002/image/` を読む。
   - 入力がテキスト直貼りの場合 → `$(git rev-parse --show-toplevel)/projects/w002/image/plan.md`・`image/brand.md` を読む。
   - 以降の案出し（ステップ4〜5）は、この方針（目的・トーン・種類の方針・配色・禁止）に沿わせる。

3. **H2 で本文を分割する。** `## ` で始まる行を見出しとして区切る。
   - 導入部（H1 直下〜最初の H2 の手前）は対象外
   - `## 参考情報` セクションは対象外

4. **各 H2 セクションの本文を読み、画像案を 3 つ考える。** そのセクションの内容を最もよく補強する画像を 3 案。種類は案ごとに下表から 1 つ選ぶ（3 案で種類が重複してよい）。`image/brand.md` の方針（図解＝本文の語・数値で理解を助ける／イメージ＝文字なしの情景／キャラ・白人間は使わない 等）に沿わせる。

   | 種類 | 用途 | 説明に書くもの |
   |---|---|---|
   | 図解画像 | 仕組み・因果・構造・時系列の視覚化 | 何を表す図か・主要素を日本語で |
   | イメージ画像 | 情景・感情・雰囲気の喚起 | どんな情景・トーンの画像かを日本語で |
   | 写真画像（Web取得） | 実在の人物・機体・史実の実写が要る場合 | Web から取得すべき被写体・年代・探し方の目安 |

5. **各案に画像種類をラベルし、日本語で画像の説明を書く。** 生成プロンプト（構図指示・英語タグ・パラメータ等）は書かない。実在性が必要な対象（実在人物・実機・史実の現場写真）は「写真画像（Web取得）」にする。

6. **セクション分けした markdown で出力する**（下記「出力形式」）。

7. **`draft/image-plan.md` に保存する。**
   - 入力がファイルパスの場合 → その入力ファイルと同じディレクトリ（通常 `…/draft/`）に `image-plan.md` を Write で保存する（例 入力 `…/2026-05-30_SCEtoAUX/draft/draft.md` → 保存先 `…/2026-05-30_SCEtoAUX/draft/image-plan.md`）。既存ファイルがあれば上書きする。
   - 入力がテキスト直貼りの場合 → 保存先が特定できないため保存はせず、出力テキストのみ提示し、その旨を一言添える。
   - 原稿（draft.md）への追記はしない。
   - 保存する中身は H2 セクション本体（`## …` と 3 案のリスト）。チャット表示用の `[画像プランニング結果]` 区切りタグは保存ファイルには含めず、先頭に `# 画像プランニング` を付ける。

## 出力形式

```
[画像プランニング結果]

## （H2セクションタイトル1）

1. 図解画像 — （画像の説明）
2. イメージ画像 — （画像の説明）
3. 写真画像（Web取得） — （画像の説明）

## （H2セクションタイトル2）

1. …
2. …
3. …

[/画像プランニング結果]
```

## 禁止事項

- 生成プロンプト（構図指示・英語タグ・パラメータ）を書かない。画像の説明のみにする
- 各セクション 3 案を必ず出す。過不足を出さない
- 実在性が要る対象（実在人物・実機・史実の現場）に「図解画像／イメージ画像」を充てない
- 導入部・参考情報セクションを対象にしない
- `image/brand.md` に反する案を出さない（煽り・誇張・文系見下し／イメージ画像への文字／キャラクター・白人間／本文にない事実 など）
