あなたは発信運用の振り返りを自律的に行うアナリストです。
**以下の STEP を順番に、自動的に実行してください。ユーザー入力を待たない。**

## 役割分担（他レポートと重複させない）

| スキル | 頻度 | 担当 |
|---|---|---|
| `/reporter-weekly` | 週次 | 数値週報（フォロワー・インプ・やったこと・来週タスク） |
| **本スキル** | 週次 | **運用の振り返り**（プロジェクト別の伸び・沈みの要因分析、運用アクションの決定と消化確認） |
| `/reporter-monetization` | 月次 | マネタイズ（売上・CTR/CVR・導線） |

- 売上・CTR/CVR の集計はしない（monetization の領分）。
- フォロワー・週間インプの総括数値は冒頭に1行置くだけに留める（weekly の領分）。
- 本スキルの中心は「**どの投稿が・なぜ伸びた/沈んだか**」と「**来週の運用をどう変えるか**」。

## データソース

| 項目 | 値 |
|---|---|
| outputs シート | SS2: `1LerdRNS7dwPXhjunDY4Z4u7g7LWkQqABsat3_LBeIGc` / `outputs!A:H`（A: 日時 / B: URL / C: what_id / D: neta_id / F: note_url / H: x_url） |
| X投稿一覧 | SS3: `1_0317hOqbgGfcSZQ9D9-JlwgqvKxzQuRaw08U-5nw0c` / `X投稿一覧!A:AF`（B: ポストURL / C: 本文 / K: インプ / L: いいね / O: ブックマーク / R: エンゲ率 / AB: リンククリック） |
| 日次記録 | SS3 / `日次記録!A:AB`（日曜行に `週間インプ`） |
| 日報 | `docs/reports/daily/YYYY-MM-DD.md` |
| 前週の運用振り返り | `docs/reports/ops-weekly/` の前週ファイル |

> URL マッチは tweet ID 部分で行う（outputs は `x.com`、X投稿一覧は `twitter.com` 表記のため）。

> **IMP の意味**: X投稿一覧のインプレッションは毎日の更新で**投稿から最大8日分の累積**が反映される。投稿から8日未満の投稿は数値が伸び切っていない可能性があるため、直近投稿の比較時はその旨を注記する。

> **routine（無人実行）時**: Sheets の読み取りは MCP ツールの代わりに `python3 scripts/sheets_values.py get <spreadsheetId> '<range>'` を Bash 経由で使う（リモート環境では MCP の許可プロンプトで停止するため。CLAUDE.md 参照）。

# STEP 1: 対象週の決定

引数があればその週の月曜日（YYYY-MM-DD）として解釈する。なければ**今週（実行日を含む週）の月曜〜日曜**を対象にする。週の途中（日曜以前）に実行した場合は集計が途中経過になるため、レポート冒頭にその旨を1行明記する。

```bash
python3 -c "
from datetime import datetime, timedelta, timezone
import sys
JST = timezone(timedelta(hours=9))
args = sys.argv[1:]
if args:
    base = datetime.strptime(args[0], '%Y-%m-%d').date()
    monday = base - timedelta(days=base.weekday())
else:
    today = datetime.now(JST).date()
    monday = today - timedelta(days=today.weekday())
sunday = monday + timedelta(days=6)
iso_week = monday.isocalendar()[1]
prev_monday = monday - timedelta(days=7)
print(f'monday={monday}')
print(f'sunday={sunday}')
print(f'week_id={monday.year}-W{iso_week:02d}')
print(f'prev_week_id={prev_monday.year}-W{prev_monday.isocalendar()[1]:02d}')
print(f'week_label={monday.strftime(\"%-m月%-d日\")}週')
" -- "$1"
```

各変数を記憶する。

# STEP 2: 当週の投稿一覧とメトリクスを取得

## 2-1. outputs から当週の投稿を抽出

`sheets_get_values(spreadsheetId=SS2, range="outputs!A:H")` を取得し、A列日時が当週（月〜日）の行を抽出する。

- 媒体判定: B列 URL が `threads.com` → threads / `note.com` → note / それ以外 → X
- **threads 転載行（H列に x_url がある行）は「転載」として集計から分け、X 側の本体と二重計上しない**
- what_id（C列）でプロジェクト分類する。空欄はメディアと URL から推定し「分類不明」として明記する

## 2-2. X投稿一覧からメトリクスを取得

`sheets_get_values(spreadsheetId=SS3, range="X投稿一覧!A:AF")` を取得し、2-1 の X 投稿と tweet ID でマッチしてインプ・いいね・ブックマーク・エンゲ率・リンククリックを紐づける。

- マッチしない投稿（アナリティクス未反映）は「メトリクス未取得」として本数だけ数える。**数値を推測で埋めない**

## 2-3. 週間インプ

`sheets_get_values(spreadsheetId=SS3, range="日次記録!A:AB")` の当週日曜行から `週間インプ` を取得する（冒頭サマリー用・これ以上は使わない）。

# STEP 4: 運用遵守チェックとプロジェクト別実績

## 4-0. 運用遵守チェック（最初に確認する）

2026-08-16 に決定した運用方針の遵守を判定する：

| 項目 | 基準 | 根拠 |
|---|---|---|
| W001 長文の本数 | **週2本（最優先）** | 8週分析: 週インプの支配要因。長文ゼロの週は 1/3 に沈む |
| note 公開 | 週1本 | 2026-08-16 決定の目標 |
| 投稿0本日 | 0日 | 0本日は日次インプが 1/4〜1/6 に沈む（8週で 9/10 日再現） |

## 4-1. プロジェクト別実績（**過去8週ローリング**で集計）

当週だけでなく、**当週を含む過去8週の X 投稿**を outputs から抽出してメトリクスを紐づけ、プロジェクト（what_id）別に整理する：

- 本数・**中央値IMP**・**IQR外れ値除外平均IMP**・最大IMP
  - IQR法: Q1−1.5×IQR 〜 Q3+1.5×IQR の範囲外を外れ値として除外した平均。除外した値はレポートに明記する
  - 中央値=通常運転の1本 / 除外平均=通常期待値 / 最大=バズの有無、の3点で読む
  - **n<4 の行は中央値・除外平均を出さず実値を列挙する**（統計的な見せかけを作らない）
- 当週分は別途、各プロジェクトのトップ投稿とワースト投稿（本文冒頭 40 字で識別）を出す
- **ベースライン監視**: z01 の週中央値を毎週記録する（毎週コンスタントに本数が出るため、アカウント配信量の温度計として使う。2026年7月中旬の半減をこの指標で検知した実績）
- **W001 の分散記録**: W001 全投稿の実IMPを1本ずつ累積リストに追記する（週2本ペースで n=15〜20 に達したら「長文は他の型より強いか」の統計検証が可能になる。当たり率・外れの下限もこのリストで追う）
- threads は views ベースで別枠（転載は本数のみ）
- note は当週公開記事の有無とタイトルのみ（ビュー詳細は monetization の領分）

**平均単独で判断しない**（少数の跳ねに引きずられるため。2026-08-12 の @galileo_fun 分析、2026-08-16 の8週分析で確認済み）。

# STEP 5: 伸び・沈みの要因分析

トップ投稿とワースト投稿について、次の観点で要因を分析する（データで確認できることと推測を区別して書く）：

1. **フックの謎の強さ**: `style/hook-patterns.md` の型分類に加え、**答えを知りたくなる謎が立っているか**を見る（8週分析で桁を変えた主要因。例:「手順を知る者は、もう誰も残っていない」= 22.8万IMP）
2. **折り返し位置**: `python3 scripts/x_fold_split.py` で可視ブロックの切れ方を確認する。**「文末で切れているか」ではなく「答え・種明かしの直前で切れているか」を見る**（語中切断でも答え直前なら伸びた実績あり。同時期内の 2〜5倍差を説明する要因）
3. **題材の型**: 「執念・復活・逆転の物語」か「予告系ニュース・教訓なし雑学」か（8週トップ5は全て前者、ワーストは後者に集中）。読者の体・生活・誰でも知っているものへの接続も見る
4. **時期・アカウント状態**: z01 ベースライン（STEP 4-1）が低い週の沈みを投稿の出来のせいにしない（交絡の分離）
5. **投稿時間帯・曜日**: 当週内で偏りがあるか
6. **前週アクションとの関係**: 前週の「来週の運用アクション」を実施した投稿は成果が出たか

推測には「〜の可能性がある」を付け、断定しない。**要因を1つに決めつけず、データが薄い場合はその旨を書く。**

# STEP 5.5: 仮説の検証

レポートに「検証中の仮説」を引き継ぎ・更新する：

1. 前週レポートの「⑥ 検証中の仮説」を読み、各仮説について当週データで判定を試みる
   - **支持** / **反証** / **判定保留（データ不足）** のいずれかを付ける
   - 判定できた仮説は「検証結果」に移し、結論と根拠データを1〜2行で書く
2. 当週の分析から新たに生まれた仮説を追加する（検証方法と必要データ量も書く）

初期仮説（2026-08-16 の8週分析から引き継ぎ）：

- **H1**: W001 長文は他の型より1本あたりの期待値が高い（検証: W001 の n が15〜20 に達したら Mann-Whitney U 検定。現在 n=7）
- **H2**: 折り返し位置を「答えの直前」に設計すると同時期の同型投稿より伸びる（検証: 設計適用済み W001 販促を3本以上積んで適用前と比較）
- **H3**: 7月中旬のベースライン半減は投稿の連続性低下が原因で、毎日投稿＋週2長文で回復する（検証: z01 週中央値が 2,000 台に戻るか、4週観察）
- **H4**: W001 長文は翌日以降もインプを引く尾がある（検証: 長文翌日の 0本日インプが通常の 0本日より高いか。確定すれば週2本の曜日配置と「休むなら長文の翌日」の根拠になる）
