# 冒頭フック

冒頭フックは [`style/hook-patterns.md`](../../../style/hook-patterns.md)（①逆説・②知識提示・③場面描写・④問いかけ・⑤語りかけ／口火 のテンプレート集）を参照して作る。長文ストーリーの1文目には ⑤語りかけ・口火型 が向く。フックの構成（2文で何の話か伝える等）は brand.md の規定に従う。

例（フックの形）：
> 返事は来なかった。それでもメッセージを送り続けた。
> 宇宙で凍りつき音信不通になった衛星を、遠い地球から救い出した、静かに熱い話。

## 本編冒頭：日付・地名・状況の具体3点セット（必須）

フック直後の本編冒頭には、以下の3要素を必ず含める。読者を「物語が始まる場面」に一瞬で連れて行くため。

- **日付**（年・月単位の具体）：「1990年4月」「2018年8月のある朝」
- **地名・場所**（具体）：「ヒューストンの管制室」「太平洋上空400km」
- **状況**（誰が・何をしていた）：「20人の技術者が画面を見つめていた」

実データ：SOHO（72,633 IMP）も「2026年に成功した衛星救出ミッション」のように年・主体・出来事が冒頭で立ち上がっていた。
抽象から始まる物語（「むかし、ある研究者が…」型）はIMPが伸びにくい。

# 進め方

1../plan.md と ./brand.md を読み込む
2. 引数（$ARGUMENTS）にテーマや題材が指定されていれば、それをもとに投稿を作成する
3. 指定がなければ、テーマを確認する
4. `examples/buzzPostData.txt` を読み、既存投稿のトーンと重複を確認する
5. ./plan.md と brand.md を参考にして投稿本文を作成する
6. **字数・完結チェック**: 作成した本文が ./brand.md で指定された文字数にだいたい収まり、その投稿内で物語が完結している（中断型でない）かを確認する。超過時は本筋に不要な記述から削り、未完／中断型なら結末まで収める
7. チェックを通した本文を提示する


# 出力後の保存手順

本文を出力したら、以下のファイルに保存する：
- 保存先: **呼び出し元の制作仕様（spec 等）に指定があればそれに従う。指定が無い場合は `./draft/draft.md` に保存する。**
- 保存内容:
  ```
  # [タイトル案から選んだ1つ]
  
  [本文]
  ```
ユーザーへの確認は不要。保存後にファイルパスを1行だけ報告する。
