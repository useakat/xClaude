# check-reader — 素朴な読者チェック

## 目的

書き手には原理的に見えない「読み手にとっての誤解・曖昧さ・不自然さ」（知識の呪い）を、**制作文脈を知らない別コンテキストの読者役エージェント**に原稿だけを読ませることで検出し、なくなるまで改稿する。

**チェックするのは「納得できるか・深く理解できるか」ではなく、「書いてあることが誤解なく読めるか」。** 読者が本文の仕組みを完全に飲み込めるかは問わない。問うのは、書かれた文章そのものが (1) 事実と違う理解に落ちる誤解を生まないか (2) 意味が2通り以上に取れて確定しない曖昧な箇所がないか (3) 日本語として引っかからず自然に読めるか、の3点。

> 由来: 2026-08-06 の Z01 制作セッション（テミス/アルテミス）。/check-fact・/check-brand を1発合格した原稿に対し、「何の影？」「どうやって運んだ？」「月面に置いたように読める」「何のために移した？」等、読者視点の指摘だけで8往復の推敲が必要だった。この読者視点の工程を代行する。
>
> 由来2: 2026-08-15 の Z01 制作セッション（DART）。当初は判定基準が「人に話せるか（理解度1〜10の自己採点）」だったため、3ループとも4/10で頭打ちになり収束しなかった。残った疑問（「相棒の星との大小関係」「なぜ周期が縮むと守れるのか」）は、テキストの誤読・曖昧性ではなく「もっと深く仕組みを知りたい」という**納得の要求**で、140字の短文では原理的に満たせないものだった。判定基準を「誤解・曖昧・不自然の有無」という検証可能な指標に絞り、納得度・理解の深さは対象外にした。

## 入力の解釈（引数規約）

- **先頭トークンが `--plan` なら【構成モード】**（後述）。残りの引数を通常と同じ規約で解釈する（ただし本文の代わりに構成案を受け取る）。
- **先頭トークンが `--fold` なら【折り返しモード】**（後述）。残りの引数を通常と同じ規約で解釈する（本文は全文を渡す。切り出しはスキル側で行う）。
- **先頭トークン（最初の空白まで）が `.md` で終わるパスなら、それをペルソナ定義ファイル（plan.md 等）として扱い、残りを本文とする。**
- 先頭が `.md` パスでなければ、全体を本文とし、ペルソナは**カレント作業フォルダの `plan.md`（Audience セクション）**から読む。それも無ければ「宇宙・物理の専門家ではない一般の科学好き」をデフォルトにする。

## 手順

### STEP 1: ペルソナの確定

ペルソナ定義ファイル（または作業フォルダの `plan.md`）を Read し、想定読者の「知識レベル・挫折経験・読む状況」を把握する（例: PE01 = 物理に憧れがあるが数式で挫折した文系会社員。通勤電車でスマホ流し見）。

### STEP 2: 読者役エージェントに原稿だけを読ませる

**Task ツール（general-purpose サブエージェント）で読者役を起動する。** プロンプトには以下**のみ**を渡す：

1. ペルソナの記述（STEP 1 の要約）
2. 原稿本文

**制作の経緯・ネタ元・意図・過去の版は一切渡さない**（書き手の文脈が混ざると「知識の呪い」の回避にならない）。

読者役への指示テンプレート：

```
あなたは次の読者です: {ペルソナ要約}

以下の文章を初見で読み、読者として正直に報告してください。
知識で補完せず、書いてあることだけから理解してください。

{原稿本文}

チェックするのは「納得できるか・深く理解できるか」ではありません。
書いてあることが誤解なく読めるか、意味がはっきりしない部分がないか、
日本語として自然に読めるかだけを見てください。「もっと知りたい」
「仕組みをもっと詳しく説明してほしい」という感想は対象外です。

報告フォーマット:
1. 【誤解の可能性】書いてある通りに読むと、事実と違う理解に落ちそうな箇所を、
   浮かんだ誤解の内容とともに列挙
   （例:「月へ運んだ」→ 月面に着陸させたと読める）
2. 【曖昧・不明瞭な箇所】指す先が2通り以上に読める語、情報が足りず意味が
   確定しない箇所を列挙
   （例:「その影」→ 何の影か直前に書かれていない／「相棒の星」→ どちらが
   大きいか本文だけでは決まらない）
3. 【不自然な日本語】読点なしの長文・「の」の連鎖・主語と述語のねじれ・
   助詞の誤用など、日本語として引っかかる表現を列挙
4. 【フック未回収】冒頭の文が立てた謎・約束のうち、「結局何の話だったか
   分からない」という誤解や混乱を招いたまま終わっているもの
   （深掘りが足りない・物足りない、という感想は対象外）
5. 【総合判定】誤解・曖昧・不自然のいずれもゼロと言えるか（Yes / No）。
   No なら該当箇所を再掲
```

### STEP 3: 指摘への回答として改稿

読者役の報告を受け、writer（呼び出し元エージェント）が**指摘に本文中で答える形**で該当箇所のみを書き直す：

- 誤解の可能性 → 誤解が生じない表現に置き換える（例: 「月へ運んだ」→「月の見張り役に就かせた」）
- 曖昧・不明瞭な箇所 → 指す先・意味を本文中で確定させる（例: 「その影」→「地球の影」）
- 不自然な日本語 → 語順の入れ替え・読点・分割で自然な言い回しに直す
- フック未回収（誤解・混乱を招くもの） → 手段・原因を本文で具体的に回収する
- **事実（数値・固有名詞・因果関係）は変えない。字数制約があれば維持する。**

### STEP 4: 収束ループ

改稿した原稿で STEP 2 を再実行する（読者役は**毎回新しいサブエージェント**で起動し、前回のやり取りを見せない）。

- **終了条件**: 誤解の可能性・曖昧不明瞭な箇所・不自然な日本語がいずれもゼロ、かつフック未回収（誤解・混乱を招くもの）がゼロ
- **最大3ループ**。3回で収束しない場合は、残った指摘を列挙して「未解消の指摘」として警告付きで出力する

## 出力形式

```
[最終原稿]

{改稿後の本文}

[/最終原稿]

[読者チェックサマリー]

| ループ | 誤解 | 曖昧・不明瞭 | 不自然な日本語 | フック未回収 | 総合判定 |
|---|---|---|---|---|---|
| 1回目 | X件 | X件 | X件 | X件 | No |
| 2回目 | … | | | | |

解消した主な指摘:
- {指摘} → {対応}

[/読者チェックサマリー]
```

3ループで未収束の場合は冒頭に警告を付す：

```
⚠️ 読者指摘が3ループで収束しませんでした（残: {残った指摘}。人手レビュー推奨）
```

## 構成モード（`--plan`）— 執筆前の読者疑問リスト

**目的**: 執筆後の検品（通常モード）を前倒しし、構成承認の段階で「読者が『なぜ？』と聞く難所」を洗い出す。出力は W002 spec の agenda「難所マップ」の材料になる。改稿ループは行わない（構成はまだ文章でないため）。

> 由来: 2026-08 のケプラー記事（W002）。黄道面の幾何という最大の難所の扱い（付録化）が執筆後に決まり、大改稿になった。難所の特定は構成段階で可能だったため、この工程を前倒しする。

### 手順

1. **ペルソナの確定** — 通常モードの STEP 1 と同じ（ペルソナ定義ファイル → 作業フォルダの `plan.md` → デフォルトの順）。
2. **読者役エージェントに構成案だけを読ませる** — Task ツール（general-purpose）で読者役を起動し、ペルソナ要約と「タイトル＋構成案（H2 と各章の内容予定）」**のみ**を渡す。制作の経緯・ネタ元・意図は渡さない（通常モードと同じ隔離）。

   読者役への指示テンプレート：

   ```
   あなたは次の読者です: {ペルソナ要約}

   以下は、これから読む記事のタイトルと構成案（章立てと各章の内容予定）です。
   初見の読者として、正直に報告してください。知識で補完しないでください。

   {タイトル＋構成案}

   報告フォーマット:
   1. 【章ごとの疑問】各章の内容予定を読んで「この章を読むとき、自分はこう聞きたくなるはず」
      という疑問を章ごとに列挙（動力・位置・因果・仕組み・「前の章の話と矛盾しない？」）
   2. 【期待する種明かし】タイトルと冒頭が立てる謎のうち、どの章で種明かしされると期待するか
   3. 【難所の予感】説明されても理解できなそうな箇所（読むのを挫折しそうな箇所）を自己申告
   ```

3. **疑問リストの整理** — 読者役の報告を H2 ごとの表に整理して返す。**扱いの決定（本編で解く／付録に送る／断言で流す）は呼び出し元 writer の仕事**であり、このスキルは疑問の列挙までを担う。

### 出力形式（構成モード）

```
[読者疑問リスト]

| H2 | 読者の疑問 | 種別（因果/仕組み/位置/矛盾/挫折予感） |
|---|---|---|
| … | … | … |

期待される種明かし:
- {謎} → {読者が期待する回収章}

[/読者疑問リスト]
```

1回の実行で完了する（収束ループなし）。

## 折り返しモード（`--fold`）— 「さらに表示」を押させられるか

**目的**: タイムラインで実際に見えるのは冒頭の一部だけ。そこで読むのをやめられたら本文の出来は無関係になる。**可視部分だけを読者役に読ませ、続きを読みたくなるかを判定する。**

> 由来: 2026-08-12 の @galileo_fun 分析。10万IMP超え13件の可視末尾が全件「その正体とは…」「それはね…」で切れており、可視ブロックの終わり方が設計されていた。一方こちらの既存投稿5本を実測すると、3本が語の途中・説明の途中で機械的に切れていた（`docs/reports/` の galileo 分析を参照）。

### 可視範囲の決め方（280 weight）

X は **280 weight** を超える投稿を長文投稿として扱い、タイムラインでは先頭 280 weight 分を表示して「さらに表示」に畳む。weight は**全角文字＝2 / 半角文字＝1**（日本語だけなら 140 字、半角数字が混じるとその分だけ字数が伸びる）。

- 本文を先頭から数えて **280 weight に達する直前まで**を「可視ブロック」とする。
- **添付画像の URL は weight に加算しない**（画像は文字数を消費しない）。
- 本文全体が 280 weight 以内なら折り返しは発生しない。**その場合はこのモードをスキップし、その旨を報告する。**

**weight は目視で数えない。必ずスクリプトで切り出す：**

```bash
python3 scripts/x_fold_split.py <本文ファイル>          # 人が読む形式
python3 scripts/x_fold_split.py <本文ファイル> --json   # visible / hidden / cut_before / cut_after を JSON で取得
```

`folded: false` が返ったら折り返しなし＝このモードはスキップする。

### 手順

1. **ペルソナの確定** — 通常モードの STEP 1 と同じ。
2. **可視ブロックの切り出し** — `python3 scripts/x_fold_split.py <本文ファイル> --json` を実行し、`visible`（可視ブロック）・`cut_before`・`cut_after` を取得する。**自分で数えない。**
3. **読者役エージェントに可視ブロックだけを読ませる** — Task ツール（general-purpose）で起動し、ペルソナ要約と可視ブロック**のみ**を渡す。**続きの本文は絶対に渡さない**（続きを知っている読者は「押したくなるか」を判定できない）。

   読者役への指示テンプレート：

   ```
   あなたは次の読者です: {ペルソナ要約}

   スマホでタイムラインを流し見しています。次の投稿が流れてきました。
   これは投稿の冒頭部分だけで、続きは「さらに表示」を押さないと読めません。
   途中で切れているのは仕様です。切れていること自体を欠点として指摘しないでください。

   {可視ブロック}

   報告フォーマット:
   1. 【判定】「さらに表示」を押すか、指でスクロールして通り過ぎるか。どちらかを必ず選ぶ
   2. 【理由】そう判断した理由を1〜2文で
   3. 【引きの強さ】続きを読みたい気持ちを1〜10で自己採点
   4. 【残った謎】読み終えた時点で「答えが知りたい」と思っている問いを列挙
      （何も思い浮かばなければ「なし」と書く）
   5. 【脱落した箇所】読んでいて意識が切れかけた箇所があれば、その一文
   ```

4. **改稿** — 判定が「通り過ぎる」または引きの強さが 7 以下なら、**可視ブロックの終わり方**を中心に書き直す：
   - 【残った謎】が「なし」→ 可視ブロック内に**答えのない問い・宣言**を作り、答えは折り返しの向こうへ送る
   - 切れ位置が語の途中・説明の途中 → 語順や文の長さを調整し、**謎・宣言・数字の直後**に切れ位置が来るようにする
   - 【脱落した箇所】→ その一文を短くするか、可視ブロックの外へ送る
   - **事実（数値・固有名詞・因果関係）は変えない。全体の字数制約は呼び出し元の spec.md に従う。**

5. **収束ループ** — 改稿後に可視ブロックを取り直して 3 を再実行する（読者役は**毎回新しいサブエージェント**）。
   - **終了条件**: 判定が「押す」かつ引きの強さ 8 以上、かつ【残った謎】が1つ以上ある
   - **最大3ループ**。3回で収束しない場合は警告付きで出力し、判断をユーザーに委ねる

### 出力形式（折り返しモード）

```
[最終原稿]

{改稿後の本文（全文）}

[/最終原稿]

[折り返しチェックサマリー]

可視ブロック: {N} weight / 切れ位置: 「…{切れ目直前15字}」｜「{切り捨て側先頭15字}…」

| ループ | 判定 | 引きの強さ | 残った謎 |
|---|---|---|---|
| 1回目 | 通り過ぎる | 5/10 | なし |
| 2回目 | 押す | 9/10 | 2件 |

改稿した点:
- {before} → {after}

[/折り返しチェックサマリー]
```

未収束の場合は冒頭に警告を付す：

```
⚠️ 折り返しの引きが3ループで基準に届きませんでした（判定: {判定} / 引き: {N}/10。人手レビュー推奨）
```

## 禁止事項

- 読者役エージェントに制作文脈（ネタ元・意図・過去の版・チェック履歴）を渡さない
- **折り返しモードで、可視ブロックより後ろの本文を読者役に渡さない**（続きを知った読者は判定できない）
- 事実（数値・固有名詞・因果関係）を変えない
- 字数などフォーマット制約を破らない（呼び出し元の spec.md に従う）
- 読者役の疑問に「本文の外」で答えない（チャットで説明しても投稿の読者には届かない。答えは必ず本文に埋め込むか、字数上入らなければ割愛の判断を明記する）
