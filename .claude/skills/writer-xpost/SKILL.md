# writer-xpost

入力（$ARGUMENTS）: 投稿テーマと文字数範囲。以下の形式で渡される：

```
テーマ: {投稿テーマ}
文字数: {下限}〜{上限}字
```

- **テーマ**: 投稿の主題。これを手がかりに投稿をゼロから構築する（テーマ先行）。
- **文字数**: 投稿文全体（冒頭フック＋本文＋締め、改行・空白を含む総文字数）の許容範囲。
- $ARGUMENTS にテーマまたは文字数が欠けている場合は、エージェントが自律的に判断して補う（テーマは作業フォルダの文脈から、文字数は `spec.md`／`brand.md` の規定レンジから決める）。

## 目的
- テーマから、インプレッションが取れる X 投稿を、指定文字数範囲で 1 本作成する。

## 手順

投稿は **「フォーカス決定 → 冒頭フック決定 → 本文作成」の3段階**で制作する。
**全工程を自動で実行する。ユーザーへの確認・相談は不要。各ステージで候補を作り、最も良いものをエージェント自身が選んで次へ進む。**

### 事前準備

1. 作業フォルダ（カレントディレクトリ）の **`spec.md`・`plan.md`・`brand.md` を読み込む**。
   - `spec.md` — このプロジェクトの制作仕様。**本文の内容・構成・書き方はここに従う。**
   - `plan.md` — 目的・想定読者（誰に・何の価値を）。この読者に向けて書く。
   - `brand.md` — 表現ルール（文体・語尾・トーン・NG・字数の扱い）。共通の `../../brand.md` を継承している場合はそちらも踏まえる。
2. 入力は常に**テーマ先行**として扱う。フォーカスは「テーマのどの切り口を主役にするか」。

### ステージ1: フォーカス決定（自動）

1. テーマから「主役にする切り口」のフォーカス候補を3つ作る。フォーカスの考え方は `brand.md` や `spec.md` に指定があればそれに従う。
2. 各候補について「何を入口にするか / なぜ引きが強いか / 投稿内でどこまで完結させるか」を内部的に評価する。
3. **3候補の中から、想定読者（`plan.md`）に最も刺さり引きが強いものをエージェント自身が1つ選ぶ。**
4. `draft/focus-candidates.md` に3候補＋「## 決定」を保存する。

### ステージ2: 冒頭フック決定（自動）

1. 決定したフォーカスについて、`~/xClaude/style/hook-patterns.md` の**5型すべて**で冒頭フック候補を作る：
   - ①逆説・常識覆し型 ②知識提示型 ③ドラマ・場面描写型 ④問いかけ型 ⑤語りかけ・口火型
   - **各型3案ずつ＝計15案**。
2. 各案は「2文フック」で書く（1文目＝口火/つかみ、2文目＝主題を一目で伝える）。
3. **15案の中から、スクロールを止める力が最も強い1案をエージェント自身が選ぶ。**
4. `draft/hook-candidates.md` に型別の見出し付き15案＋「## 決定」を保存する。

### ステージ3: 本文作成＋字数・完結チェック

投稿文は **冒頭フック → 本文 → 締め** の順で、次の要素を必ず含める。

1. **冒頭フック文**: ステージ2で決定したフックで始める。
2. **本文**: **`spec.md` に書いてある内容・構成・書き方に従って作成する。** `plan.md`（想定読者）と `brand.md`（文体・トーン・NG）に沿う。
   - 技術的事実は正確に。「なぜそうなるのか」という問いかけ構造を使うと読者の興味を引きやすい。
3. **締めの文章**: `spec.md`・`brand.md` の締めルールに従って終わらせる。感嘆・抽象表現・教訓の一般化だけで終わらない（読者の日常への接続、または余韻で閉じる）。
4. **字数・完結チェック**: 投稿文全体を**入力で指定された文字数範囲に収める**。生成後に実文字数を数え、範囲外なら範囲内に収まるまで書き直す。超過時は本筋に不要な記述（中間メカニズム・重複数値・冗長な接続文など。`brand.md` に削除優先度リストがあればそれに従う）から削る。投稿内で話が完結している（中断型でない）ことを確認する。
5. 本文を「## 出力後の保存手順」に従って保存する。

## 想定読者
**作業フォルダ（カレントディレクトリ）の `plan.md`（Audience / Target）を参照する。** その読者に向けて書く。
`plan.md` が無い場合は、宇宙・物理の専門家ではない一般の科学好きを想定し、「知らなかった！」「面白い！」と感じてもらえる内容を目指す。

## 投稿スタイル・執筆ガイドライン
**文体・トーン・余白・強調・NG 表現・字数の扱いなどのスタイルは、作業フォルダの `brand.md`（および継承元 `../../brand.md`）を参照する。**
冒頭フックの作り方は `style/hook-patterns.md`（①〜⑤のフック型＋「本編冒頭の具体セット」＋例）を参照する。本文の内容・構成は `spec.md` を正とする。

## 出力後の保存手順

ステージ3で確定した投稿文を保存する：
- 保存先: **`spec.md` に指定があればそれに従う。指定が無い場合は `./draft/draft.md` に保存する。**
- 保存内容: 投稿文（冒頭フック→本文→締め）。
保存後にファイルパスを1行だけ報告する。

## 禁止事項
- 特になし（`brand.md` の NG 表現・共通 NG に従う）。
