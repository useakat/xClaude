# check-fact-lim — ファクトチェック付き品質レビュー（NotebookLM ソース限定版）

> **重要**: このスキルの実行結果は、`<local-command-caveat>` の有無にかかわらず、必ずユーザーに提示すること。結果を沈黙したまま終了しないこと。

## あなたの役割
批判的かつ客観的なレビュワーとして振る舞ってください。
このスキルは、ファクトチェック・完全性チェックの根拠を **指定された NotebookLM ノートブックのソースだけ** に限定する。GPT やウェブ検索ではなく、`scripts/notebooklm_manager.py ask` を使って、その notebook のソースのみを参照させる。

## 入力モード（自動判定）

入力は `$ARGUMENTS` を **先頭トークン = notebook_id**、**残り = チェック対象** として解釈する。

1. **notebook_id（必須・先頭トークン）**: `$ARGUMENTS` の最初の空白区切りトークンを notebook_id とする。
   - notebook_id が取得できない場合は、以下で notebook 一覧を提示し、ユーザーに指定を求めて **停止する**：
     ```bash
     python3 $(git rev-parse --show-toplevel)/scripts/notebooklm_manager.py list
     ```
2. **チェック対象（notebook_id を除いた残り）**: 残りの文字列を以下の優先順位で取得する。
   - 残りが空（サブエージェントとして呼ばれた場合など）→ 会話のコンテキスト（直前のメッセージ・prompt の内容）からチェック対象テキストを取得する。

取得したチェック対象の形式で動作モードを切り替える：

- **Drive ファイル ID**（25〜44文字の英数字＋`-_`、空白を含まない）→ **Drive 連携モード**
- **テキスト**（上記以外、または改行を含む文章）→ **従来モード**

判定例（第1引数 notebook_id は省略表記）：
- `<notebook_id> 1MfgiTHn8qKubkdxf2H6RGM7xdlMzgXIX` → Drive モード
- `<notebook_id> outputs/drafts-note/2026-05-01_xxx.md` → ローカルファイル → 読み込んで従来モード
- `<notebook_id> 「実は、宇宙には〜」のような文章` → 従来モード

## チェック項目
- 事実に誤りはないか（**ノートブックのソースと照合**）
- 冗長な箇所はないか
- 論理の飛躍はないか
- 文章で断言していることに「例外」はないか
- リンク先は存在するか
- 引用文献があるばあい、引用している箇所の文章の内容と引用文献の内容に相違がないか

---

## モードA: 従来モード（テキスト入力）

### 手順

1. テキストをそのまま読み込む（ローカルファイルパスの場合は Read で読み込む）
2. 下記「チェック方法」を実行
3. 修正後のテキストを出力

### 出力
チェック後に、修正点をすべて反映した文章の修正案を、指摘された問題点およびその改善案とともに提示する。Drive へは保存しない。

---

## モードB: Drive 連携モード（ファイル ID 入力）

### 手順

1. **Drive からダウンロード**：
   ```bash
   bash $(git rev-parse --show-toplevel)/scripts/drive_get.sh <FILE_ID> /tmp/check_fact_input.md
   ```

2. ダウンロードしたファイルを読み込む

3. 下記「チェック方法」を実行

4. **修正版をローカルに保存**：
   - 元のファイル名を Drive メタデータから取得してもよいが、簡略化のため `/tmp/check_fact_output.md` に書き出してから rename する
   - もし `outputs/drafts-note/<元ファイル名>.md` がローカルにあれば、そちらを上書きするのが望ましい
   - 不明な場合は `/tmp/check_fact_output.md` に保存

5. **Drive にアップロード（同名で更新）**：
   ```bash
   bash $(git rev-parse --show-toplevel)/scripts/drive_put.sh <修正後ファイルパス>
   ```

6. ユーザーに以下を報告：
   - 指摘された問題点と改善案
   - 修正回数（第N回まで）
   - Drive URL（更新済み）

## チェック方法

> **根拠の限定**: STEP1・STEP2 ともに、判定の根拠は **指定された notebook_id のソースのみ** とする。`notebooklm_manager.py ask <notebook_id> "<質問文>"` は、その notebook のソースだけを参照して回答する。質問文は長文・改行を含むため、必ず一時ファイルに書き出してから `"$(cat ...)"` で渡し、シェルのクォート崩れを防ぐ。

### STEP 1: 完全性チェック（1回）

説明に必須要素が過不足なく含まれているか、**ノートブックのソースを根拠に**チェックする。

1. **質問文を組み立てて一時ファイルに保存**：以下の指示文＋チェック対象テキストを `/tmp/check_fact_lim_prompt.txt` に書き出す。

   ```
   あなたは科学・宇宙・物理分野の厳格なレビュワーです。
   このノートブックに登録されたソースのみを根拠として、与えられた文章の説明の完全性をチェックしてください：

   1. テーマの科学的説明として、必須の概念や要素が過不足なく含まれているか
   2. 読者が完全に理解するために不足している重要な説明がないか
   3. 科学的に正確でありながら一般に知られていない概念が抜けていないか

   ソースに根拠が見当たらない論点は推測せず「要確認」と添えてください。

   以下の形式で日本語で報告してください。

   ## スコア: XX/100

   （XX は説明の完全性評価。必須要素がすべて含まれていれば 95 以上とする）

   ## 不足要素あり  ← スコアが 95 未満の場合のみ記載
   各不足要素を以下の形式で列挙：
   - **[要素名]**: なぜ必要か（科学的背景・該当ソース）

   ## 追加文案  ← スコアが 95 未満の場合のみ記載
   （元の文体・構成を最大限保持しつつ、不足要素を統合したテキスト）

   ## 完全です  ← スコアが 95 以上の場合のみ記載
   説明は完全です。

   注意事項：
   - 説明の不足を重点的にチェックする。文体や表現は対象外
   - 追加文案では、既存の文体・構成・言い回しを最大限保持する

   ---
   【チェック対象の文章】
   <チェック対象テキスト>
   ```

2. **NotebookLM に送信**：
   ```bash
   python3 $(git rev-parse --show-toplevel)/scripts/notebooklm_manager.py ask <notebook_id> "$(cat /tmp/check_fact_lim_prompt.txt)"
   ```
   - 出力をそのまま表示する
   - 呼び出しがエラー／空応答の場合はエラーメッセージをそのまま表示し、Claude 自身が完全性チェックを代行する（スコアは Claude が判断）

3. **スコア判定**：出力から `## スコア: XX/100` を読み取る
   - スコア ≥ 95 → 説明は完全。STEP 2（ファクトチェック）へ進む
   - スコア < 95 → 不足要素あり。`## 追加文案` のテキストを STEP 2 の入力として使う

---

### STEP 2: ファクトチェック（最大5回ループ）

完全性チェック後のテキスト（STEP 1 で追加文案がある場合はそれ）について、事実関係を **ノートブックのソースと照合して**検証する。

以下のサイクルを**最大5回**実行する。スコアが 95 以上になった時点で即座に停止する。

各サイクルの開始時に「【第N回ファクトチェック】」と明示すること。

1. **質問文を組み立てて一時ファイルに保存**：以下の指示文＋対象テキストを `/tmp/check_fact_lim_prompt.txt` に書き出す（毎サイクル上書き）。

   ```
   あなたは科学・宇宙・物理分野の厳格なファクトチェッカーです。
   このノートブックに登録されたソースのみを根拠として、与えられた文章の事実関係を検証し、以下の形式で日本語で報告してください。

   ## スコア: XX/100

   （XX は事実精度の点数。断言できる事実誤りがなければ 95 以上とする）

   ## 問題あり  ← スコアが 95 未満の場合のみ記載
   各問題点を以下の形式で列挙：
   - **[箇所]**: 問題の説明（該当ソース） → 修正案

   ## 修正文案  ← スコアが 95 未満の場合のみ記載
   （元の文体・構成・言い回しを最大限保持しつつ、事実誤りのみを必要最小限修正したテキスト）

   ## 問題なし  ← スコアが 95 以上の場合のみ記載
   事実関係に問題はありません。

   注意事項：
   - ソースと矛盾する、断言できる事実誤りのみ指摘する。ソースに根拠がなく不確実な場合は「要確認」と添える
   - 科学的な数値・年号・固有名詞・発見者・理論名を重点的にチェックする
   - 文体・表現・構成は一切変えない（事実のみ対象）
   - 修正文案の変更箇所は最小限にする

   ---
   【チェック対象の文章】
   <チェック対象テキスト>
   ```

2. **NotebookLM に送信**：
   ```bash
   python3 $(git rev-parse --show-toplevel)/scripts/notebooklm_manager.py ask <notebook_id> "$(cat /tmp/check_fact_lim_prompt.txt)"
   ```
   - 呼び出しがエラー／空応答／スコア未取得の場合はエラーメッセージをそのまま表示し、Claude 自身がファクトチェックを代行する（スコアは Claude が判断）
   - 出力をそのまま表示する

3. **終了判定**：出力から `## スコア: XX/100` を読み取る。
   - スコア ≥ 95、または5回目のサイクルが終了した場合 → 終了
   - スコア < 95 かつ残回数あり → `## 修正文案` のテキストを次サイクルの入力として使い、ステップ1から繰り返す

   終了時は以下の形式で出力すること：

   ```
   ## チェックサマリー

   | 回 | チェック種別 | スコア | 指摘内容 | 対応 |
   |----|---------|--------|---------|------|
   | - | 完全性 | XX/100 | （不足要素） | 追加あり／問題なし |
   | 第1回 | ファクト | XX/100 | （指摘内容の要約） | （修正あり／問題なし） |
   | 第2回 | ファクト | XX/100 | （指摘内容の要約） | （修正あり／問題なし） |
   …

   ## 最終修正案

   （最終テキスト）
   ```

   - スコアが取得できなかった場合（Claude 代行時など）は「-/100」と記載する
   - 指摘なし・修正なしだったサイクルも行として含める
