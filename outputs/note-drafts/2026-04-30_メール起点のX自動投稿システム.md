# Gmailに送るだけ——X自動投稿システムの作り方

SNSの投稿を毎日続けるのは思ったより手間がかかる。特に「画像付き」「スレッド形式」となると、ツールを開いて、貼り付けて、送信して……という作業が積み重なる。

この記事では、**Gmailに決まった形式のメールを送るだけで、指定した時刻にXへ自動投稿される**仕組みの作り方をまとめる。Pythonとシェルスクリプト、Claude CLIを組み合わせて構築した。

---

## 全体の仕組み

```
[原稿メール送信] → [Gmail受信]
                        ↓
               [定時 cron 起動]
                        ↓
             [Claude CLI が処理]
           ┌─────────────────────┐
           │ ① Gmailを検索       │
           │ ② 投稿文を抽出      │
           │ ③ 添付画像をDL      │
           │ ④ X APIで投稿       │
           │ ⑤ ラベル付け・archive│
           │ ⑥ 投稿URLを記録     │
           └─────────────────────┘
```

メールには決まったタグで本文を囲む。それだけ。Claude CLIがGmail MCPとBashを組み合わせて処理を全自動化している。

---

## メールのフォーマット

件名に識別キーワードを入れる。

```
件名: 【ワンポイント解説】脳は自分の痛みを感じない
```

本文には以下のタグを使う。

```
[投稿文]
Xに投稿したいテキストをここに書く。
[/投稿文]

[リプ]
スレッドの2ツイート目（セルフリプライ）に投稿したい内容。
省略可。
[/リプ]
```

画像を添付すれば、自動的に画像付き投稿になる。

## 構成ファイル

```
xClaude/
├── scripts/
│   ├── post_from_email.sh           # メイン処理（汎用）
│   ├── run_xonepoint_post.sh        # ワンポイント解説用（毎朝6時）
│   ├── run_question_post.sh         # 質問回答用（毎日12時）
│   ├── post_to_x.py                 # X API投稿スクリプト
│   ├── download_gmail_attachment.py # Gmail添付ファイルDL
│   └── record_output.py             # 投稿URLの記録
├── database/
│   └── outputs.csv                  # 投稿ログ
└── gcp/
    └── gmail_token.json             # Gmail OAuth2トークン
```

## 各スクリプトの役割

### `post_from_email.sh`（メイン処理）

```bash
bash post_from_email.sh <件名キーワード> <howID> <ログファイル名>
```

内部では `claude -p`（非対話モード）でClaude CLIを呼び出す。ClaudeがGmail MCPとBashツールを使いながら以下を順番に実行する。

1. **Gmail検索** — `subject:キーワード -label:投稿済み` で未処理メールを全件取得
2. **最古のメールを選択** — 複数ある場合は受信日時が最も古い1件を処理（FIFOで処理できる）
3. **テキスト抽出** — `[投稿文]`/`[/投稿文]` と `[リプ]`/`[/リプ]` をパース
4. **添付画像のダウンロード** — Gmail APIで画像を `/tmp/xpost_image.png` に保存
5. **X投稿** — `post_to_x.py` を呼び出してツイート。`[リプ]` があればtweetIDを取得しセルフリプとして続けて投稿
6. **ラベル付け＆アーカイブ** — `投稿済み` ラベルを付けてINBOXから削除
7. **投稿記録** — `database/outputs.csv` にURL・日時・種別を記録

### `run_xonepoint_post.sh`（cron用ラッパー）

```bash
#!/bin/bash
exec /bin/bash "$(dirname "$0")/post_from_email.sh" "【ワンポイント解説】" W003 x_post_xonepoint.log
```

`post_from_email.sh` に引数を渡すだけのラッパー。新しい種類の定時投稿を追加したいときも、同じ形でラッパーを作れば済む。

### `post_to_x.py`

tweepyを使い、X API v1.1（メディアアップロード）とv2（ツイート投稿）を組み合わせている。

```python
python3 post_to_x.py --text "投稿テキスト"
python3 post_to_x.py --text "投稿テキスト" --image /path/to/image.png
python3 post_to_x.py --text "リプ文" --reply-to <tweet_id>
python3 post_to_x.py --dry-run --text "テスト"
```

`--dry-run` フラグで実際には投稿せずに動作確認できる。

### `download_gmail_attachment.py`

Gmail API（OAuth2）で指定メッセージの添付画像を取得する。Claude MCPはファイルのダウンロードに対応していないため、このスクリプトで補完している。

```python
# 画像があれば exit 0、なければ exit 1
python3 download_gmail_attachment.py <message_id> /tmp/xpost_image.png
```

## cron の設定

```bash
# 毎朝6時（JST）にワンポイント解説を投稿
0 21 * * * /bin/bash /root/xClaude/scripts/run_xonepoint_post.sh

# 毎日12時（JST）に質問回答を投稿
0  3 * * * /bin/bash /root/xClaude/scripts/run_question_post.sh
```

サーバーのタイムゾーンがUTCのため、JSTより9時間引いた時刻を指定している。

## 認証の準備

### X API（tweepy）

`.env` ファイルに以下を設定する。

```
X_OAUTH_CONSUMER_KEY=...
X_OAUTH_CONSUMER_SECRET=...
X_OAUTH_ACCESS_TOKEN=...
X_OAUTH_ACCESS_TOKEN_SECRET=...
```

### Gmail API（添付ファイル取得用）

Gmail APIの有効化とOAuth2クライアントIDの作成が必要。ブラウザが使えないサーバー環境では、以下のように手動で認証URLを生成してトークンを取得する。

```python
from google_auth_oauthlib.flow import InstalledAppFlow
from google.oauth2.credentials import Credentials
import requests, json, webbrowser

SCOPES = ["https://www.googleapis.com/auth/gmail.readonly",
          "https://www.googleapis.com/auth/gmail.modify"]

# OAuth URLを直接構築（PKCE不使用）
flow = InstalledAppFlow.from_client_secrets_file("gcp/gmail_oauth_client.json", SCOPES)
flow.redirect_uri = "urn:ietf:wg:oauth:2.0:oob"
auth_url, _ = flow.authorization_url(prompt="consent")
print(auth_url)

# → ブラウザでURLを開いてコードを取得
code = input("コード: ")
flow.fetch_token(code=code)
Path("gcp/gmail_token.json").write_text(flow.credentials.to_json())
```

### Gmail MCP（ラベル操作用）

Claude.ai の設定画面でGmail MCPコネクタを接続する。`gmail.modify` スコープが必要（デフォルトでは読み取り専用の場合がある）。

## スレッド投稿（セルフリプライ）

メール本文に `[リプ]` タグを追加するだけで、スレッドの2ツイート目を自動投稿できる。

```
[投稿文]
脳は自分自身の痛みを感じない。

手術中に患者を起こして話しかけながら進める「覚醒下手術」が存在するのはそのためだ。
[/投稿文]

[リプ]
ちなみに「頭痛」は脳が痛んでいるわけではない。

血管・筋肉・髄膜・神経——痛みに敏感な周辺組織が刺激されて起きている。

全身の痛みを処理する司令塔が、自分は痛みを感じない。
人体の設計、不思議すぎる。
[/リプ]
```

システム内部では、`[投稿文]` 投稿後にtweetIDを取得し、`--reply-to` オプションで続けてリプライとして投稿している。

## 投稿ログ

投稿のたびに `database/outputs.csv` に記録が追記される。

```csv
dateTime,URL,howID
2026-04-26 06:01:23,https://x.com/i/web/status/1234567890,W003
2026-04-27 12:02:11,https://x.com/i/web/status/1234567891,W006
```

`howID` は投稿の種別（W003=ワンポイント解説、W006=質問回答など）。後で分析したいときに使う。

---

## よかった点・工夫した点

**汎用化**：投稿の種類ごとにスクリプトを作らず、`post_from_email.sh` を共通処理として汎用化した。新しい定時投稿を追加するときは、ラッパースクリプト1本書くだけで済む。

**FIFOで処理**：複数の未投稿メールが溜まっていても、一番古いものから順番に処理する。投稿したいタイミングで書いたものが、そのまま時系列で流れていく。

**dry-run**：`--dry-run` フラグで実投稿なしにテストできる。デバッグが楽になった。

**Claude CLIの非対話モード**：`claude -p` で使うことで、cronから呼び出せる。`--allowedTools` で使えるツールを明示的に絞っている。

---

## まとめ

「Gmailに送るだけ」というシンプルなインターフェースで、X投稿を完全自動化できた。

原稿はスマホでも書けるし、画像も添付するだけ。スレッド投稿も `[リプ]` タグを足すだけで対応できる。投稿日時はcronで管理するので、朝に原稿を仕込んでおけば夜中に考える必要もない。

仕組みとしては地味だが、毎日続ける上での「ちょっとした手間」を取り除くことが大事だと思っている。続けやすい仕組みを作ること自体が、発信を続ける上での大きな一歩になる。
