# Claude Code と Google Drive で「note 記事を書く仕組み」を作った話

note の記事を書くたびに、毎回同じことで時間を使っていた。

「ネタを選ぶ」「構成を考える」「6000字書く」「事実確認する」「ハッシュタグを選ぶ」「投稿する」。一つひとつは大したことがないのに、全部つなげると半日が溶ける。

Claude Code（Anthropic の CLI 型 AI コーディング環境）と Google Drive を組み合わせて、この一連を **「AI が書く部分」と「自分が判断する部分」** に分離する仕組みを作った。完成してから一週間ほど運用しているが、思ったよりも楽になった。

## 何を作ったか

ざっくり以下の流れを、3つの skill と 2つのヘルパースクリプトで自動化した。

```
[writer-note] 構成→本文執筆→演出セルフチェック→ファクトチェック→保存→Drive アップロード→完了通知メール
                                                                                          ↓
[ユーザー]                                                                  Drive で内容を確認・編集
                                                                                          ↓
[check-fact <ファイルID>]                                                  DL→再ファクトチェック→Drive 更新
                                                                                          ↓
[ユーザー]                                                                  Drive で最終確認
                                                                                          ↓
[hashtag-note <ファイルID>]                                                DL→ハッシュタグ選定→末尾追記→Drive 更新
                                                                                          ↓
[ユーザー]                                                                  note にコピペ投稿
```

要するに、**Drive 上のひとつの markdown ファイルを中核にして、AI と人間が交互にそれを更新していく**設計だ。

---

## なぜ Drive を中核にしたか

最初は「Google Docs を中核にしようか」と考えた。共同編集ができるし、バージョン履歴も残るし、スマホからも読める。

ただ、**markdown と Google Docs の往復は可逆ではない**。見出しや太字、リスト、コードブロックを Docs に変換して、そこをユーザーが編集して、また markdown に戻すと、書式の細部が崩れる。「AI が書いた markdown を Docs に変換 → 編集 → markdown に戻す」みたいな処理を毎回挟むのは、見えないところで疲弊が溜まる。

そこで、**markdown のまま Drive にファイルとして置く**方式にした。Drive のテキスト編集 UI で読めるし、スマホでも開ける。書式はずっと markdown のまま、ロスゼロ。

## 中核の3 skill

### writer-note：構成案 → 本文 → 自動ファクトチェック → 保存 → Drive アップロード → メール通知

ネタは Google Sheets に蓄積している「未使用」フラグのついたものから選ぶ。一回の起動で「構成案を出す → ユーザー承認 → 本文執筆 → 6000字チェック → 演出セルフチェック → ファクトチェック → ローカル保存 → Drive アップロード → 完了メール送信」までを一気通貫でやる。

ファクトチェックは別 skill（check-fact）の手順を内部で参照する形にして、コードの重複を避けた。「最終版になるまで保存もアップロードもしない」というのが地味に重要で、途中の汚いバージョンが Drive に上がらないようにしている。

完了メールには **Drive URL とファイル ID と次のアクション** が書かれている。スマホに通知が来るので、外出先でも「次は Drive を確認して check-fact を回す」というのが分かる。

### check-fact：テキスト/Drive ID の自動分岐

事実確認の skill。引数の形式で2つのモードに自動分岐する。

- **テキスト入力**：従来動作（修正版を返すだけ）
- **Drive ファイル ID 入力**：Drive からダウンロード → 修正 → Drive を更新

writer-note の内部ファクトチェックでは「テキスト入力モード」が呼ばれる。一方、ユーザーが Drive で編集した後に再チェックしたいときは「Drive ID モード」を使う。

最大5回ループで「事実誤り・冗長・論理飛躍・例外の見落とし・引用と本文の不一致」を潰す。問題ゼロになった時点で抜ける。

### hashtag-note：3モード（note 記事 ID / Drive ファイル ID / テキスト）

note のハッシュタグ辞書（PDF）を読み込み、記事内容に合うタグを選ぶ skill。

- **note 記事 ID**：すでに公開された記事を取得して分析（タグ追記なし）
- **Drive ファイル ID**：Drive からダウンロード → タグ選定 → 末尾追記 → Drive 更新
- **テキスト**：内容を見てタグ候補を返すだけ

選定ロジックは「お題タグから2つ」「カテゴリ別タグから関連するもの全部」「共起タグマップから派生」の3段構え。スパム判定を避けるため、関連性の薄いタグは入れない。

## ヘルパースクリプト2本

skill たちが共通で使う Drive I/O。

- `drive_put.sh <local-file>`：ローカルの markdown を Drive の `drafts-note` フォルダにアップロード。**同名ファイルがあれば更新**（Drive のリビジョン履歴が残る）
- `drive_get.sh <file-id> <output-path>`：Drive ファイル ID 指定でダウンロード

中身は `gws` CLI（Google 公式の Workspace CLI）を呼んでいるだけだが、「同名ならリビジョン更新、なければ新規作成」のディスパッチをスクリプト側で吸収しているので、skill 側の記述がシンプルに保てる。

## 運用してみての感想

### 良かったこと

- **Drive をスマホで開ける**ので、執筆途中の原稿を電車の中で読み返してメモを Drive UI から書き込める。「ローカル PC を立ち上げないと進まない」状態から脱した
- **完了メールが来る**ので、AI に投げて他の作業をしていても、終わったタイミングで自然に戻ってこれる
- **ファクトチェックが自動でかかる**ので、「書きっぱなしで雑な原稿が Drive に上がる」ことがない
- **ファイル名と Drive リビジョンで履歴が追える**ので、自分の修正と AI の修正が混ざっても遡れる

### まだ詰めきれていないこと

- ハッシュタグの追記は markdown 末尾に「`<!-- ハッシュタグ -->`」コメント付きで入れているが、note にコピペするときに少し手間がかかる
- Drive 上で大幅に書き換えた後の二回目 check-fact は、AI の修正と自分の修正がぶつかることがある（マージ判断は結局自分でやる）
- 画像挿入はまだ仕組みに入っていない（インフォグラフィックは別 skill で作っているが、本文との結合は手動）

## 設計の核：「skill は薄く、データは Drive、人間は判断だけ」

3つの skill それぞれは、内部処理が単機能で薄い。複雑な状態管理は Drive 上の markdown ファイル一枚に集約している。

人間がやることは「構成案に OK を出す」「Drive 上で気になる箇所を編集する」「最後に note に投稿する」の3つだけ。**選び、判断する仕事だけが残る**。書く・チェックする・タグを付ける、という機械的な作業は AI 側に渡せる。

「AI に任せる」と「自分で書く」の中間がほしかった。書きっぱなしを AI に任せるのは怖いし、全部自分で書くのは時間がない。中間の落としどころは、**「最終的な意思決定だけ自分の手元に残す」** だった。

実装してから自分の note 記事の更新ペースが少し上がった。半日溶けていた工程が2時間くらいで回るようになった気がする。
