# X（旧Twitter）For You アルゴリズム 解説報告書

**作成日**: 2026-05-16  
**情報源**: `https://github.com/xai-org/x-algorithm` リポジトリのソースコードのみ  
**注意**: 本報告書に記載の内容はコードから読み取れる事実に限定しており、X社の公式発表や外部情報は含まない。

---

## 1. システム全体構成

X の For You フィードは複数のサービスが連携して生成される。

```
スマホ/PC
    ↓ HTTPS リクエスト
Home Mixer（オーケストレーター）
    ├── Thunder      ← フォロー中の最新ポスト取得
    ├── TweetMixer   ← ネットワーク外ポスト取得
    ├── Phoenix      ← ML ベース検索・ランキング
    └── Kafka        ← リアルタイムイベントバス
```

スマホ上にアルゴリズムは存在しない。すべてサーバー側で完結する。

---

## 2. 各コンポーネントの役割

### 2-1. Thunder（インネットワーク取得）

フォロー中アカウントの最新ポストを高速に返す**リアルタイム in-memory キャッシュ**。

**仕組み**
- Kafka からツイートイベント（投稿・削除）を常時購読
- ポストをサーバーの RAM 上に保持
- gRPC サービスとして動作し、Home Mixer からのリクエストに応答

**保持するデータの構造**

| マップ名 | 内容 |
|---|---|
| `original_posts_by_user` | 通常投稿（リプライ・RTでないもの） |
| `secondary_posts_by_user` | リプライ・リポスト |
| `video_posts_by_user` | 動画を含む投稿 |

**制約**
- デフォルト保持期間: **2日間**（`retention_seconds = 2 * 24 * 60 * 60`）
- 著者ごとに上限あり（`MAX_ORIGINAL_POSTS_PER_AUTHOR` 等・実数値は非公開）
- 古いポストは2分ごとに自動削除（`start_auto_trim`）

**Thunder の限界**  
全アカウントの全投稿ではなく、「直近2日以内に投稿したアカウントの最近N件」のみを保持する。X の規模では複数台に分散して動作していると考えられる。

---

### 2-2. Grok（Transformer アーキテクチャ）

Phoenix の内部で使われる**ニューラルネットワーク本体**（`grok.py`）。

- Multi-Head Attention + RoPE（回転位置エンコーディング）
- Decoder Layer 構成
- 推薦用の特殊アテンションマスクを実装  
  （候補ポスト同士はお互いに attention しない → 独立スコアリング）

---

### 2-3. Phoenix（ML 検索・ランキング）

Grok を backbone とした**推薦モデル**。**検索（Retrieval）**と**ランキング（Ranking）**の2段階で動作する。

#### 検索フェーズ（2タワーモデル）

```
ユーザー行動履歴（最大128件）
    → User Tower（Transformer）
    → ユーザーベクトル [D次元]
            ↓ 内積
コーパス（事前計算済みポスト埋め込み群）[N×D]
            ↓
        上位K件を返す（ANN 近似最近傍探索）
```

- コーパスはフォロー外のポストも含むが、**フォロー中ポストを明示的に除外していない**
- コーパスの保持期間はこのリポジトリには記載なし
- Phoenix のスコアリングモデルに `POST_AGE_MAX_MINUTES = 4800`（80時間 ≈ 3.3日）という年齢上限が定義されている

#### ランキングフェーズ

Transformer に以下を連結して入力する：

```
[ユーザートークン 1件]
 + [行動履歴 最大128件]
 + [候補ポスト 最大32件]
→ 候補ごとにエンゲージメント確率を出力
```

---

### 2-4. Home Mixer（オーケストレーター）

6つのソースから候補を収集し、フィルタリング・スコアリング・選択を行う。

**候補ソース一覧**

| ソース名 | 内容 | 有効条件 |
|---|---|---|
| `ThunderSource` | フォロー中の最新ポスト | `has_cached_posts` でないとき |
| `TweetMixerSource` | ネットワーク外推薦 | `in_network_only` でなく `has_cached_posts` でないとき |
| `PhoenixSource` | Phoenix 検索結果 | `in_network_only` でなく `has_cached_posts` でないとき |
| `PhoenixTopicsSource` | トピックベース検索 | トピックリクエスト時 |
| `PhoenixMOESource` | MoE モデル検索 | 設定による |
| `CachedPostsSource` | キャッシュ済み候補 | `has_cached_posts` のとき |

**処理フロー**

```
候補収集（6ソース）
    ↓
フィルタリング
    - AgeFilter（古すぎるポストを除去）
    - DropDuplicatesFilter（重複 tweet_id を除去）
    - VFFilter（安全性ラベルチェック）
    - MutedKeywordFilter（ミュートワード）
    - その他多数
    ↓
スコアリング
    - PhoenixScorer（ML 予測スコア取得）
    - WeightedScorer（重み付きスコア計算）
    - OONScorer（ネットワーク外ペナルティ）
    - AuthorDiversityScorer（著者多様性補正）
    ↓
選択・出力
```

---

### 2-5. Kafka（イベントバス）

X 上のすべてのイベント（投稿・削除など）をリアルタイムに流す**メッセージバス**。

- 誰かが投稿 → Kafka トピックにメッセージが積まれる
- Thunder・検索サービス・通知サービスなど複数のサービスが同じメッセージを受信できる
- **クラスター**構成（複数台冗長化）で1台故障しても止まらない

Thunder は Kafka を常時ポーリングし、新着ポストを即座にメモリに反映する。

## 3. スコアリングの詳細

### 3-1. Transformer への入力（行動履歴）

ユーザーの過去行動（最大128件）が入力される。入力されるアクション種別：

**離散アクション（18種）**

| カテゴリ | アクション |
|---|---|
| ポジティブ | いいね、リプライ、リポスト、引用RT、クリック、プロフィールクリック、写真展開、動画視聴(VQV)、シェア、DM共有、リンクコピー、滞在(dwell)、フォロー |
| ネガティブ | 興味なし、ブロック、ミュート、報告 |
| その他 | 引用RTクリック |

**連続アクション（8種）**

`dwell_time`（滞在時間）、`video_watch_time`（動画視聴時間）、`scroll_depth`（スクロール深度）など。

### 3-2. 重み付きスコア計算式

```
score = Σ (予測確率 × 重み)

= p(いいね) × FAVORITE_WEIGHT
+ p(リプライ) × REPLY_WEIGHT
+ p(リポスト) × RETWEET_WEIGHT
+ p(引用RT) × QUOTE_WEIGHT
+ ...（ポジティブ）
+ p(興味なし) × NOT_INTERESTED_WEIGHT   ← 負の値
+ p(ブロック)  × BLOCK_AUTHOR_WEIGHT    ← 負の値
+ p(ミュート)  × MUTE_AUTHOR_WEIGHT     ← 負の値
+ p(報告)     × REPORT_WEIGHT          ← 負の値
```

**重要**: 各アクションの重みの実数値（`params.rs`）は**非公開**でこのリポジトリには含まれない。「Replies > 引用 > リポスト > いいね」という序列はコードからは確認できない。

### 3-3. 追加スコア補正

**OON スコア補正**（`oon_scorer.rs`）  
フォロー外のポストには `OON_WEIGHT_FACTOR` を乗算してスコアを下げる。フォロー中のポストは減点なし。

**著者多様性補正**（`author_diversity_scorer.rs`）  
同一著者の2件目以降のポストにペナルティを適用する。スコアが高い順に処理するため、同一著者の中で最もスコアが高い1件のみがフルスコアを維持する。この処理は1回のフィード生成リクエスト内でのみ適用される。

**動画スコア特例**（`weighted_scorer.rs`）  
`MIN_VIDEO_DURATION_MS` を超える長尺動画のみ `VQV_WEIGHT` が適用される。短い動画はこの重みが0。

## 4. このリポジトリからわかること・わからないこと

### わかること

- システム全体のアーキテクチャと各コンポーネントの役割
- 候補ソースの種類と有効条件
- スコアリングに使われるアクション種別の一覧
- Thunder の保持期間（デフォルト2日）
- Phoenix スコアリングの年齢上限（80時間）
- ネガティブフィードバックがスコアを下げること
- ネットワーク外ポストがペナルティを受けること
- Phoenix がフォロー中のポストも返しうること

### わからないこと

| 項目 | 理由 |
|---|---|
| 各アクションの重みの実数値 | `params.rs` が非公開 |
| アクション間の優先順位（Reply > Quote > RT > Like など） | 重みが非公開 |
| OON_WEIGHT_FACTOR の値 | `params.rs` が非公開 |
| Phoenix コーパスの保持期間 | コーパス管理コードが非公開 |
| 外部リンク含有によるペナルティの有無 | コード内に該当ロジックなし（隠れている可能性は排除できない） |
| MAX_POST_AGE の実数値 | `params.rs` が非公開 |

## 5. 実用的な示唆

コードから読み取れる範囲で、For You に表示されやすくするための構造的事実：

1. **Thunder の保持期間は2日**。投稿後2日を超えるとフォロワーのフィードに候補として上がりにくくなる可能性がある。

2. **著者多様性補正がある**。1回のフィード生成で同一著者の複数ポストが候補に上がった場合、2件目以降はスコアが下がる。大量投稿よりも質の高い投稿1件の方が有利な設計になっている。

3. **ネガティブフィードバックはスコアを直接下げる**。ブロック・ミュート・「興味なし」・報告が多いとスコアが負方向に動く。

4. **フォロー外でもフォロー中でも同じ Transformer でスコアリングされる**。ソースの違いはスコアリングに影響しないが、フォロー外は OON ファクターで減点される。

5. **行動履歴128件が Transformer の入力**。ユーザーが最近どんなポストに反応したかが推薦に直接影響する。
