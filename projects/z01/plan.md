# Project Plan — X 短文投稿（Z01）

## Purpose

- **140 字テキストのみ**の投稿で、ネタに対する X での反応（いいね・ブクマ・引用RT・リプ）を観測する。
- 毎日の投稿頻度を上げ、X アカウントのアクティブさ（更新頻度・接触機会）を保つ。
- **反応の良かったネタを次の制作の起点にする**：手応えのあるネタを note 記事（W002）/ X 長文ストーリー（W001）/ ワンポイント解説（W003）へ昇格させる。
- W003（200〜300 字の作り込んだ解説）に対し、Z01 は**軽量・高頻度・低コスト**で「ネタの当たり外れ」を測る実験枠。

## Audience

- メインターゲットは W003 に準拠：**PE01 — 物理に憧れがあるが数式で挫折した文系会社員**（例: 中村美咲・32歳・メーカー総務・名古屋・独身）。
- 状態: 高校までは物理が好き。相対論・量子力学の本を開くと数式で挫折。Newton や Eテレは見る。知的好奇心は強いが、自分で深掘りする時間と余裕がない。
- 心理: 「文系だから無理」という諦めと、それでも惹かれる気持ちの板挟み。
- 接触: 朝の通勤電車（7:30〜8:15）・昼のカフェ・就寝前 23 時前後に X を流し見。リプより、いいね・ブクマで静かに反応する。
- 読む目的: 知的好奇心を満たす / 翌日の雑談ネタ / 静かな興奮。

## Offer

- 人に言いたくなるような宇宙・物理や科学の話を、**1 ツイートで完結**する形で手渡す。
- 直接の商品案内はしない（Z01 は本文の質と頻度でフォロー・信頼・反応データを得る短文投稿）。
- 中長期の導線: 反応の良かったネタを同じ価値観（執念・再挑戦）の **note 記事（W002）/ X 長文ストーリー（W001）/ ワンポイント解説（W003）** へ展開する。

## Deliverables

→ `spec.md` 参照（Media / Output / Format / Naming / Rules）。

## Success Criteria

- 毎日 1 本以上の継続投稿（投稿頻度・アクティブ維持）。
- ネタごとの反応データが蓄積され、**昇格候補ネタ**が特定できる。
- 反応の良いネタが W001 / W002 / W003 の制作に流れる。

## CTA（このプロジェクトのターゲットに取ってもらいたい行動）

- フォロー
- 引用RT・ブックマーク・いいね（明示的に誘導はしない。反応の多寡そのものがデータ）

## Risks（プロジェクトの失敗要因）

- **ファクトの弱さ**: 短文でも出典未確認・数値の曖昧表現は信頼毀損リスク。固有名詞・数値は事実ベースで書く。
- **量産による質低下**: 高頻度ゆえに使い回し・既出感が出やすい。冒頭フックと日常接続で差をつける。
- **反応の取りこぼし**: 反応データを記録・振り返らないと「実験枠」の意味が消える。良かったネタの昇格判断を定期的に行う。
