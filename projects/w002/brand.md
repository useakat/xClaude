# Project Brand — 困難を乗り越え成功した執念の物語の note 記事（W002）

## Inherits
- `../../brand.md`（共通ブランド定義：人格・温度感・1人称/2人称・共通NG）
- `../../style/story-check.md`（物語型推敲チェックリスト。採点基準の項目8が参照する）

固有ルールが共通定義と矛盾する場合は共通定義を優先する。本ファイルには W002 固有の方針のみ記す。

## Project Impression
- **「ガチな科学」×「中の人の泥臭いドラマ」**を、6000字超の物語として読ませる知的エンタメ。
- 科学の解説に見せて、語っているのは**人間の知性・執念・再挑戦**。読後に「諦めなくていい」と静かに背中を押す。
- 騒がしさ・煽りより、**落ち着いた驚きと余韻**を優先する。クライマックスで一気に感情を放出するメリハリ構造。
- 先輩が後輩に「これ、かなり震える話なんだけど」と熱を抑えながら語りかける距離感。
- 挫折経験のある読者（PE01/05/09）の劣等感を刺激しない。「文系でも分かる」と銘打たず、自然に分かる構造で書く。

## Visual Rules
- **余白**: 1 段落 1〜3 文。段落間は必ず空行。情景の転換・強調したい一文の前後は空行を厚く取る。
- **画像**: 各 H2 に画像案を添えてよい（実生成はスキルに委ねる）。
- **強調**: 太字は各節で本当に強調したい部分のみ（その段落の結論／歴史的意義／数値や到達点の重み／主題を要約する一文）。多用しない。

## Writing Rules

### 構成
- 導入部は **H1 直下から本文を始める**（H2を付けない）。ズラシの型で「えっ？」を作り、有料部分への期待で終える。
- 各 H2 末尾は `---` で区切り、次セクションへの橋渡しを一文残す（完結させきらない）。
- **H3 は使わない**。月別・時系列の進行も見出しで区切らず、散文の中で「8月、ついに〜が起きた」のように文中で時間を示す。
- 物語の基本形は「困難 → 工夫 → 逆転」。困難に立ち向かう「主人公」を立て、その判断・失敗・立て直しを軸にする。
- 締めは「意味の宣言」「感情」「未来へのまなざし」で終え、PR001 を解消する読後感（諦めなくていい）に着地する。

### タイトル
- 人目を引き、クリックしたくなる引きの強いものにする。
- **語尾は動詞で終わらない。** 体言止め・問いかけ・「〜の物語」「〜した話」で締める。

### ズラシの型（導入部で「えっ？」を作る）
- **スケールのズラシ**: 個人の話 vs 国家・地球・宇宙規模の話
- **時間軸のズラシ**: 今の話 vs 100年前の話
- **分野のズラシ**: 本題と構造が同じ異分野の事例から入る
- **立場のズラシ**: 賛成 vs 反対 →さらに一段掘る三段構造
- **感情のズラシ**: 論理的解説を予測させて、突然感情・五感の描写を差し込む

### 導入で使わない表現
- **概念ラベル語でまとめない**（「共生」「絆」などの漢語1語で結論づけない。読者が「よく分からない」と感じる）。何がどう関係するのかを、具体的な行為・現象で書く
- **記事の核心を先に言わない**（種明かしの禁止）。何が結末や仕掛けの答えにあたるかは agenda の難所マップ（読者の疑問・期待する種明かしリスト）で分かる。導入で該当箇所に触れる場合は、①抽象度を1段上げる（具体的な仕組み・固有名→一般的な言葉。例：「砂・風」→「環境」）か、②疑問形に変換する（「〜とは何だったのか」）
- **検証不能な誇張の定型句を使わない**（「世界中を泣かせた」「誰もが涙した」等。効果を測れない主観の誇張）

### 文体・語尾
- **常体（だ・だった・である）。ですます調・敬語は使わない。**
- 同じ語尾を3文以上続けない。`〜だ` `〜だった` を主軸に、要所で `〜である` `〜だろうか` `体言止め` を混ぜる。
- **短文の畳みかけ**: 緊張・転換・盛り上がりでは短文を3〜5本連打する。読点を控え句点で切る。
- 書き出しフック例: 「これ、かなり震える話。」「もっと知られていい話なんだけど、」「ここからの話が、めちゃくちゃ熱い。」
- **ひらがなに開くのは接続詞・助詞のみ。動詞・名詞は常用漢字で書く**（操る・速める・緩める・積む。「あやつる」「はやめる」はNG）。
- 雅語・詩語より平明な日常語を選ぶ（「かげる」→「弱くなる」）。
- **隣接する段落の頭を、同種の接続詞で始めない**（「しかし〜」の次の段落を「しかも〜」で始める等。逆接×2・添加×2の連続はリズムを壊す）。
- トピック文は文内で情報を完結させる。「ケプラーの仕事は、じっと見つめることだった」で切らず、**何を**見つめるのかを同じ文に入れる。

### 専門語の翻訳（最重要）
専門用語が出たら、**直前か直後に必ず噛み砕いた説明を入れる**。残してよいのは噛み砕きが隣接する場合のみ。
3つの翻訳手法：
1. **実体に置き換える**（「方向センサー」「燃料」「機体の記憶」）
2. **動作で説明する**（「向きがわからなくなった」「凍りついて流れなくなる」）
3. **身近な比喩で重ねる**（スマホ・心臓・呼びかけなど生活感のある対象に）

- **翻訳・比喩に使う語自体が日常語であること**。訳語が読者にとって未知語なら翻訳になっていない（NG例：リアクションホイール→「はずみ車」。flywheel の直訳だが一般読者には未知語。→「金属の円盤」「ホイール」）。
- 比喩は読者が**身体で追体験できる動作**を優先する（回転いすに座って体をひねると、いすが逆に回る）。
- 装置の言い換え（「舵」等の雅語）は**初出の比喩としてのみ**使い、以降の地の文では正式呼称（ホイール等）に戻す。

| NG | OK |
|---|---|
| 3軸姿勢制御を失った | 自分がどちらを向いているか、わからなくなった |
| ヒドラジンの粘性が急上昇しスラスターに流れなくなる | 燃料が凍りついて、エンジンに流れなくなる |
| 高速で回るはずみ車で | 電気でモーターを回し、金属の円盤を高速で回す |

### 固有名・説明は必要最小限に（鉄則）
**固有名詞や説明が増えるほど、読者は離脱しやすくなる。** 本筋（執念の物語）に効かない固有名・由来・脇道の説明は、書く前に削る（spec.md「事実の採用マーク」＝「この事実は主筋にどう効くか」を1行で書けたものだけ採用する）。書いてしまった場合も、演出＋読者視点セルフチェック（spec.md）で拾う。「面白いから」「事実として正確だから」は採用理由にならない。主筋に効くかだけで判断する。

### 物語のドライブ装置
各 H2 に**最低1つ**、物語の核となる H2（救出劇・逆転・決断）には**3つ以上**組み込む：
1. **比喩で温度を上げる**（「凍りついた心臓に、もう一度血を通わせるように」）
2. **クライマックスは短文＋太字で刻む**（**成功だった。** / **そのスピンが、希望になった。**）
3. **「である」調を要所で混ぜる**（「SOHOは確かに生き延びていたのである」）
4. **当事者のセリフ・感嘆を入れる**（「『まだ戦える』」）
5. **意味の宣言**（「これは、単なる通信の回復ではなかった。『まだ終わっていない』という宣言だった」）
6. **次セクションへの橋渡し**を H2 末尾に置く（完結させきらない）
7. **暗転の直前に平常・成功を1段落置く**（順調な日々・積み上がる成果を描いてから落とす。落差が切迫感を生む。前触れなく壊すと淡々として読める）。**この1段落は固有名の紹介で済ませず、「そこで何をしていたか」の中身で書く**（NG:「調べていた谷の名は『忍耐の谷』だ。／5月の末、異変が始まった」＝地名を出しただけで転換し、場面が急に切り替わる。OK: 谷の成り立ちを確かめるため谷筋を下りながら地形を調べていた、と任務の中身を書いてから異変へ）
8. **危機の場面は「数える」**（残数・期限・失うものを短文で刻む。「残るは3基。だがもう予備はない。次の1基が壊れたら、そこですべてが終わる」）
9. **見せ場 H2 の山場は1文で流さず、場面として書く**。agenda で「見せ場」と設計した H2（課金壁直前・クライマックス）の山場を、事実の報告1文（「一夜にして発電量が5%跳ね上がった」）で済ませない。発見なら「異変への気づき→検証→謎→種明かし」の順に構成し、読者が当事者と一緒に驚ける場面にする（「ありえない数字があった。／発電量が、上がっている。／見間違いではない。…／でも、どうやって？」）
10. **見せ場は実数で裏付ける**。見せ場 H2 には効果・変化を示す具体的な数値（Before/After）を1つ以上入れる（「371ワット時→615ワット時。じつに7割増し」）。定性表現（「何度も」「大きく」）だけで山場を語らない。数値が手元に無ければ notebook で探す

### 論理の橋（飛躍させない）
読者が知らない因果を1ステップでも飛ばさない。状況→比喩、物理の因果、桁違いの量・時間の比較では必ず橋を渡す。
```
[NG] 通信が途絶えた → 機体は凍りついた
[OK] 宇宙空間で機体が沈黙するとは、電波を発する力さえ失ったこと。
     電力を失えばヒーターも止まる。極低温の闇が、そのまま機体を蝕んでいく。
```
- 光（電磁波）と粒子（プラズマ・物質）は速度が桁違い。時間スケール（秒/分/時間/日/年）の混在は必ず明示する。

**読者の即時疑問チェック**：装置・現象を書くたびに、次の3つを自問して先回りする。
1. **動力**：それは何のエネルギーで動くのか（電気？燃料？光？）
2. **位置**：外の現象がなぜ内部の部品に効くのか（貫通・伝播の一段を書いたか。例：CMEの電子は機体の外壁を突き抜けて内部にたまる）
3. **因果**：「壊れた」「失敗した」にはその場で理由を一段そえたか（詳細な種明かしを後章に置くなら、その場に軽い理由＋伏線として設計する）

### 物語の疑問と理解の疑問（サスペンスの設計）
読者の疑問には2種類あり、**扱いを逆にする**。ここを混同すると「正確だが面白くない」原稿になる（2026-08-20、「説明が多く頭で理解しないといけない」というユーザー診断から。オポチュニティ冬ごもり章の Before/After 実験で方針確定）。

- **理解の疑問**（なぜ壊れる？どう動く？）＝**その場で即答する**。「論理の橋」「読者の即時疑問チェック」のとおり。
- **物語の疑問**（助かるのか？どちらが正しいのか？その正体は？）＝**意図的に保留して引きにする**。答えを遅らせることが面白さそのもの。どの疑問をどの章まで保留するかは agenda の「保留リスト」で設計する（spec 構成フェーズ参照）。

運用ルール：
1. **説明は質問の後**。仕組み・幾何・背景の説明は、読者がその答えを欲しがる**出来事の後**に種明かしとして置く（例:「なぜ、斜面だったのか。」→幾何の説明）。出来事より先に仕組みを講義しない。先回りしてよいのは理解の疑問（動力・位置・因果の一段）だけ。
2. **問いと答えを同じ段落に密着させない**。「チームの出した答えは、〜だった。冬ごもりをする」のように問い→即答で流さず、見せ場では問い→場面（実行）→種明かしの順で1拍以上あける。
3. **章の頭は場面・決断・異変から入る**。季節学・装置解説などの背景説明で章を開始しない。背景は危機の文脈の中に1文で後置する（例: 火星の1年＝地球の約2年分、は「5回目の冬が近づいていた」の直後に置く）。
4. **賭け金（stakes）は一般論でなく記憶で立てる**。危険の説明を抽象論（「壊れるおそれがあった」）で終わらせず、当事者が知っている前例・失敗（例: 半年前のスピリットの凍死）で立てる。ただし前例も出典の範囲で書く。

### 列挙の型を揃える
打ち手・制約・成果などを並べて総括するときは、要素の**型（構文と論理関係）を揃える**。「制約→打ち手」で並べるなら全要素をその型にする。型の違う要素（幸運・偶然など制約でないもの、態度・心構えなど打ち手でないもの）を混ぜると、並列に見えて論理関係が違うため、列挙全体の意味がぼやける。型が違うものは列挙から外し、別段落で本筋との関係を明示する。
```
[NG] 風の幸運は、あてにせず、来たら全部受け取る。／冬は、斜面にもたれてやり過ごす。／
     車輪が弱れば、後ろ向きに走る。／記憶が消えるなら、毎晩地球に預ける。
     （後ろ3つは「制約→打ち手」だが、1つ目だけ「幸運→心構え」で型が違う）
[OK] ヒーターが切れなくなれば、夜ごとバッテリーを切り離して眠る。／冬が来れば、斜面に
     もたれて日差しを稼ぐ。／車輪が弱れば、後ろ向きに走る。／記憶が消えるなら、毎晩地球に預ける。
     （全要素を「制約→打ち手」に統一。幸運は別段落に切り出し「呼び寄せられないからこそ、
      その日まで生き延びる手を考え続けた」と本筋との因果を明示する）
```

### 概念の依存順序（前方参照を作らない）
ある用語・スイッチ・仕組み・**数値**を「使う／操作する」前に、その理解に必要な前提を先に説明しておく。読者がその時点までに読んだ説明だけで理解できる順序にする。種明かしを後の段落に置かない（意図した伏線を除く）。
```
[NG] 「SCEをAuxに切り替える」と書いた後の章で、初めてSCEとAuxの仕組みを説明する
[OK] 先にSCEの役割（宇宙船の「声」をつくる装置）と「低電圧で自動停止する安全装置」を説明し、
     そのうえで「Aux＝その安全装置を外すモード」を出す
```
数値も同じ。読者がまだ根拠を読んでいない数値を、説明より先に前提として使わない。
```
[NG] 「90日の任務なら、砂が積もっても持ちこたえられる」と書いた後の段落で、初めて「寿命90日」の根拠を説明する
[OK] 先に「発電量が1日0.1〜0.2%ずつ落ち、約90日でヒーター用の電力を確保できなくなる」という根拠を説明し、
     そのうえで「これが『寿命90日』の中身だった」と受ける
```

### 断定の強さは事実に合わせる（誇張しない）
「すべて」「必ず」「最初の」「〜寸前」など強い断定は、出典が支える範囲を超えやすい。事実が「一部」「一時的」「主要な」なら、その通りに書く。
```
[NG] 正常飛行中の機体を「墜落寸前」／一時復旧した計器を「すべて失った」
[OK] 「いつ中止がかかってもおかしくない」／「計器がいっせいにダウンした」
```
- 失敗・喪失を書くときは「**何が失われ、何が残ったか**」を書き分ける。それまでの成果まで消えたように読める総括（「積み上げがすべて無駄になった」式）は書かない。
```
[NG] 何年分の積み上げも、この先の計画も、すべてが宙に浮いた
[OK] 惑星候補はすでに山ほど見つかっていた。だが、延長で手に入れたはずの未来が、まるごと消えた
```

### 同一対象の呼称統一
1記事に複数の実体（例：打ち上げ機＝ロケット／搭乗機＝宇宙船／中立＝機体）が登場する場合、冒頭で呼称の役割を決め、最後まで揺らさない。装置がどちらに属するか（例：燃料電池・SCEは宇宙船側）も取り違えない。

### 史実・出典
- 史実・数値・科学的知見・特定ミッションの記述には出典を付ける。感想・比喩・情緒的な締めには付けない。
- **出典を確認してから書く。想像で当事者の発言・心情を捏造しない。** 不明な点は抽象度を上げて書く。
- 出典には URL を付け、リンクが開けること（DOI があれば優先）。
- 出典マーカーの記法・参考情報リストの書式・draft/index の2段階運用は、spec.md「参考情報の書式（2段階運用）」を参照。

### 表記
- `""` は使わず `「」` または太字。かぎ括弧を強調する場合は「**語句**」（かぎ括弧自体は太字にしない）。
- 体言止めは余韻を残す箇所だけに使う（「青白く生々しい傷跡。」）。
- **ダッシュ「——」は使わない**（共通NGの再掲。タイトル・H2見出し・図キャプション含む）。言い換え・並置は括弧（「軸受（ベアリング）」）、余韻・転換は読点・句点で書く。

## Do Not
- 専門用語の無翻訳（直後の噛み砕きがない）
- 当事者を出さず組織名・プロジェクト名だけで物語を進める
- 出典のないセリフ・心情の捏造
- 「すごい」「とても」「非常に」など中身のない強調語の連発
- 検証不能な誇張の定型句（「世界中を泣かせた」「誰もが涙した」等、効果を測れない主観のまとめ）
- 結論を引き延ばす冗長な前置き
- 体言止め・「である」調・短文太字の多用（要所だけに使う）
- 「文系でも分かる」「これが分からないと恥」系の煽り／上から目線
- 明示的 CTA（「フォローしてください」等）。フォロー・スキ・購入は本文の質で取りに行く。

## 採点基準

`/check-brand` が本文を採点するための基準。各項目を 0〜10 で採点し、**全項目8点以上で合格**。
8点未満の項目は該当箇所のみ事実を変えず書き直す（最大5回ループ・既に8点以上の項目は壊さない）。

| 項目 | 9〜10（優） | 7〜8（合格） | 5〜6（要改善） | 0〜4（不可） |
|---|---|---|---|---|

| 4. 論理の橋・依存順序 | 因果の飛躍がなく、全用語が登場時点で既出の説明だけで理解できる | 橋・順序はほぼ保たれ、1箇所だけ弱い | 飛躍または前方参照が複数 | 読者が知らない因果・用語が説明なしに使われる |
| 5. 事実の忠実さ | 断定の強さが出典の範囲に収まり、呼称が統一され、セリフ・心情に出典がある | ほぼ忠実、わずかに強い断定が残る | 出典を超えた断定・呼称の揺れが複数 | 捏造されたセリフ・心情がある |
| 6. 構成・体裁 | H1 直下導入・H2 末尾 `---`・H3 なし・段落1〜3文・語尾3連続なしをすべて満たす | 1箇所だけ体裁の乱れ ← **8点の最低ライン** | 体裁の乱れが複数 | 構成ルールを無視している |

## 出力前セルフチェック
- [ ] 冒頭1行で読者に「えっ？」「続き読みたい」と思わせているか（ズラシが効いているか）
- [ ] 導入が、難所マップの「読者の疑問・期待する種明かし」を先に答えていないか（該当するなら抽象化するか問い形にしたか）。概念ラベル語（「共生」等）でまとめていないか。検証不能な誇張の定型句を使っていないか
- [ ] 導入部に H2 が付いていない（H1直下から本文）／各 H2 末尾に `---`／H3 を使っていないか
- [ ] 各 H2 に物語のドライブ装置が1つ以上あるか
- [ ] 専門用語が直前か直後で噛み砕かれているか（**訳語自体が日常語か**）
- [ ] 専門用語・仕組みが、登場時点で既出の説明だけで理解できるか（前方参照になっていないか）
- [ ] 装置・現象の「動力・位置・因果」の即時疑問に先回りしているか（論理の橋）
- [ ] 各 H2 が場面・決断・異変から始まっているか（背景説明で章を開始していないか）。仕組みの説明が出来事より先に来ていないか（「説明は質問の後」）
- [ ] agenda の保留リスト（物語の疑問）が設計どおりの章で回収され、途中で答えを漏らしていないか。見せ場で問いと答えが同じ段落に密着していないか
- [ ] 「すべて／必ず／〜寸前」等の断定が、事実・出典の範囲を超えていないか
- [ ] 喪失・失敗の場面で「何が失われ、何が残ったか」を書き分けているか
- [ ] 同一対象の呼称が全文で統一され、装置の帰属が正しいか
- [ ] 本筋に効かない固有名詞・由来・脇道の説明が残っていないか（読者離脱の主因）
- [ ] 打ち手・制約を並べた列挙で、要素の型（制約→打ち手など）が揃っているか
- [ ] 数値・年月日・人物名が具体的で、当事者の固有名詞と発言・判断が出ているか
- [ ] 段落が1〜3文に収まり、同じ語尾が3連続していないか
- [ ] 隣接する段落の頭が同種の接続詞で始まっていないか
- [ ] 動詞・名詞を不要にひらがな開きしていないか（開くのは接続詞・助詞のみ）
- [ ] ダッシュ「——」を使っていないか（タイトル・見出し・図キャプション含む）
- [ ] 想像で書いたセリフ・心情がないか（出典で裏が取れているか）
- [ ] 参考情報が spec.md「参考情報の書式（2段階運用）」どおりか（下書き＝`[N]`マーカー＋本文での参照内容／公開版＝マーカー除去＋文献の概要）
- [ ] 締めが「意味の宣言」「感情」「未来へのまなざし」で終わり、「諦めなくていい」読後感に着地しているか
- [ ] `../../style/story-check.md` の7項目（時系列・行動とテーマの整合・接続詞の受け先・史実帰属・結末の完結・フックの回収・語の重複）をすべて通過しているか
