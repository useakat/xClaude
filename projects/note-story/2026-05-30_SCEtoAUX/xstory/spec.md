# Production Spec — 困難を乗り越え成功した執念の物語の X長文ポスト（W001 / SCEtoAUX）

このプロジェクトの題材（ネタ）は確定している：同フォルダの note 記事（W002「SCEをAUXに」アポロ12号を救った話）。
ネタ選定は行わず、**既存 note 記事を入力に X長文ポストを制作し、note 記事への流入・購入につなげる**（plan.md の Funnel 参照）。

## Media (生成する媒体)
- X 長文ポスト本編（プレーンテキスト、**約600字**、X 内で完結）
- note 導線のセルフリプ（本編とは分離した2投稿目）
- 末尾ハッシュタグ（数個）
- 添付画像（エンゲージメント用）— `thumbnail/` のフローで生成


## Input (読み込むファイル)
- `../../../plan.md`／`../../../brand.md`（共通の発信目的・ブランド定義）
- `plan.md`（本プロジェクトの目的・ターゲット・Funnel）
- `brand.md`（本プロジェクトの表現ルール・文体・X長文の型）
- `../output/index.md`（**題材の正本**。事実・人物名・装置の帰属・呼称はここに合わせる）
- `../../spec.md`（note 記事側の出典・参考情報の扱い）
- `~/xClaude/.claude/skills/writer-xstory/examples/buzzPostData.txt`（既存投稿のトーン・重複確認）
- `~/xClaude/style/hook-patterns.md`（冒頭フックの4型テンプレート）


## Output (保存先)
- 作業用下書き: `draft/draft.md`
- 公開原稿: `output/index.md`
- 添付画像: `output/images/thumbnail.png`


## Naming
公開原稿 `output/index.md` には、以下を明示して1ファイルにまとめる：

```
# [タイトル/識別用の短い1行]

## 本編
[約600字の本文。X内で完結。末尾にハッシュタグ]

## セルフリプ
全部 note に書いた → [note URL]
```

- 本編とセルフリプは別投稿として送る前提で、見出しで明確に分ける。
- note URL が未確定の段階では `[note URL]` のままにし、公開時に差し替える。


## Rules

### 制作フロー
1. **題材の事実確認**: `../output/index.md`（題材の正本）を読み、物語の核（雷被弾→計器全ダウン→ジョン・アーロンの「SCEをAUXに」→復旧）と、人物名・日付・装置の帰属・呼称を確定する。**ここに無い事実を新たに作らない。**
2. **トーン確認**: `buzzPostData.txt` を読み、既存投稿の口語トーンと重複を確認する。
3. **本文作成**: `/writer-xstory` を使い、約600字の本編を作成する。`brand.md` の X長文の型（冒頭フック2文 → 具体3点セット〔日付・場所・状況〕→ 困難/工夫/逆転 → 教訓は末尾集約 → 「諦めなくていい」着地）を遵守。冒頭フックは `hook-patterns.md` を参考にする。本編には note 誘導を入れない。
4. **字数・完結チェック**: 約600字に収まり、X 内で物語が完結しているか（中断型でないか）を確認する。超過分は削るか、note 側に委ねる。
5. **セルフリプ作成**: note 導線を本編から分離し、別投稿として作る。note記事を読みたくなるような導入の1文と、note記事へのリンクを記載する。
6. **ファクトチェック**: `/check-fact`（テキスト入力モード、最大5回ループ）。**特に note 記事 `../output/index.md` の事実と矛盾しないこと**を確認する。指摘を反映した版を最終本文とする。
7. **ブランド適合チェック**: `/check-brand brand.md {本文}` を実行する。`brand.md` の `## 採点基準` で全項目8点以上になるまで該当箇所を書き直し（採点ループ・最大5回）、合格本文をトンマナ調整する。事実は変えない。
8. **添付画像**: 必要なら `thumbnail/` の `plan.md`／`brand.md`／`design-brief.md`／`nanobanana-prompt.md` に沿って添付画像を用意する。画像生成自体は外部（nano banana）で行い、`output/images/thumbnail.png` として保存する。
9. **保存**: 本編・セルフリプ・ハッシュタグを `output/post.md` に保存する。
10. **記録**: 投稿後、`outputs` シート（SS2）に W001 の投稿を記録し、紐付く note 記事 URL を **F 列（note_url）** に記入する（`/sync-x-note-analytics` の CTR・CVR 集計に必要）。

### その他
- **X への投稿は cron 定時実行以外では行わない**（CLAUDE.md 禁止事項）。本スキルは原稿作成・保存までを担当する。
- 本編は単体で満足できる完成度にしつつ、note 記事に「収まらなかった裏側」があると感じさせ、続きを取りに行かせる。


## Verification
- 本編が **約600字**で、X 内で物語が完結している（中断型でない）
- 冒頭2文だけで「何の話か」が伝わり、続きを読みたくなる
- 本編冒頭に日付・場所・状況の具体3点セットがある
- 専門用語が直前か直後で噛み砕かれ、前方参照になっていない
- 教訓・メッセージが最後の1〜2段落に集約され、前半は描写に徹している
- 史実・人物名・装置の帰属が note 記事（`../output/index.md`）と矛盾していない（`/check-fact` 通過）
- note 誘導が本編に入っておらず、セルフリプ定型で分離されている
- 末尾に関連ハッシュタグがある
- `brand.md` と矛盾しない（煽り・上から目線・出典なき捏造・明示的 CTA がない）
- `/check-brand` のブランド適合スコアリング全項目が 8 点以上（不合格時は警告を明記）
- `plan.md` の目的に沿う（読後に「諦めなくていい」着地／note へ続きを取りに行かせる引きがある）
- 出力ファイル名が命名規則に揃っている
