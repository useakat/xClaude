# Production Spec — 困難を乗り越え成功した執念の物語の note 記事（W002）

- note 記事本文（Markdown、**6000字以上**）
- 各 H2 セクションの画像プロンプト（テキストで提案。実画像生成はスキルに委ねる）


## Input (読み込むファイル)
- `../../plan.md`（共通の発信目的・ターゲット）
- `../../brand.md`（共通ブランド定義）
- `plan.md`（本プロジェクトの目的・ターゲット）
- `brand.md`（本プロジェクトの表現ルール・文体・演出ルール）
- `reference/articles/`（過去記事 mhtml）／`reference/thumbnails/`（サムネイル参考画像）／`reference/markdown-rules.md`（Markdown 表記ルール）
- Google Sheets `noteNeta`（spreadSheet ID: `1zCT0Kv0Q0qr83c6e_jQxUJeUQ1Y8iz0Zlm_0U5RMaEM`）— ネタ在庫（L列ステータス「未使用」のみ対象）


## Output (保存先)
`YYYY-MM-DD_<短いタイトル>/`

* <短いタイトル> は、その note記事を表す15文字以内の英文字列

## Rules

### 制作フロー
1. **ネタ選定** — `noteNeta` シートで L列「未使用」のネタから選ぶ（ユーザー指定時も未使用を確認）
2. **記事フォルダの作成**: `YYYY-MM-DD_<短いタイトル>`という名前のフォルダを作成する。作成する記事に関するファイルはこのフォルダの中に格納する。
3. **関連情報リサーチ**: research_setup-sources スキルを使い、notebookLM の notebook を作成し、ネタに関連する信頼度の高い情報源をソースとして追加する。スキルが出力する <notebook ID> は保存しておく。以下のステップ 3~5 は、notebook のソースの情報だけをもとに行う。
4. **参考情報の確認**: `reference/articles/` フォルダにある過去の記事例（mhtml）を読み込む
5. **構成フェーズ**: タイトル案10個とその中の推奨案を1つ・狙い・想定読者・構成案・文字配分を提示し、**ユーザー承認を待つ**（承認前に本文を書かない）。この内容は構成案として保存しておく。
6. **本文フェーズ**: 承認済み構成を厳守して執筆する。`brand.md`（文体・演出ルール）を遵守
7. **6000字チェック**: 6000字未満なら不足セクションを加筆し再カウント
8. **演出セルフチェック**: 導入H2なし／各H2末尾`---`／H3なし／専門語の噛み砕き／各H2に演出装置／`[^N]`形式 を確認
9. **ファクトチェック**: /check-fact`（テキスト入力モード、最大5回ループ）。指摘を反映した版を最終本文とする
10. **画像生成**: `/visual_section-planner` スキルを使い、各H2セクションに配置する図解・イメージ・写真画像の案を立て、`draft/image-plan.md` に保存する。ユーザーが1案に絞り込んだのち `/visual_section-imager` で実画像を生成する。
11. **サムネイル生成**: thumbnail 
12. **ハッシュタグ**: `/hashtag-note {本文}`で、note記事につける hashtag を選定し、本文下書きの末尾に追加する。
14. **ネタを使用済みに更新**: `noteNeta` シートの該当行 L列を「使用済み」に更新
15. **完了メール送信**: `scripts/send_gmail.sh` で useakat@gmail.com へ通知

### タイトル
- 人目を引き、クリックしたくなる引きの強いもの。
- **語尾は動詞で終わらない**。体言止め・問いかけ・「〜の物語」「〜した話」で締める。


### その他
- **構成承認前に本文（全文・サンプル段落含む）を書かない。** ユーザーの明示承認を待つ。
- ネタ使用後、即座に Sheets の L列を「使用済み」に更新する。

## Verification
- 本文が **6000字以上**ある
- 導入部に H2 が付いていない／各 H2 末尾に `---` がある／H3 を使っていない
- 専門用語が直前か直後で噛み砕かれている
- 数値・年月日・人物名が具体的で、当事者の発言・判断が出ている
- 参考文献が `[^N]` footnote 形式で、末尾に `## 参考情報` がある
- 参考文献のリンク先が存在し、開くことができる。
- ファクトが出典確認済み（`/check-fact` 通過）
- brand.md と矛盾しない（煽り・上から目線・出典なき捏造がない）
- plan.md の目的に沿う（読後に「諦めなくていい」読後感に着地している）
- 出力ファイル名が命名規則に揃っている
